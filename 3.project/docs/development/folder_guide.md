# 자료·캐시·원본 보관 기준

> 상태: 현재 기준
> 확인일: 2026-10-07
> 기준: HEAD `54a8841` + 작업 트리. 이번 작업은 이동·삭제를 하지 않음.

| 구분 | 취급 |
| --- | --- |
| backend·frontend·tools | 현재 앱·개발 도구. 수정 범위를 확인하고 유지 |
| docs | 현재 안내·기록·고정 평가를 구분. 담당 내용은 manifest에 등록 |
| storage_root의 업무 자료 | DB·원본·텍스트·가림·설정·계정. 고객 백업·복구 기준으로 보존 |
| eval·docs/eval·sample-data | 원본·정답·예측·receipt·재현 자료. 평가가 끝났다고 자동 삭제하지 않음 |
| outputs의 검수 Excel | 정답 출처나 사람 확인과 연결된 원본/사본인지 확인 |
| .venv·node_modules·빌드 | 재생성 가능성과 사용 버전·오프라인 반입 필요를 확인 |
| pytest_cache·__pycache__ | 재생성 가능한 캐시. 고객 자료와 구분하고 대상 경로 확인 후 별도 정리 |
| 루트/프로젝트의 tmp | 프롬프트·진행 중 검증·시안·산출물. 필요·완료·출처부터 확인 |
| 루트 _local_archive | 이전 output·수동 복구 백업·move receipt. 복구 근거 보존 |

작업 공간 바깥의 실제 분류와 공유 ZIP 비교는 [작업 공간 경계](workspace_layout.md)가 기준이다. Git 저장소가 상위에 있다는 점을 고려해 대상 경로를 확인한다. 전체 tmp나 백업 폴더를 한 번에 비우지 않는다.

물리적으로 옮길 때는 원래 경로·새 경로·SHA-256·사용처를 기록하고 참조 링크를 확인한다. 원본·정답·고객 자료·복구 백업을 캐시로 간주하지 않는다. 삭제는 재생성·원본/복사본·보관 필요를 확인한 별도 작업이다.

앱 제공 범위는 [배포 경계](distribution_boundary.md), 고객 자료는 [백업·복원](../operations/backup_restore.md)을 따른다. 이번 문서 정리에서 기존 공유본·ZIP·tmp·보관함 파일은 변경하지 않았다.
