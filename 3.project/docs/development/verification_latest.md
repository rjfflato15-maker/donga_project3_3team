## 2026-10-09 조회 성능 수정

## 2026-10-09 기능 복구와 Setup

등록 실패 재시도 시 계약·파일 중복 방지, 선택한 서류 종류와 계약 금액 기준 동시 저장, 계약 제외 후 기록 보존·복원, 지급 기록 정정·취소, 회신 기록 정정·대기 복원을 구현했다. 최초 지급 사실과 정정 전 회신 내용은 감사 이력에 보존한다. 기존 삭제 API는 이제 제외 표시를 만드는 동작이다. 이전 버전에서 이미 삭제한 데이터를 복원하는 것은 아니다.

작업 공간 백엔드 560개, 프런트 28파일·124개 테스트와 TypeScript/Vite 빌드가 통과했다. 후속 계약 ZIP·맡은 일·설치·문서·개인정보 검사 묶음 40개 및 실행기/패키지 24개를 확인했다. 관리 문서 49개 오류 0, ERD는 신규 3개를 포함한 27테이블이다. 작업 공간 전체와 원본 평가 자료를 제외하는 제출 ZIP 테스트 개수는 구분한다.

동일 payload를 별도 AppId로 격리 설치하고 개발용 Python·Node가 PATH에 없는 상태에서 빈 업무함 초기화·실행·업데이트·재실행·제거·자료 보존을 확인했다. 실제 화면의 지급 정정, 계약 제외→복원, 회신 대기 복원을 가상 QA DB에서 확인했다. 현재 PC의 시험이며 새 PC·실제 AI 다운로드·설치 마법사 시각 검사·제품 서명은 미검증이다. [구조화된 검증 기록](recovery_release_verification_20261009.json)과 [고객 패키지](../operations/customer_package.md)에 범위를 기록한다.

### 같은 날 후속 수정: 제출본 이메일 점검

앞선 비밀 값 검사에는 이메일 정책이 없어서 비밀번호 재설정 화면의 개인 이메일 리터럴 두 곳을 놓쳤다. 로그인한 사용자 이메일이 없으면 빈 값으로 시작하고, 예시는 `name@example.com`으로 수정했다. 수정한 프론트엔드 27파일·121테스트와 배포 빌드를 다시 확인했다. 백엔드 소스는 앞선 531테스트 이후 동일하다.

ZIP 생성기에 미승인 이메일 차단을 추가하고 정책 검사 4테스트를 확인했다. example.com/net/org·명시한 가상 로컬 도메인·해당 파일에 한정한 공개 서비스 예시만 허용한다. 합성 샘플 이메일은 제출 사본에서 example.com으로 바꾸며 실제 이메일 값은 검사 보고서에 출력하지 않는다. 이전 ZIP을 최종 제출본으로 사용하지 않고 후속 수정본을 새로 생성한다.
