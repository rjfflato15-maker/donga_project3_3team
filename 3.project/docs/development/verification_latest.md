## 2026-10-10 계약 전체 결과·UNKNOWN·확인 후 판단 연결

계약 전체 검사 결과와 필수 사람 확인 수를 서류 목록 앞에 표시한다. 진행 전 상신 차단의 중복 패널은 서류 탭에서 숨기되 결과 요약의 의무·문제 수와 해결 진입점을 유지하고 결재 탭에서는 기존 상세 조건을 제공한다. 문제 확인 버튼은 저장된 정상값 위치보다 실제 문제를 우선한다. 청구 범위 UNKNOWN은 정상 묶음 확인에서 제외하여 계약 조건·청구액에 따른 입력을 바로 열며, 업무함도 입력 의무를 원문 대조 수와 구분한다. UNKNOWN의 과거 확인 기록은 유효한 현재 확인으로 인정하지 않는다. 성공한 같은 차수·필드·값·확인 시각에서만 사실 확인 뒤 판단 선택을 이어간다.

이전 기능 작업에서는 실제 Qwen2.5-VL로 가상 이미지 후보 생성→세액만 선택 저장, PC·모바일 화면과 콘솔을 확인했다. XLSX 다운로드·10초 폴링·다른 사용자 변경 안내도 별도 업무함에서 확인했다. 이번 문서 작업에서 라이브 모델 추론·고객 DB 수정·설치기 빌드를 다시 실행하지 않는다.

원문 대조 시안의 실제 앱 이전은 별도 UI 작업으로 완료했다. 한 번 확인·되돌리기·다음 항목 이동·후보 반영 저장을 분리된 QA DB에서 확인했다. 이 UI 검증의 VLM은 테스트 응답이며 실제 모델 시험으로 계산하지 않는다. [시각·동작 검증 기록](../../design-qa.md)을 함께 읽는다. Windows 백엔드 테스트는 Python `-X utf8`로 실행한다.

2026-10-07 당시에는 고객용 Setup의 다운로드·설치·업데이트·제거·새 PC 확인을 수행하지 않았다. 이후 2026-10-09의 격리 설치 결과는 위 기록을 따른다. 일부 실행기 단위 테스트 통과를 새 PC 설치 검증 완료로 쓰지 않는다.

검증 환경은 Python 3.12.14·Node v24.15.0이다. [패키지 버전 기록](verification_environment.json)과 [문서 점검 결과](../submission/omitted_records.md)를 참고한다. backend requirements는 최소 버전 범위이므로 새로 설치한 환경이 이 검증 환경과 같다고 가정하지 않는다. frontend는 package-lock을 기준으로 npm ci를 사용한다. 외부 웹 주소의 생존 여부와 새 PC 설치는 이번 문서 lint 범위에 포함되지 않는다.
