## 먼저 보존

현재 Git 상태·미커밋 파일·업무 자료·설정·백업을 확인한다. 이번 작업과 다른 사람의 변경을 함께 폐기하지 않는다. 코드 변경은 로컬 커밋이나 별도 보관으로 남기고, 정상으로 확인한 버전과 비교한다. 코드 버전과 DB/원본 백업의 시점을 따로 기록한다.

## 코드 복구

해당 업무함의 분석·저장이 끝난 뒤 백업하고 서버를 종료한다. 검증한 코드 버전을 별도 체크아웃/폴더에서 테스트·빌드한 뒤 적용한다. 기존 고객 설정·자료 폴더는 코드 교체에서 제외한다. DB 스키마가 달라졌다면 이전 코드만 실행해서 호환된다고 가정하지 않는다.

## DB·원본 복원

관리 메뉴 7번에서 아직 존재하지 않는 새 폴더로 복원한다. 복원 도구가 경로와 파일 해시를 검사하며 성공한 뒤 실행 설정이 바뀐다. 실패하면 기존 설정을 유지한다. 이전 업무함은 보존하고 복원된 로그인 세션은 만료되어 다시 로그인한다. 기본 백업 경로는 소스 실행기의 storage/backups이며 실제 설정값을 확인한다.
