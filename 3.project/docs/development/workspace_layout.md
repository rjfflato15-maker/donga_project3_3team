# 작업 공간·저장소·공유본의 경계

> 상태: 현재 기준
> 확인일: 2026-10-07
> 기준: HEAD `54a8841` + 작업 트리. 폴더 이동·삭제 없이 읽기 전용 분류.

현재 실제 구성은 다음과 같다.

```text
C:\3조 색인\
├── .git/                    이 전체 작업 공간의 Git 저장소
├── .gitignore               루트 tmp·로컬 보관함 제외
├── .gitattributes           Git 파일 처리 설정
├── README.md                작업 공간 입구
├── 3.project/               현재 앱·소스·개발/운영 문서
├── 팀공유_시범C안/         공유용 HTML·안내의 풀림본
├── 팀공유_시범C안.zip      같은 공유 자료의 전달본
├── tmp/                     진행 중 프롬프트·검증·시안 산출물
└── _local_archive/          이전 output·수동 rollback 백업·이동 기록
```

## 실제 수정 범위

앱 소스와 앱 문서는 3.project에서 관리한다. 루트 README는 작업 공간 탐색만 담당한다. Git 저장소는 3.project 안이 아니라 상위에 있으므로 프로젝트 안에서 git status를 실행해도 바깥 공유본의 변경이 보일 수 있다. 전체를 무조건 stage·압축하지 않고 대상 경로를 확인한다.

이번 문서 작업은 폴더·ZIP 이동/삭제, .git 설정 변경, 고객 자료 정리, 설치기 재개를 포함하지 않는다. 검증의 임시 파일은 쓰기 가능한 별도 Codex 작업 폴더에 보관했다. 루트 tmp와 .project 내부 tmp는 용도와 소유 기록을 확인한 뒤 정리한다.

## 바깥 자료의 분류

| 대상 | 확인한 내용 | 현재 처리 |
| --- | --- | --- |
| 팀공유_시범C안 폴더·ZIP | HTML 2개·안내 1개. ZIP의 3파일이 풀림본과 해시 일치 | 둘 다 보존. 전달본/열어보는 본으로 구분 |
| tmp/app-audit·UX·launcher 검증 | 개발 중 분석·화면·실행기 결과 | 진행 중/완료/재현 필요 여부를 먼저 확인 |
| tmp/guard_v3·eval-artifacts·test-review | 평가 작업 중간 자료 | 고정 원본·정답·receipt의 복사 여부와 출처 확인 전 이동·삭제하지 않음 |
| tmp/pdfs·presentations | 문서·발표 산출물 | 원본 재료/중간본/최종 제출본을 구분한 뒤 최종 목록 지정 |
| _local_archive/output | 이전 발표·보고서 보관 | 재사용 가능한 과거 자료로 보존 |
| _local_archive/rollback_backups | 수동 복구 자료 | 고객 DB·정상 버전 복구와 관련성을 확인할 때까지 보존 |
| _local_archive/move_receipt.json | 이전 이동 경로·SHA 기록 | 원래 경로 복원 근거로 보존 |
| .git·.gitignore·.gitattributes | 저장소와 관리 설정 | 자료 보관함으로 취급하거나 임의 이동하지 않음 |

## 앞으로 물리적으로 정리할 때

먼저 파일 목록·사용처·동일 내용·참조 링크·보관 책임을 확인한다. 공유본은 날짜/버전 목록으로 관리하고, 완료된 임시 자료는 필요한 것만 이동 후보로 정한다. 이동을 실행한다면 원래 경로·새 경로·SHA-256을 receipt에 남기고 링크·복구 가능성을 확인한다. 삭제는 백업·원본 여부를 검토한 별도 작업이다.

현재 앱 자료는 설정된 storage_root에서 관리한다. 고객 DB·원본·계정·백업을 루트 보관함 정리와 섞지 않는다. 자세한 구분은 [배포 경계](distribution_boundary.md), [폴더 보관](folder_guide.md), [자료 복구](recipes/recovery.md)를 읽는다.
