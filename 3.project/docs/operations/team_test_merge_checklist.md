# UI 병합·측정 빌드 고정 체크리스트

2026-10-04 사용자 지정 UI `4c428b6`을 `dcd4608`에서 main에 병합했다. 앞선 업무 연결·복원 수정 `db7b243`도 보존했다. 병합 전에 사용자에게 알렸으며 화면 파일 두 개만 바뀌었다.
날짜를 기다리지 않고 앞 작업이 완료된 구간부터 확인한다. 10/5 동결 이후에는 기능 추가 없이 오류 수정만 한다.
남은 작업은 첫 화면 금액 검색 오류 수정·그 화면 재확인·측정용 업무함의 새 코드 재시작·사용자의 실제 ZIP 저장 확인·측정 빌드 확정이다. 지급 기록 기능은 아직 미구현이며 이번 업무 연결 점검은 대표 결재와 ZIP까지다.

관련 API 연결 102항목·회귀 테스트 78개·복원 파일 36개 확인은 [별도 검증 결과](workflow_rehearsal.md)에 기록했다. 이는 브라우저 클릭과 파일 저장 확인을 대신하지 않는다. 첫 화면 오류 재현과 Claude 수정 범위는 [화면 담당자 안내](../api/frontend_handoff.md#ui-통합-기준과-첫-화면-점검-2026-10-04)에 기록했다.

## 순서 (앞 단계 성공 후 다음 단계)

1. 사용자에게 병합 예정임을 먼저 알린다. 사용자가 전달하는 마지막 UI 커밋과 로컬 `feat/ui-polish` SHA가 같은지 확인한다. 준비 시점 SHA를 최종 SHA로 쓰지 않는다.
2. 양쪽 작업 상태와 커밋을 확인하고 main에 그 커밋을 병합한다. frontend 충돌은 UI 브랜치 기준으로 처리한다. 백엔드/API나 변경 의도가 애매한 충돌은 멈추고 사용자에게 알린다. push·PR은 하지 않는다.
3. `backend/.venv/Scripts/python.exe -m pytest backend/tests -q`로 전체 백엔드 검사. 실제 모델 호출·가드 평가 배치·test/test2 평가 재실행은 하지 않는다.
4. `frontend/`에서 `npm test`, 이어서 `npm run build`. 성공한 수와 로그 경로를 아래 고정 기록에 기입한다.
5. [자료 준비 안내](team_test_materials.md)의 `--verify`를 새 시연 폴더에서 실행해 규칙 결과를 확인한다.
6. 테스트 전용 서버만 명시적인 설정 파일로 종료한 뒤 시작한다. **브라우저 새로고침이나 EXE 다시 실행만으로는 이전 백엔드가 교체되지 않는다.** [실행·설정](startup_settings.md)의 재시작 절차를 따른다. 실제 업무함은 대상에서 제외한다.
7. 사용자가 새 서버에서 로그인 → 대시보드 → 원문/수정 → 요청·회신 → 재발행·이전본 → 맡기기 완료 → 결재를 확인한다. ZIP 버튼으로 가린 본 실제 다운로드·압축 해제, 원본 확인창 취소, 확인 후 원본 다운로드를 확인한다. 원본 감사 기록도 확인한다.
8. 사용자 확인 후에만 측정용 전체 40자리 SHA를 확정한다. 수정이 발생하면 관련 검사와 영향받는 화면을 다시 확인한 마지막 커밋을 기록한다. 측정 중 수정하면 별도 측정 묶음으로 분리한다.
