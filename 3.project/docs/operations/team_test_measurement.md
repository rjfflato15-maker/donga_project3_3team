# 화요일 기존 방식·앱 작업시간 비교 초안

목적은 같은 난이도의 계약을 **정확히 처리하는 데 걸린 시간**을 비교하는 것이다. 자동 판독 정확도 평가와 별개이며, 화면에 표시되는 ‘계약 생성 후 경과시간’을 절감 시간으로 사용하지 않는다.

## 준비

- 실제 업무와 분리한 시연 업무함, dev 합성 서류만 사용한다. NTS disabled, AI 설정·캐시 사용 여부·앱 커밋을 기록한다. test/test2 원문이나 답안은 사용하지 않는다.
- 담당자 과제 세 개: 정상 계약, 외부 필수 서류 누락, 금액이 다른 견적서의 재발행본 교체. 대표는 마지막 결과와 확인 이력을 보고 결재 또는 반려하는 별도 과제를 한다.
- 기존 방식에도 **동일한 등록 계약 기준금액·번호, 필수 서류 목록, 현재본·이전본 구별 정보**를 준다. 불리한 비교가 되지 않게 평소 사용할 폴더·문서 뷰어·Excel과 업무 기준표를 허용한다. 앱의 정답·검수 결과는 주지 않는다.
- 양쪽에서 제출할 결과를 동일하게 한다: 누락·불일치 판단, 근거 문서·금액, 다음 처리, 요청 기록, 대표 확인 대상. 실제 카톡·이메일 발송은 하지 않는다.
- 시작 전에 3분 설명과 측정에 쓰지 않을 연습 한 건을 제공한다. 로그인·설치·파일 배치는 측정 전에 끝낸다. 도움 없이 첫 화면을 5초 보고 다음 할 일을 말하는 검사는 별도로 기록한다.

## 과제와 완료 기준

| 과제 | 기존 방식 | 앱 | 성공 조건 |
| --- | --- | --- | --- |
| 정상 | 원문을 열어 필수 6종·번호·금액을 대조하고 표에 기록 | 서류 업로드 → 문제·근거 확인 → 검수 기록 | 실제 누락·차이 없이 담당자 확인을 마치고 대표가 확인할 자료 준비 |
| 누락 | 누락 서류 확인 → 요청 문구 작성 → 연락 방법·기한 기록 | 누락 카드 → 요청 초안 검토 → 보냈다고 가정하고 요청 기록 | 누락 서류를 정확히 지정하고 회신 대기 기록. 미연동 NTS를 오류로 세지 않음 |
| 재발행 | 차이 발견 → 정정 요청·기록 → 제공된 회신에서 새 파일을 현재본으로 구분 | 차이·원문 확인 → 요청 기록 → 재발행본 올리기 → 재검사·회신 처리 | 이전본 보존, 현재본으로 재검사, 차이 해결 여부 기록. 확인되지 않은 계약을 완료 처리하지 않음 |

회신은 진행자가 준비한 가상 회신·재발행본을 같은 단계에서 즉시 제공한다. 사람이 실제로 연락하고 기다리는 시간은 측정하지 않는다. 앱 화면의 기록 기능이 아직 연결되지 않은 부분은 연결 완료 뒤 측정한다.

## 순서와 시간 재기

1. 한 과제에 대해 기존 방식과 앱을 둘 다 수행한다. 가능하면 금액·이름만 다른 **동일 난이도 A/B 계약**을 사용한다. 같은 원문을 반복하면 답을 기억해 빨라지므로 ‘두 번째 수행의 학습 효과’를 기록해야 한다.
2. 참가자 절반은 기존 방식 → 앱, 나머지는 앱 → 기존 방식으로 진행한다. 인원이 적으면 과제마다 순서를 번갈아 정한다. A/B도 같은 방식에 고정하지 않고 바꾼다.
3. 진행자가 “시작”하고 서류를 공개할 때부터, 참가자가 완료를 선언하고 결과를 제출할 때까지 잰다. 원문 확인·클릭·입력·수정과 **앱 처리 대기**를 포함한다. 업로드도 작업의 일부다.
4. 앱 처리 대기는 별도 초로 함께 적는다. 네트워크 장애·전화 등 과제 밖 중단은 양쪽 동일 기준으로 제외하고 중단 사유·시간을 남긴다. 대표가 접속할 때까지의 대기는 담당자 시간에 넣지 않는다. 대표 시간은 별도 측정한다.
5. 한 과제·방식당 5분을 넘으면 `미완료(300초 초과)`로 기록한다. 도움을 줬다면 내용·횟수를 적고 ‘도움 없이 성공’에서 제외한다. 미완료·오답을 기록에서 빼지 않는다.

담당자 세 과제를 두 방식으로 모두 하면 측정 상한은 30분이다. 15분만 가능하면 정상+재발행 두 과제의 상한을 3분씩으로 줄이거나 팀원별로 과제를 나눈다. 참가자별로 둘 다 수행하지 않은 결과는 같은 사람의 전후 비교로 표현하지 않는다.

## 기록 양식

아래 CSV 열을 사용한다. 익명 참가자 ID를 쓰며 개인 업무 자료나 비밀번호를 적지 않는다.

```csv
participant_id,role,task,variant,method,order,start_at,end_at,excluded_pause_seconds,elapsed_seconds,machine_wait_seconds,success_without_help,help_count,critical_error,completion_status,notes,app_commit,llm_mode,nts_mode
```

`elapsed_seconds = 종료 - 시작 - 과제 밖 중단`. `machine_wait_seconds`는 elapsed에 포함된 값이며 다시 빼서 ‘전체 시간’으로 보고하지 않는다. `critical_error`는 문제가 남았는데 완료·결재, 잘못된 현재본 선택, 누락 서류 오인 등이다.

## 결과 보고

- 방식별 참여 인원·성공·미완료·도움 요청·중요 오류 수를 먼저 적는다. 시간만 빨라도 오답이면 개선으로 보지 않는다.
- 같은 참가자·과제에서 **양쪽 모두 성공한 쌍**의 시간 차이와 절감률 `(기존-앱)/기존 × 100`을 계산한다. 앱이 더 느리면 음수 그대로 적는다. 계산에서 제외한 쌍과 이유·개수도 함께 적는다.
- 쌍별 결과, 중앙값·범위를 제시한다. 소수 팀원·합성 서류·일회성 측정이므로 일반 회사의 시간 절감이나 월 150건 효과로 확대하지 않는다.
- 현재는 **측정 방법 초안**이다. 실제 시간 절감 수치는 아직 없다. Claude의 과제 안내와 연결 상태를 맞춘 뒤 적용한다.
