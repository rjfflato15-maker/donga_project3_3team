# 5분 업무 흐름 시연 대본

목적: C업체 담당자가 서류 문제를 발견하고, 보완·재확인 뒤 대표에게 전달하는 흐름을 보여준다.
`team-test-dev-v1` 자료를 사용하고, 이 시연은 **규칙만·LLM 꺼짐·NTS 미연동**이다. AI 보완의 효과는 보존된 평가 보고서로 별도 설명한다.
참가자 작업시간 측정과 분리하며 진행자가 보여준 정답을 참가자에게 미리 공개하지 않는다.

| 시간 | 보여줄 흐름 | 설명할 말 |
| --- | --- | --- |
| 0:00~0:30 | C업체 역할·필수 6종 | “직원 6명 회사에서 담당자 한 명이 서류를 챙기고 대표가 최종 확인합니다.” |
| 0:30~1:30 | 과제 1 A 업로드 → 누락 → 요청 기록 | “통장사본이 빠졌습니다. 거래처에 요청했다고 기록하면 회신 대기로 남습니다. 실제 메시지는 자동 발송하지 않습니다.” |
| 1:30~2:30 | 과제 2 A 견적 차이 → 원문 근거 | “등록 금액과 견적서 합계를 비교합니다. 읽은 값을 눌러 원문 근거를 확인할 수 있습니다.” |
| 2:30~3:30 | 수정 견적서 → 이전본/현재본 → 회신 처리 | “고쳐 보낸 견적서를 반영하면 이전 파일도 남고, 현재본으로 다시 검사합니다.” |
| 3:30~4:20 | 담당 업무 완료 → 대표 확인 | “담당자의 업무 완료와 대표의 최종 확인은 구분합니다. 자료가 바뀌면 다시 확인해야 합니다.” |
| 4:20~5:00 | 계약 ZIP 받기 | “현재·이전 서류, 검사 결과, 처리 기록을 한 묶음으로 받습니다. 기본은 가린 본입니다.” |

진행자는 [자료 안내](team_test_materials.md)에 따라 새 시연 폴더를 사용한다. 로그인·비밀번호 변경·원문/수정본 파일 배치는 시작 전에 끝낸다.
업로드 대기가 길면 편집 없는 전체 영상에는 그대로 남기고, 발표용 짧은 영상에서 생략한 부분은 ‘처리 대기 생략’으로 표시한다. 이 대본의 5분은 발표 목표이며 측정 결과가 아니다.

백업·복원은 무대에서 기다리지 않고 [검증 결과](workflow_rehearsal.md)를 설명한다. “가상 자료로 새 폴더에 복원했고 문서와 처리 이력이 유지되는 것을 확인했습니다.”라고 말할 수 있다.
