# 화요일 팀원 테스트 접속 안내

**내 PC 한 대가 서버, 팀원 PC는 같은 네트워크에서 브라우저로 접속한다.** 앱 설치·DB 복사 없이 dev 가상 서류만 사용한다. 서버 PC는 테스트 동안 켜 두고 절전하지 않는다. 과제 테스트 안내문은 Claude가 별도로 준비한다.

## 서버 PC에서 준비

1. `3.project/storage/demo/c-company-v1/Run-demo.bat`에서 **0**을 선택해 시연 서버를 종료한다. 기존 업무 서버 8000은 종료하지 않는다.
2. 프로젝트 폴더에서 아래 명령을 실행한다.

   ```powershell
   .\C-Pilot.exe manage --settings-file .\storage\demo\c-company-v1\guarded-replay\launcher\settings.json
   ```

3. 관리 메뉴 **5(실행 설정)**. 포트 `8021`·자료·백업 폴더는 Enter로 유지하고 **다른 사내 PC의 접속 허용에 y**를 입력한다. 메뉴 **1**로 시작한다. 설정은 시연 업무함에만 적용된다.
4. `ipconfig`에서 사용 중인 Wi-Fi 또는 이더넷의 **IPv4 주소**를 확인한다. 예를 들어 `192.168.0.20`이면 팀원에게 **`http://192.168.0.20:8021/`**를 전달한다. 팀원 PC에서 `localhost`나 `127.0.0.1`은 서버 주소가 아니다.
5. Windows 방화벽에서 막히면 서버 PC의 고급 설정 → 인바운드 새 규칙 → TCP `8021`을 허용한다. 신뢰하는 사내 네트워크의 프라이빗 프로필과 로컬 서브넷 범위로 제한한다. 게스트 Wi-Fi의 PC 간 차단 여부도 확인한다. 이 문서가 방화벽을 자동 변경하지는 않는다.

## 팀원용 테스트 계정 두 개

| 역할 | 로그인 ID | 사용할 업무함 |
| --- | --- | --- |
| 담당자 | `operator@demo.local` | AI 보완 결과 업무함(8021) |
| 대표 | `representative@demo.local` | 같은 업무함(8021) |

두 계정은 시연 생성 스크립트가 이미 준비했다. 초기 비밀번호는 **서버 PC의 `storage/demo/c-company-v1/initial-accounts.txt`**에서만 확인하고 첫 로그인 때 변경한다. 변경한 테스트 비밀번호를 해당 역할의 팀원에게 따로 전달한다. Git·설명 문서에 비밀번호를 넣지 않는다. 담당자·대표는 각각 별도 PC 또는 별도 브라우저 프로필로 접속한다. 같은 브라우저에서 역할을 바꾸면 로그아웃 후 다시 로그인한다.

8020 업무함도 같은 IP로 동시에 열면 포트가 달라도 로그인 쿠키가 겹칠 수 있으므로 팀원 테스트에서는 **8021 하나**를 사용한다. 여러 PC의 수정 결과는 서버의 동일 DB에 저장된다. 검수 수정·회신·결재 기록은 시연 자료에만 남는다. 이번 두 계정은 역할 시연용이며 실제 운영은 직원별 계정을 사용한다.

## 접속 확인과 종료

서버 PC에서 앱이 열리는지 → 팀원 PC에서 위 주소가 열리는지 → 담당자·대표 로그인이 되는지 순서로 확인한다. 연결이 안 되면 IP·8021 포트·같은 네트워크·사내망 y·방화벽을 먼저 확인한다. 다른 PC에서 DB 파일을 직접 열거나 서버 폴더를 공유하지 않는다.

끝나면 같은 관리 메뉴 **9**에서 서버를 종료하고 **5**에서 사내망 허용을 n으로 돌린다. 시연 기록을 초기화하려면 기존 업무함을 지우지 말고 [시연 준비 도구](demo_inbox.md)로 새 폴더를 만든다.

국세청 조회는 항상 disabled다. AI 결과는 고정 dev qwen3 응답·가드 v3의 캐시 재생이고 새 실시간 LLM 호출은 꺼져 있다. 이 안내는 가상 자료의 사내망 HTTP 테스트이며, 실제 업무 운영의 HTTPS·접근 제한은 [사내망 운영 안내](network.md)를 따른다.
