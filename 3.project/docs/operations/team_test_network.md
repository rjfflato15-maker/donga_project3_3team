# 화요일 팀원 테스트 접속 안내

**내 PC 한 대가 서버, 팀원 PC는 같은 네트워크에서 브라우저로 접속한다.** 이번 시간 비교는 `team-test-dev-v1`, 규칙만·LLM 꺼짐·캐시 없음·NTS disabled로 고정한다. 서버 PC는 켜 두고 절전하지 않는다. 참가자 안내는 Claude의 [배포용 사본](../../sample-data/team-test-dev-v1/participant_guide.md)을 사용한다.

## 서버 PC에서 준비

1. 이전 시간 과제 서버가 있으면 그 업무함의 `stop.bat`으로 종료한다. 기존 업무 서버 8000은 종료하지 않는다.
2. 프로젝트 폴더에서 아래처럼 **새 업무함**을 만든다. `--case`는 이번에 배정한 자료에 맞춘다. 과제별 초기화 상세는 [자료 준비 안내](team_test_materials.md)를 따른다.

   ```powershell
   backend/.venv/Scripts/python.exe backend/scripts/prepare_team_test_inbox.py --case task_1_A --output storage/demo/team-test/p01-task1-app --intranet
   ```

3. 만들어진 폴더의 `start.bat`을 실행한다. 포트는 기본 `8030`, 사내망 접속은 위 `--intranet` 옵션으로 허용한 상태다. 원문은 아직 업로드하지 않는다.
4. `ipconfig`에서 Wi-Fi/이더넷의 IPv4 주소를 확인한다. 예를 들어 `192.168.0.20`이면 팀원 접속 주소는 **`http://192.168.0.20:8030/`**다. 팀원 PC의 `localhost`는 서버 주소가 아니다.
5. 접속이 막히면 서버 PC 방화벽의 TCP `8030` 허용 여부와 게스트 Wi-Fi의 PC 간 차단을 확인한다. 방화벽 허용은 신뢰하는 사내 네트워크의 프라이빗 프로필·로컬 서브넷으로 제한한다. 스크립트는 방화벽을 바꾸지 않는다.

## 팀원용 테스트 계정 두 개

| 역할 | 로그인 ID | 사용할 업무함 |
| --- | --- | --- |
| 담당자 | `operator@team.local` | 이번 과제 업무함(8030) |
| 대표 | `representative@team.local` | 같은 업무함(8030), 결재는 담당자 시간 측정과 별개 |

새 업무함마다 두 계정을 만들고 임시 비밀번호는 **그 폴더의 `storage/initial-accounts.txt`**에만 저장한다. 측정 전에 로그인·비밀번호 변경을 끝낸다. 변경한 비밀번호는 해당 역할 팀원에게 따로 전달하며 Git·보고서에는 넣지 않는다. 역할별 별도 PC/브라우저 프로필을 사용한다.

테스트는 한 번에 한 업무함만 연다. 포트가 달라도 같은 IP의 로그인 쿠키가 겹칠 수 있어 다른 업무 서버와 브라우저 프로필을 분리한다. 다음 업무함 전환 시 로그아웃 후 새 계정으로 접속한다. 측정 참가자는 같은 업무함을 동시에 수정하지 않는다.

## 접속 확인과 종료

서버 PC → 팀원 PC → 담당자·대표 로그인 순서로 확인한다. 접속이 안 되면 IP·8030 포트·같은 네트워크·`--intranet`·방화벽을 확인한다. DB 파일이나 서버 폴더를 팀원에게 공유하지 않는다.

끝나면 해당 업무함의 `stop.bat`으로 종료한다. 결과 폴더는 보존하고 다음 과제는 새 이름으로 만든다. 타이머 시작 전에 등록 계약만 있는 빈 업무함을 열고, 시작과 동시에 배정된 참가자 ZIP을 제공한다.

10/5 병합 뒤에는 [서버 재시작·확인](team_test_merge_checklist.md)을 마친 빌드로 측정한다. 이전 `c-company-v1/guarded-replay` 시연은 이번 시간 측정에 사용하지 않는다. 이 안내는 가상 자료 HTTP 테스트용이며 실제 업무 환경은 [사내망 운영 안내](network.md)를 따른다.
