## 주요 관찰과 개선

1. **왜 지금 승인할 수 있는지가 일반 요약과 이력에 흩어져 있다.** 등록 금액·서류 수·남은 확인 없음이 반복되며, 실제 견적서 합계 220→110원 정정은 아래 이력에 묻혀 있다. ‘문제 → 조치 → 현재 결과’ 한 묶음으로 먼저 보여 준다. 존재하는 재발행/요청/검사 기록만 연결하고, 기록 없는 과거 문제나 실제 발송 사실을 만들어 채우지 않는다.
2. **최근 처리 목록이 결정 영역을 밀어낸다.** 전체 이력은 접거나 ‘처리 기록 보기’로 보내고 주요 변경만 위에 표시한다. 승인/반려와 입력 조건은 보이는 위치에 둔다. 하단을 고정한다면 메모·키보드 포커스·지급 후 재결재 경고를 가리지 않아야 한다.
3. **담당자의 실제 검토 메모가 보이지 않는다.** 화면에는 ‘담당 검토 결재’와 사람·시각·완료 표시만 있다. `ApprovalPanel`은 `/approvals`의 `history[].note`를 받지만 렌더링하지 않으며, 첫 검토 AuditEvent에는 revision만 저장되어 최근 이력만으로 메모를 찾을 수 없다. 현재 자료 기준의 담당 검토 기록과 메모를 대표에게 보여 준다. 1단계 회사 등 기록이 없으면 ‘담당자 확인 기록 없음’으로 표시한다.

현재 역할/결재 단계 표시, 현재본 목록·원문 열기, 국세청 미조회 구분은 유지할 가치가 있다. 자동 검사 일치와 사람이 원문을 확인한 사실은 따로 표시한다. ‘남은 자동 확인 0건’을 모든 사람이 검토했다는 의미로 바꾸지 않는다.

## Claude에게 요청할 대표 화면 시안

대표 화면을 다음 순서의 결재서로 정리한다. 실제 구현 전 시안에서 정보 배치와 현재 API로 만들 수 있는지 함께 확인한다.

- **계약 요점:** 계약명·거래처·금액·금액 기준·지급 방식·이번 결재 대상 현재본.
- **문제와 처리:** 무엇이 달랐는지 → 어떤 서류를 다시 받았는지 → 이전/현재 금액과 현재 검사 결과. 자세한 원문/비교로 연결.
- **담당자 확인:** 현재 자료를 검토한 사람·시각·메모. 자동 검사와 구분하며 없으면 없다고 표시.
- **대표 결정:** 남은 확인과 국세청 미조회 안내, 필요한 체크/직접 메모, 분명한 승인·반려 버튼. 전체 처리 기록은 별도로 펼쳐 보기.

한 페이지에서 핵심을 읽고 필요한 원문만 열 수 있게 한다. 현재 정책의 1/2단계 역할·승인/반려 조건·원본 누락 제한·revision/fingerprint 검증·자료 변경 시 재결재·기존 지급 재확인 경고는 유지한다. 기본 체크·자동 메모로 사람 동의를 대신하지 않는다.

### 데이터 연결과 가림

- 계약 요점/현재본/자동 검사: 기존 ContractDetail·workflow·overview·versions/compare API.
- 요청/재발행 처리: 기존 activity의 기록된 사건. 페이지 일부만 조회해 전체 변경을 확인했다고 표시하지 않는다.
- 2단계 현재 담당 검토: `/api/pilot/contracts/{id}/approvals`의 `history[].current=true`, actor_name/note/created_at. 과거 다른 revision 기록을 이번 검토로 표시하지 않는다.
- 현재 approvals의 note는 원문이다. 개인정보 가림 ON에서 그대로 노출하지 않는다. 서버가 가린 표시용 메모를 제공하거나 기존 가림 규칙을 적용할 수 있는지 Codex와 연결 조건을 맞춘다. 담당자 이름과 메모 속 민감한 값의 처리도 구분한다.
- ‘지난 결재 이후 바뀐 것’은 실제 이전 결재와 그 기준이 있을 때만 사용한다. 최초 결재는 ‘이번 검토에서 바뀐 서류’가 적절하다.

현행 시안 `c55a40d`의 D6 제안은 최근 처리 범위를 줄이는 방향이다. 이번 요청은 대표 판단 정보를 앞에 모으는 것까지 포함한다. 시안/후속 구현은 측정용 코드와 분리하며 root는 frontend를 수정하지 않았다.
