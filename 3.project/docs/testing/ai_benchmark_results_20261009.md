## 결론

고정된 OCR 페이지와 모델 응답을 사용한 95문서 재생에서 수정 전후 필드 예측과 가드 결정 전체가 동일했다. 이 자료에서 정확도 상승은 측정되지 않았다. 실제 Windows OCR·Ollama·VLM을 실행한 결과는 아니므로 OCR 정확도, 모델 품질, 전체 처리 속도 개선을 주장하지 않는다.

## 확인한 범위

- TEST 59문서(v3): 필드 262/337, 77.74% → 77.74%. 없는 필드에 잘못 추출한 값 0/76.
- TEST2 36문서(v4): 필드 195/204, 95.59% → 95.59%. 없는 필드에 잘못 추출한 값 0/48.
- 두 집합 모두 입력 해시, 필드 예측 해시, 가드 결정 전체 해시가 전후 동일하다. 수락/거부·사유뿐 아니라 제안·근거 위치·경고도 같은 결정 해시로 비교했다.
- 사람 추가 확인 비율과 채택 값 정확도 등 가드 결과도 동일했다. TEST와 TEST2는 서로 다른 자료이므로 두 점수 차이를 v4 개선률로 해석하지 않는다.
- 과거 공식 네 모드 보고서의 모든 기존 지표를 저장된 예측에서 정확하게 재현했다. 수정 전 소스에서도 동일하게 재현했다.
- 파일 receipt 337개(TEST), 191개(TEST2), 개별 체크포인트, 정답/manifest freeze를 확인했다. 실행 뒤에도 고정 패키지와 정답을 다시 검증했다. 압축에 포함된 Python 코드는 실행하지 않았다.

이 재생은 이미 사용한 held-out 자료의 탐색적 재사용이다. 새 독립 최종 평가가 아니며 결과를 보고 코드를 맞추는 튜닝에 사용하지 않았다. 과거 정답과 예측을 고치거나 고정 릴리스 검사를 완화하지 않았다. 변경된 필드로 계약 검수 상태를 새로 계산한 측정도 아니다.

## 시간 측정의 한계

동일 Linux 환경에서 문서별 가드 호출을 20번 반복했다. 최종 기록의 문서별 호출 평균은 TEST 0.137→0.173ms, TEST2 0.063→0.066ms였다. 빈 요청 호출과 첫 호출 비용을 포함하며 OCR·모델·API·UI·사람 검수 시간은 포함하지 않는다. 짧은 구간의 반복 측정은 실행마다 흔들렸고 유의한 속도 향상을 입증하지 않는다. 상세 p50/p95와 표본 수는 JSON에 있다.
