# 가드 v4 개발 정책

목적은 원문 근거가 있는 값을 과도하게 거부하는 문제를 줄이는 것이다. `backend/app/ai/grounding_v4.py`에 별도 정책을 두고 기존 `grounding.py`의 v3는 보존한다. 개발 근거는 dev2만 사용했으며 [예비 비교](../eval/dev2/guard_v4/preliminary_comparison.md)는 사람 확인 전 수치다.

| 검증 항목 | v4 정책 |
| --- | --- |
| 필드 의미 | 기존 라벨에 dev2에서 확인한 세전 대금·부가세액·총 청구액을 추가. 부분 문자열이 아닌 전체 라벨 경계 확인 |
| 한 줄의 여러 필드 | 다음 명시 라벨에서 값의 끝을 구분. 공급자·공급받는자 구역은 라벨 위치에서 확인 |
| 표의 줄바꿈 | 라벨과 바로 다음 줄의 값을 각각 원문 위치로 검증. 다른 라벨·당사자 구역을 건너뛰지 않음 |
| 줄 번호 오차 | ±1에서 같은 인용문·라벨·값의 유일한 위치만 허용. 다른 당사자로 이동 금지 |
| DOCX 위치 | 기존 문단·표 셀 위치로 글자 근거 확인. 물리 페이지 배치는 계속 미확인 |
| 후보·형식 | 복수 후보, 라벨 없는 참고값, 잘못된 형식·체크섬은 계속 거부. 계산으로 인쇄되지 않은 값을 만들지 않음 |
| 산술 | 인쇄된 공급가액+세액≠합계는 경고를 저장하고 인쇄 값을 보존. 최종 일치·오류 판정은 규칙 엔진 |
| 미확인 ABSENT | 계약·견적·세금계산서·검수확인서의 금액·범위에서 원문 미확인을 이유로 기존 규칙 값을 지우지 않음 |

채택·거부 사유, 값 위치, 라벨 위치, 모델 인용 위치를 함께 저장한다. 모든 AI 제안은 `human_confirmed=false`이며 사람이 확인한 것으로 기록하지 않는다. 거부되면 기존 규칙 값을 보존하고 `unresolved_fields` 및 `guard_review_required`로 추가 확인을 표시한다. 규칙이 이미 잘못 읽은 값까지 가드가 자동으로 수정하거나 무효화하는 것은 아니다.

## 선택과 검증

`APP_LLM_GUARD_POLICY=v3`가 기본이다. 개발 전용 환경에서 `v4`를 선택하면 `llm_supplement.py`가 v4를 사용한다. `APP_LLM_ENABLED` 기본값은 계속 false이며 실제 업무함 설정을 바꾸지 않았다. 잘못된 정책 이름이나 LLM·원문 오류는 기존 규칙 결과를 보존하고 수동 확인으로 넘긴다. 모델·프롬프트·호출 대상 선택은 변경하지 않았다.

고정된 dev2 응답으로 재비교하려면 프로젝트 폴더에서 다음 명령을 사용한다. 아래 명령은 새 LLM 응답을 생성하지 않는다.

```powershell
$env:PYTHONIOENCODING = 'utf-8'
& .\backend\.venv\Scripts\python.exe .\backend\scripts\compare_guard_dev2.py
```

이 도구는 dev2 경로와 dev 계약만 허용하고 입력·응답·정답 초안 해시를 검증한다. 출력은 `docs/eval/dev2/guard_v4/`에 두며 v3 test의 고정 예측과 채점 파일을 덮어쓰지 않는다. 현재 버전 선택은 v3 test 결과를 본 뒤 이루어졌으므로 v4 독립 검증에는 미사용 test2가 필요하다. 최종 평가 전까지 v3 수치와 v4 예비 수치를 구분한다.
