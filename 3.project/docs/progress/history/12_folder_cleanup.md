# 탐색기 폴더·중복 파일 정리

사용자가 필요 없는 파일을 줄이고 역할별 폴더로 묶어 달라고 요청했다. 작업 공간의 `자료/`는 사용자가 삭제한 상태로 두었다. 업무 DB·문서·평가 근거는 삭제하거나 이동하지 않았다.

## 이동과 삭제

루트의 개발 BAT 세 개와 Node 스크립트는 `tools/dev/`, 운영 PowerShell은 `tools/ops/`, EXE 소스·빌드는 `tools/launcher/`, Dockerfile·Compose는 `tools/docker/`로 묶었다. 일반 실행용 `C-Pilot.exe`와 첫 준비용 `start_pilot.bat`은 루트에 유지한다. 루트 package.json의 npm 명령 이름은 그대로 유지하며 새 스크립트 경로를 참조한다.

루트 requirements.txt와 backend/requirements.txt는 줄바꿈을 정규화하면 같은 내용이었다. 의존성 관리 기준을 backend 파일 하나로 통일하고 Node 준비·Docker 참조를 수정한 뒤 중복 루트 파일을 제거했다. 다시 생성할 수 있는 작업 공간·프로젝트의 `.pytest_cache`를 제거하고 pytest의 다음 캐시는 작업 공간의 `tmp/pytest_cache/`에 저장하도록 했다.

예전 `output/` 산출물과 `3.project/backups/`의 수동 rollback 백업은 작업 공간의 `_local_archive/`로 이동했다. 이동 파일의 SHA256을 대조하고 로컬 이동 기록을 보관했다. 보관함은 Git에서 제외하며 원본 파일 내용은 그대로다. 사람 검수 Excel이 있는 `outputs/`, 정답과 출처가 있는 `eval/`, 업무 자료 `storage/`, 실제 참조가 있는 `sample-data/`는 현 위치를 유지했다. 임시 프롬프트와 진행 중 자료가 있는 `tmp/`도 무작정 삭제하지 않았다.

`3.project` 첫 화면 항목은 28개에서 15개로 줄었다. [도구 안내](../../../tools/README.md)와 [폴더 보관 기준](../../development/folder_guide.md)에 위치와 삭제 기준을 기록했다. 과거 작업 기록의 옛 경로는 당시 이력으로 남기고 현재 설치·개발 안내는 새 경로로 갱신했다.

## 확인 결과

백엔드 209개 테스트(기존 경고 597개), TypeScript·Vite 빌드(1,908모듈), PowerShell 여섯 파일 구문 검사, Node 다섯 스크립트 구문 검사가 통과했다. 메뉴의 자동 실행·백업 선택이 같은 설정 파일과 새 운영 스크립트를 호출하는 확인 두 개를 추가했다.

Windows 예약 작업은 정리 전에 해당 앱의 등록 작업이 없음을 확인했다. 설치 스크립트의 등록 명령은 모의 함수로 대체하여 새 Action 경로와 작업 폴더를 확인했고 실제 예약 작업은 생성하지 않았다. 별도 임시 업무함에서 이동된 scheduled_launcher로 시작·백업하고 EXE로 같은 서버 재사용·종료하는 동작을 확인했다. Docker 실행 도구가 없어 실제 컨테이너 빌드는 실행하지 않았고 빌드 문맥·Dockerfile·의존성 참조만 확인했다.

실행 중인 EXE가 Windows에서 잠겨 직접 덮어쓰는 컴파일은 거부되었다. 사용자 실행 창과 앱 서버는 종료하지 않고 같은 소스를 별도 임시 EXE 경로에 컴파일해 통과했다. 기존 EXE와 BAT 초기 경로의 상태 명령도 통과했다. 현재 실행기 소스는 바꾸지 않았고 옮긴 빌드 스크립트의 프로젝트·소스 경로를 확인했다.

가드 v3 고정 코드와 dev 정답·자료 목록·설계 초안 해시가 그대로임을 확인했다. 실제 test 자료는 열지 않았고 최종 평가 시도도 생성하지 않았다. 화면과 디자인은 변경하지 않았다.

작업 중 사용자가 쓸 로그인 계정 하나를 요청하여 초기 계정의 기존 비밀번호가 변경되었음을 확인한 뒤 별도 임시 담당자 계정을 추가했다. 기존 계정·비밀번호는 바꾸지 않았다. 새 계정은 첫 로그인 후 비밀번호 변경을 요구하고 계정 생성 감사 기록을 남겼다. 실제 아이디·임시 비밀번호는 이 문서·소스·커밋에 포함하지 않으며 로컬 자료 폴더에서만 보관한다.
