## 결과 해석

가드 없음은 199/204(97.55%, Wilson 94.39–98.95%), 가드 v4는 195/204(95.59%, 91.83–97.66%)다. 서로 다른 6칸 중 가드 없음만 맞은 5칸, 가드만 맞은 1칸으로 exact McNemar p=0.21875다. 이번 표본에서 4칸 차이를 통계적으로 구분할 근거가 부족하며 동등성을 증명하지 않는다. 계약 내 필드 상관 때문에 참고 구간·검정이다.

가드 v4 오답 9칸은 빈칸/UNKNOWN이며 5칸은 금액이다. 가드 없는 조건은 빈칸 4칸과 읽을 수 없는 합계에 5,000,000원을 채운 1칸이다. 양쪽 모두 오류가 있는 문서에 사람 확인 표시는 있어 ‘경고 없는 확신 오류’로 단정하지 않는다. 상호 2칸은 칸별 unresolved 표시가 없었다. 계좌번호는 평가에 없으므로 미측정이다.

정확도 분모 204칸에서 사람 직접 라벨 확인 39칸, 사람 관찰 후 문구 정정·기준 적용 1칸, 두 AI 일치 164칸으로 구분했다. 원문 사실만 질문한 N/A 18개를 사람의 상태 라벨 확인으로 계산하지 않는다. 중립 재확인 표본 중 이런 질문 5개도 같은 원문 사실끼리 비교한다.

규칙만의 비교 기준은 dev 78.34%·기존 test 75.67%·test2 91.67%다. 기존 test 77.74%는 가드 적용 조건이다. test2가 더 쉬운 사례 구성이거나 규칙에 맞는 서식을 더 포함했을 가능성을 명시했다. 다른 버전·자료의 효과를 분리해 입증한 것은 아니다.

## 검증과 보존

저장 예측 패키지의 receipt를 분석 전후 확인했다. 기존 사람 답·정답·워크북·원래 확인 페이지는 수정하지 않았다. 현재 원래 페이지는 HEAD와 바이트가 일치하며, 과거 제출 시 페이지 해시와는 다르다. 새 표본은 현재 해시와 실제 사람 답의 주장 문장 일치를 함께 확인해 출처를 구분했다.

추가 분석·중립 재확인 도구 14개와 기존 ZIP 내보내기 11개를 합친 **25개 테스트가 통과했다.** Wilson 끝점의 미세한 부동소수 오차에 대한 테스트를 근사 비교로 수정했다. 기존 라이브러리·datetime 사용 중단 예고 경고는 남아 있다. 운영 DB·frontend·AI 구현은 변경하지 않았다.

중립 페이지는 Browser 플러그인이 없어 설치된 Chrome과 번들 Playwright로 확인했다. 1400×900 및 390×844에서 원문 로딩·선택·입력 검증·답 저장·새로고침 복원·20문항 완료·JSON 다운로드를 확인했고 콘솔 오류는 없었다. QA 답은 독립 브라우저의 QA_ONLY 임시 파일이며 실제 사람 답이나 보고서 일치율로 가져오지 않았다. [화면 검증 기록](../../eval/test2/result_audit/page_qa.md) 참고.

원본 ZIP 감사 이벤트는 `CONTRACT_BUNDLE_EXPORT_REQUEST`의 `details.masked=false`로 구분되는 것을 테스트에서 확인했다. 계약·작업자·문서 수·revision이 함께 남는다. 이 이벤트는 묶음 준비 성공이며 브라우저에서 전체 파일을 수신했다는 증명은 아니다.

## 추가로 전달된 UI 통합 보고 확인

`feat/ui-polish`의 ff58374, e6fb91c, e9e8bca, ba01997 커밋과 맡기기 백엔드 코드를 읽었다. 브랜치를 병합하거나 frontend를 수정하지 않았다. Claude가 보고한 브라우저 검증 전체를 이번 세션에서 다시 수행한 것은 아니다.

- **맡긴 일의 값 수정 후 COMPLETE 409**: `assignments.py`가 START와 COMPLETE 모두 is_stale이면 막으므로 실제 문제다. 변경하지 않은 업무까지 모두 완료 불가인 것은 아니다. 현재본의 작업 완료를 허용하고 이전본·삭제된 문서의 작업은 막는 방향이 타당하다. 권한·assignment_revision 충돌 검사·필수 note·감사 이력을 유지하고, 완료를 계약의 최종 결재와 구분해야 한다. 이 요청은 확인이므로 정책 변경은 아직 적용하지 않았다.
- UI는 e6fb91c에서 현재본에 끝냄 버튼을 이미 보여주므로 위 규칙과 아직 다르다. **10/5 통합 전 해결할 항목**으로 남긴다. 원래 배정 시점과 실제 완료 시점의 자료 기준도 감사 기록에서 구분하는 것이 좋다.
- ZIP은 Claude가 버튼 표시만 확인했고 실제 클릭은 하지 않았다고 명시했다. API 검증과 별개로 가린 ZIP 받기·원본 확인 취소·승인 후 원본 받기를 병합 후 화면 확인에 포함한다.
- 빈칸 체크 숨김은 오확인 방지에 도움이 된다. 실제로 문서에 없는 값도 있으므로 ‘비어 있음’을 무조건 값을 채워야 한다는 뜻으로 해석하지 않는다.

10/5 밤 병합 전에 사용자에게 알리고 최신 UI 커밋을 확인한다. 병합 후 전체 테스트·빌드 및 사용자의 화면 검증이 끝난 커밋 SHA를 화요일 측정 기준에 기록한다. 지금은 병합·측정 커밋 고정을 완료한 상태가 아니다. 로컬 커밋만 하고 push·PR은 하지 않는다.
