# 가드 v4 개발 개선

사용자의 정확도 개선 요청에 따라 v3를 보존하고 dev2만으로 별도 가드 v4를 만들었다. 기존 test 원문·응답·거부 사례를 튜닝에 사용하거나 다시 추론하지 않았다. 모델 qwen3:latest, 프롬프트 v3, 규칙 추출·최종 판정은 유지했다. frontend 직접 수정은 없다.

## 변경과 결과

명시 라벨의 동의어와 경계, 표의 인접 라벨·값 근거 연결, 한 줄의 여러 필드 구분을 개선했다. 다른 당사자·모호한 후보·원문 누락·페이지 오류·체크섬·형식 검증은 유지했다. 근거 없는 ABSENT가 금융 문서의 규칙 값을 지우지 못하게 했다. DOCX는 기존 문단·표 위치 정책을 유지한다.

dev2 6개 계약·36개 문서, 같은 입력·보완 대상·저장 모델 응답으로 비교했다. **정답은 설계 초안이며 독립 판독·사람 확인 전이므로 전부 예비다.**

| 항목 | v3 | v4 |
| --- | --- | --- |
| 필드 정확도 | 97.55% (199/204) | 99.51% (203/204) |
| 검수 상태 정확도 | 90.91% (40/44) | 95.35% (41/43) |
| 채택 VALUE 중 정답 일치 | 6/6 | 10/10 |
| 맞는 제안 거부 | 5건 | 1건 |
| 틀린 제안 거부 | 1건 | 1건 |
| 보완 대상 중 미해결·추가 확인 | 6/12 (50%) | 2/12 (16.67%) |

기존 잘못된 PASS 지표는 양쪽 모두 0건이다. 다만 이 지표가 제외하는 N/A→PASS 오류는 양쪽 모두 1건이며 도장 가림 사례의 규칙 판정 문제로 남았다. 기계 검증이 사람 확정은 아니므로 AI 제안의 `human_confirmed=false`를 유지한다. 추가 확인 비율을 전체 사람 검수 비율로 표현하지 않는다. 자세한 조건·한계·CSV·해시는 [예비 비교 보고서](../../eval/dev2/guard_v4/preliminary_comparison.md)에 있다.

## 적용과 확인

- 소스: `backend/app/ai/grounding_v4.py`, `llm_supplement.py`, `backend/scripts/compare_guard_dev2.py`. v3 기본에 v4 명시 선택 옵션만 추가했다.
- 실행 중 업무함의 LLM 사용·가드 설정·서버는 변경하지 않았다. [가드 정책·재비교 방법](../../ai/grounding_v4_policy.md).
- 최신 작업 트리에서 백엔드 전체 316개 통과. DOCX 문단·표 위치와 변조 사례를 포함한 가드 관련 77개 통과. frontend 빌드 성공. 전체 검사에서 발견한 감사 기록 비교 오류는 병행 작업에서 수정 후 재검사에 통과했으며 그 API 수정은 이 커밋에 포함하지 않는다.
- 고정 v3 test 패키지와 정답 확정 해시를 다시 검증했다. 과거 확정 test의 가드 적용 77.74%는 그대로 보존한다.

## 남은 작업

v3 test 결과를 본 뒤 v4 작업을 선택했다는 사실을 남긴다. dev2에서 조정한 예비 개선을 독립 test 성능처럼 보고하지 않는다. dev2 독립 판독·정답 확인, 도장 가림의 규칙 판정 문제, 고정 버전의 미사용 test2 최종 평가가 남았다. frontend와 다른 세션의 API 변경은 이 가드 커밋에 포함하지 않는다.
