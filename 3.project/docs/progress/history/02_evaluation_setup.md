# 평가 준비 작업 기록

이 문서는 해당 작업 당시의 기록이다. 현재 상태는 [진행 요약](../development_report.md)을 확인한다.

## 평가 준비와 사람 확인

최종 평가의 정답표는 아직 확정하지 않았다. 합성 문서, 빈 정답 양식, 라벨링 기준 및 측정 도구를 준비했다. 이후 사용자가 Codex 초안과 Claude 검토를 함께 활용하는 방식에 동의하여 생성 설계 초안과 명시적인 dev 예비 측정을 추가했다. 미확정 초안으로 정식 성능 또는 최종 목표 달성을 주장하지 않는다. 사람 확정이 필요한 정식 측정 명령은 계속 차단된다.

| 준비물 | 위치와 내용 |

시나리오는 정상 제출, 필수 서류 누락, 공급자 사업자번호 불일치, 합계 불일치, 부가세 별도 계약, 분할 지급, 스캔과 노이즈, 품목 표, 모호한 금액, 공급가액·세액과 합계의 산술 불일치이다. 회사명과 거래는 가상이다. 테스트 사업자번호는 실제 등록 번호를 사용하지 않는다. 기존 샘플을 이번 자료에 넣지 않았으며, 두 합성 서식 계열만으로 실제 회사의 다양한 증빙을 대표한다고 주장하지 않는다.

사람 작성용 Excel과 `ground_truth_dev.json` 및 `ground_truth_test.json`은 자동 추출 결과를 넣지 않은 빈 상태다. Excel의 정답 칸이 실제로 모두 비어 있는지 확인했다. 미확정 JSON으로 정식 측정 명령을 실행하면 종료 코드 2로 중단하고 보고서를 생성하지 않았다. 빈 Excel 가져오기도 거부했으며 사람 정답 JSON과 확정 기록이 바뀌지 않았다. 생성 정보 초안은 별도 파일에 저장했다.

### 파일 확인과 환경 제약

37개 PDF 전부를 Poppler로 렌더링했고 45개 PNG와 함께 페이지 배치와 문자 표시를 확인했다. Excel 7개 시트도 렌더링해 확인했다. 36개 DOCX는 문단과 표가 있는 유효한 파일인지 검사했다.

DOCX 페이지의 시각 검증은 미완료다. [Documents 스킬](C:/Users/Donga/.codex/plugins/cache/openai-primary-runtime/documents/26.904.11930/skills/documents/SKILL.md)의 필수 기준은 “Run `render_docx.py` to produce `page-<N>.png` images”이며, 패키지 렌더러 실행은 `LibreOffice soffice.exe was not found on PATH`로 실패했다. Windows 번들 런타임에 해당 렌더러가 없어 DOCX를 페이지 검증 완료로 표시하지 않았다. 다른 렌더링 지원 환경에서 확인해야 한다. 이 제약은 백엔드 테스트 또는 LLM 추출 성능의 측정 결과가 아니다.

측정할 목표는 분류 Macro F1 0.90 이상, 핵심 필드 정확도 90% 이상, 누락 Recall 95% 이상, 교차검증 F1 0.90 이상이다. 잘못된 PASS, 확인 필요 비율, 자동 추출 처리율과 처리시간도 함께 기록한다. 자동 추출과 사람 확정은 별도 상태이며 업로드부터 대표 확인까지의 경과시간은 대기시간을 포함하므로 실제 검수 작업시간 또는 시간 절감으로 해석하지 않는다.

평가 도구는 VALUE와 REVIEW 정답을 핵심 필드 정확도의 분모로 삼는다. 존재하는 값의 추출을 보류해도 분모에 남는다. 없는 필드를 쉽게 정답으로 세어 정확도가 높아지는 것을 막기 위해 ABSENT의 거짓 추출률을 별도로 기록한다. 잘못된 PASS는 문제가 있어야 하는 정답 중 PASS가 나온 비율과 출력 PASS 중 잘못된 비율을 함께 계산한다. 분모가 0이면 측정 불가로 표시한다. 유형별 표본 수와 오류 수도 남긴다.

규칙 측정은 임시 저장소를 사용하고 국세청 조회를 미연동으로 고정한다. 파일명과 사용자 문서 유형 힌트로 정답을 주지 않는다. `test` 실행은 `--final`을 명시해야 한다. 아직 LLM 클라이언트, 가드, 동일 응답을 사용한 네 모드 비교 및 가드 거부 사유 집계는 구현하지 않았다.

## 현재 남은 작업

0번 안정화와 2A의 사람 확인 113칸 반영·dev 정답 확정·정식 규칙 기준 성능을 마쳤다. 1번 로컬 LLM 클라이언트·근거 검증·백엔드 저장 구조와 2B 네 조건 비교 도구를 구현했으며 확정 dev 전체 네 조건 비교를 마쳤다. 가드 포함 핵심 필드 정확도는 92.28%, 교차검증 Macro F1은 0.9869다. 실제 test 평가와 test 정답 확정은 아직 실행하지 않았다. DOCX의 물리 페이지 확인과 AI 근거·거부 사유를 표시하는 화면은 남아 있다. 화면 작업은 계획과 이미지 시안 승인 뒤 진행하며 그 전에는 앱의 LLM 기본 설정을 비활성화로 유지한다. 다음 권장 범위인 업무 흐름의 빠진 부분과 결과 설명·요약, 선택 에이전트는 이번 작업에 추가하지 않았다.

화면 디자인을 수정할 때는 변경 이유와 적용 범위를 설명하고 이미지 시안을 먼저 제시한다. 사용자가 승인하기 전에는 화면 변경을 적용하지 않는다. 기존 파일의 다른 변경을 이번 작업의 신규 기능으로 소개하지 않으며, 이후 단계의 구현·검증·한계를 이 보고서에 계속 추가한다.
