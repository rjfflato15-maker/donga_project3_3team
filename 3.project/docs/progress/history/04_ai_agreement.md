이 문서는 해당 작업 당시의 기록이다. 현재 상태는 [진행 요약](../development_report.md)을 확인한다.

## Claude 실제 응답 대조와 사람 확인 양식

2026년 10월 2일 사용자가 Claude 판독 완료 결과와 `eval/claude_blind_review/replies/case_01.json`부터 `case_10.json`까지 전달했다. 실제 원문 59개는 PDF 18개·PNG 23개·DOCX 18개다. Claude 요약의 DOCX 20개와 이미지·PDF 39개 표기는 개수 오기이며, JSON의 판독 방법은 PDF 텍스트와 이미지 17개, 이미지 판독 24개, DOCX 내용 판독 18개로 실제 형식과 일치한다. 모든 답변은 미확정이고 정답 초안 및 앱 결과를 참조하지 않았다고 기록되어 있다. Claude 실행 중 접근한 파일의 범위를 Codex가 독립적으로 감사했다고 주장하지 않는다.

원문 해시와 실제 응답의 문서·계약 ID, 모든 7개 필드의 형식, 중복 없는 동일 후보 검수 목록과 상태를 확인했다. 다음 표는 기존 생성 정보 초안과 실제 Claude 응답을 대조한 결과다. 유형에 관계없는 추가 후보 검사는 이 정답표의 채점 항목 수에 넣지 않았다.

이 수치는 AI 정답 초안 간 일치율이다. 앱 정확도나 정답이 오류 없이 확정됐다는 의미가 아니다. 특히 Claude가 명시한 세 가지 해석 질문은 두 초안이 일치해도 사람 확인이 필요하다. 검수확인서 9개의 금액 범위 FULL 해석, case_09 견적서의 범위 REVIEW, case_10 세금계산서의 구성 합계 및 전액 금액 대조 FAIL 두 항목을 별도 질문으로 기록했다. 검수확인서에는 계약 전체 금액이 명시되어 있어 현재의 문서 금액 범위 정의에 따라 FULL을 제안하지만 사람이 기준을 확인해야 한다.

초기 대조 `reconciliation-v1`은 191칸을 선정했다. 후속 `reconciliation-v2`는 해석 질문을 표본 추출 전에 포함해 필수 확인 26칸과 나머지 일치 868칸에서 무작위로 선택한 174칸, 총 200칸을 선정했다. seed는 42다. 필수 확인에는 원래 모호한 상태 15칸과 해석 질문 12칸이 있으며 1칸이 중복된다. 계약별 선정 여부와 입력 파일 해시를 기록했다. 해석이 불확실해도 두 모델이 같은 값을 낸 경우를 단순 일치 표본으로 넘기지 않도록 `--human-questions`를 추가했다.

사람 확인용 Excel은 `outputs/01a0f640-7f7a-7eb1-8eb2-bb5a189f1850/human_review.xlsx`이다. 안내, 필드확인(105칸), 검수확인(95칸), 원문목록(59개)으로 구성했다. 두 AI 답과 Claude 근거·해석 질문, 원문 경로를 제공하고 최종 답은 초안으로 미리 채운다. 사람 직접 확인과 판단 근거 200칸 및 검수자 별칭은 비워 두었다. 사업자번호의 앞자리 0, 금액 숫자, 날짜 값이 보존되는지 저장 파일에서 확인했으며 네 시트를 렌더링하여 읽기와 입력 영역을 검증했다. 지금 파일은 사람 확정 자료가 아니다.

`import_reconciled_labels.py`를 추가하여 원본 초안·실제 Claude 응답으로 대조 및 표본 목록을 재계산한다. 원문 목록·초안·응답·Excel 해시 및 검수자, 중복이나 누락된 확인 ID, 각 필수 칸의 실제 확인과 판단 근거를 검사한다. 누락되거나 미확인인 자료는 정답과 확정 기록을 변경하지 않는다. 이미 확정한 정답은 덮어쓰지 않는다. 무작위 표본에서 수정이 발견되면 기존 20% 범위로 확정하지 않고 전수 확인으로 확대하도록 차단한다. 원래 명시적으로 지정한 해석 질문은 해당 범위를 모두 확인하고 수정 이유를 기록할 수 있다.

확정 후에는 각 항목의 출처를 `human_direct`와 `ai_agreement`로 나눈다. 이번 200칸을 모두 확인한다면 나머지 694칸은 두 AI의 일치로 채택한 값이며 사람 전수 확인으로 표시하지 않는다. 정식 성능 보고서도 이 확인 범위를 설명한다. 현재 사람 정답 dev·test JSON은 미확정 상태이고 새 확정 기록은 생성하지 않았다. 최초 초안과 예비 결과를 정답 오류에 맞춰 덮어쓰지 않았다.

이 단계의 추가 검증은 13개다. 일치한 해석 의문도 필수 확인으로 선정하는지, 실제 사람 확인과 AI 일치 출처 및 집계가 보존되는지, 미완료 검수와 응답 변경을 차단하는지, 표본 오류에서 범위 확대가 필요한지, 전수 확대 후 수정이 가능하고 보고서에 검수 범위를 명시하는지를 독립적인 작은 예제로 확인했다. 전체 백엔드 테스트 141개가 통과했고 기존 경고 555개가 남았다. TypeScript 및 프런트 빌드도 통과했다.

사용자가 Excel의 선택 항목을 원문으로 확인하여 저장하면 dev 정답 확정과 정식 규칙 기준 성능을 측정한다. 이후 로컬 LLM과 근거 검증 및 네 조건의 비교 평가를 진행한다. 이번 단계는 앱 화면이나 디자인을 변경하지 않았다.
