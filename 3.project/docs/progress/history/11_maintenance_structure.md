# 유지보수를 위한 역할별 구조 정리

문서와 소스의 책임을 분명히 나누어 추후 수정 위치를 쉽게 찾고 판매용 배포 범위를 정하기 쉽게 해 달라는 요청을 반영했다. 기능 추가나 파일 길이에 따른 전면 분리는 진행하지 않았다.

## 문서 정리

README는 실행 방법과 안내 링크만 남겼다. `docs/README.md`는 역할별 문서 목록, `docs/architecture/module_map.md`는 기능별 소스와 책임, `docs/development/maintenance.md`는 변경·검증 절차를 담당한다. 운영 문서는 처음 설치, 실행·설정, 계정·퇴사, 사내망 접속, 백업·복원, 유지보수, 배포·판매로 나누었다.

`docs/progress/development_report.md`의 합의 기준과 '앞선 검토에서 추가한 결정' 표는 같은 경로에 유지했다. 기존 세부 내용은 `history/01`~`10` 작업 기록으로 보존하고 현재 상태는 요약에서 관리한다. 과거 작업 기록의 당시 미완료 표현을 현재 상태로 혼동하지 않도록 안내를 추가했다. 정답 출처·이전 수치·가드 조정 사실은 삭제하거나 새 성능으로 바꾸지 않았다.

LLM 안내도 실행 설정, 근거 검증 정책, dev 비교, 최종 평가 조건, 모델 라이선스 기록으로 나누었다. 원본 결과 JSON·CSV·캐시·고정 기록은 이동하거나 수정하지 않았다. 기존 ERD가 초기 핵심 테이블의 기록임을 표시하고 현재 DB 모델 소스에 연결했다.

## 소스 정리

`backend/pilot_launcher.py`의 446줄 실행·관리 코드를 `backend/launcher/`의 환경, 설정, 서버, 준비·백업·복원, CLI 모듈로 분리했다. 기존 Python 파일은 13줄 실행 입구로 유지하여 EXE·예약 작업의 호출 경로를 바꾸지 않았다. 기능 본문을 비교하여 그대로 이동했음을 확인했고 테스트의 패치 위치도 새 담당 모듈로 연결했다. 환경 준비 모듈의 이동 후 필요한 os import 누락은 회귀 확인에서 발견해 수정했다.

앱은 이미 api/services/ai/validation/db/schemas로 나뉘어 있어 불필요하게 전면 이동하지 않았다. 특히 최종 평가를 위해 고정한 AI·검수·스키마·평가 코드와 데이터는 그대로 유지했다. 화면과 디자인도 변경하지 않았다.

## 검증과 남은 범위

백엔드 207개 테스트가 통과했고 기존 경고 597개는 남아 있다. TypeScript·Vite 빌드(1,908모듈)도 통과했다. 별도 임시 자료 폴더에서 기존 EXE로 업무함 준비·서버 실행·같은 서버 재사용·백업·종료·새 폴더 복원·재실행·최종 종료를 확인했다. 기록은 [분리 후 실행 확인](../../operations/launcher_smoke_after_split.json)에 보관한다. 고객 업무함과 예약 작업은 변경하지 않았다.

dev 정답·자료 목록·설계 초안 해시와 가드 v3 고정 코드가 그대로임을 확인했다. 실제 test 자료는 열지 않았고 최종 평가 시도도 생성하지 않았다. 문서의 로컬 링크도 확인했다.

[배포 경계](../../development/distribution_boundary.md)는 실행 코드·고객 자료·비밀 설정·평가 도구를 구분하는 안내다. 소스 숨김·독립 설치형 패키지·자동 업데이트를 구현한 것은 아니다. 실제 패키징은 대상 PC에서 의존성과 설치·업데이트·복구를 검증하는 별도 작업이다.
