# UI 병합과 팀원 접속 준비

사용자에게 병합 전에 알린 뒤 `feat/ui-flow-redesign`의 `8e7b2c2`를 main에 병합했다. UI 작업 폴더에 미커밋 변경이 없음을 직전에 확인했고 충돌은 없었다. 병합 커밋은 `a8c8b89`다. 사용자가 알려 준 10개 이후 Claude의 AI 상태·업무 통계 보완 두 개까지 포함해 UI 커밋 12개를 통합했다. Codex는 frontend 소스를 직접 고치지 않았다.

계약 상세 결론·문제 카드, 서류 대조와 근거 보기, 요청 기록·회신 대기, 할 일 대시보드, 최대 2단계 결재, 회사 설정 및 좁은 화면 대응을 통합했다. 대시보드는 목록 API의 `open_issue_count`를 사용한다. C업체의 시연 설정은 SMALL_BUSINESS·결재 1단계를 유지한다.

## 병합 후 확인

| 확인 | 결과 |
| --- | --- |
| 백엔드 전체 pytest | 253개 통과, 40.15초 |
| frontend `npm test` | 3개 파일·14개 테스트 통과 |
| frontend `npm run build` | TypeScript 검사와 Vite 빌드 통과 |
| 고정 평가 버전 해시·설정 | 모델·프롬프트·가드 v3 및 고정 구현 일치 |
| dev 정답·설계 정답·manifest 해시 | 이전 버전과 일치 |
| test 최종 평가 시도 | 시작 기록 없음 |

의존성은 기존 잠금 파일과 로컬 캐시로 설치했고 패키지 버전을 변경하지 않았다. 백엔드 실행에는 기존 의존성 등의 경고 1,195건이 표시됐으나 테스트 실패는 없었다. 위 테스트·빌드 통과는 화요일 팀원 사용성 테스트를 대신하지 않는다.

## 화요일 접속 안내

[팀원 접속 한 장 안내](../../operations/team_test_network.md)에 서버 PC 하나·같은 네트워크의 브라우저 접속·담당자와 대표 테스트 계정 두 개를 정리했다. 초기 비밀번호는 시연 업무함의 로컬 파일에만 보관하며 문서와 Git에 넣지 않는다. 두 역할 모두 8021의 동일 시연 업무함을 사용한다.

국세청 조회는 disabled, 시연 AI 결과는 dev 응답 캐시 재생이며 새 LLM 호출은 꺼져 있다. 이번에는 사내망 허용·방화벽·실제 업무 서버 설정을 변경하지 않았다. 사내망 연결은 테스트 당일 안내대로 준비하고 팀원 PC에서 확인해야 한다. 과제 테스트 안내문은 Claude가 맡는다.

test는 두 초안 대조만 완료한 상태다. 사람 확인 134칸의 실제 결과 파일을 받은 뒤 정답을 확정하고 고정 버전으로 최종 평가를 한 번 실행한다. 사람 확인을 이미 마쳤다고 기록하거나 성능 수치를 먼저 산출하지 않았다.
