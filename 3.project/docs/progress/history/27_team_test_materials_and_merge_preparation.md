# 화요일 자료·10/5 병합 준비

사용자 요청 범위는 dev 기반 시간 비교 자료 준비, 의도한 문제 검증, 초기화 절차, 병합 점검표다.
앱 기능·frontend·모델·프롬프트·가드를 변경하지 않았고 test/test2 및 실제 업무함을 읽거나 사용하지 않았다.

- `sample-data/team-test-dev-v1`: 누락 A/B, 재발행 A/B, 연습 1건. 원문 28개·수정 견적서 2개·등록 정보표 5개, 총 PDF 35개.
- 참가자용 ZIP 5개에 원문·계약 정보·업무 기준·빈 CSV만 포함. 정답·수정본·검증 결과는 진행자용으로 분리했다. 전체 폴더 배포 금지를 명시했다.
- dev 기본 문단 서식을 재사용하고 값만 새로 만들었다. dev 원문 6개 출처 해시를 기록했으며 혼합 dev/test manifest는 열지 않았다.
- 분리한 임시 시연 DB의 실제 업로드·규칙 검수 서비스에서 28개 원문과 2개 수정본 확인: 누락 각 1건, 견적 차이 각 1건, 수정 후 차이 0건, 연습 문제 0건. NTS 미연동 안내는 별도 유지한다.
- 모든 PDF를 Poppler 렌더 후 AI가 육안 확인했다. 사람 검수로 기록하지 않는다. 표·금액 좌표도 A/B가 같은지 자동 검사했다.
- 새 업무함 생성 도구는 등록 계약 1건·원문 업로드 0개로 시작한다. 기존 폴더·실제 업무 경로 덮어쓰기를 거부한다. 기존 업무함을 삭제하는 초기화는 없다.
- 검증 실행에서 모델·프롬프트·가드 호출과 네트워크 접근을 차단·계수했으며 모두 0건이다. LLM false, 캐시 없음, NTS disabled를 강제했다.
- 회귀 테스트 11개 통과. 해시·참가자 정답 유출 방지·추가 문제 감지·경로 보호·실패 후 재사용 방지를 확인했다. backend 전체 검사와 frontend 검사·빌드는 10/5 병합 후 순서대로 진행한다.

[자료 안내·결과](../../operations/team_test_materials.md), [측정 기준·동등성 확인표](../../operations/team_test_measurement.md), [병합 점검표](../../operations/team_test_merge_checklist.md)를 추가·갱신했다.
실행 패키지 문서에는 백엔드 변경 후 명시적인 대상 서버 재시작이 필요하다고 기록했다.

UI 브랜치 `681df4f`의 참가자 안내와 이름·절차를 맞췄다. 안내의 약 50분은 표 합계가 최대 55분이므로 진행자 준비에 명시했다. UI 원문은 바꾸지 않았다.
병합은 아직 하지 않았다. 마지막 UI SHA는 사용자가 전달한 뒤 확정하며, 새 서버에서 사용자 화면 흐름·ZIP 실제 다운로드 확인 후 측정 SHA를 정한다.

이번 확인에서 동결 전 추가 구현이 필요한 필수 백엔드 기능 누락은 발견하지 못했다. 남은 작업은 병합·회귀 검사·재시작·화면 확인이다. 시간 절감 성능은 참가자 측정 후에만 보고한다.
