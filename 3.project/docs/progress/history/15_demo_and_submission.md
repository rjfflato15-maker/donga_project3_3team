# C업체 시범·시연 업무함·제출 목차

## 정리한 범위

[C업체 프로필](../../architecture/c_company_profile.md)에 직원 6명·월 약 150건·담당자 1명과 대표 최종 확인을 시범 가정으로 기록했다. `SMALL_BUSINESS`는 대표 공식 결재 1단계, `MID_SIZED`는 2단계 확장 설계다. 월 업무량은 처리 능력 실측이 아니며 법적 소기업·소상공인 해당 여부는 업종별 기준 확인이 필요하다.

`backend/scripts/prepare_demo_inbox.py`로 dev의 정상 제출·서류 누락·금액 불일치·사업자번호 불일치·모호한 금액 다섯 계약, 원본 28개를 준비했다. 실제 업무 DB·계정·설정은 복사하지 않고 새로운 시연 DB와 임시 담당자·대표 계정을 만들었다. 저장 위치는 Git에서 제외한 `storage/demo/c-company-v1/`이다. 기존 폴더 덮어쓰기·삭제와 고객 저장소 경로 지정은 차단한다.

`Run-demo.bat` 하나에서 규칙만(8020), 기존 AI 보완 결과(8021), 시연 서버 종료를 선택한다. 두 업무함을 별도로 저장하고 호스트 이름을 달리하여 로그인 쿠키를 구분한다. 초기 비밀번호는 시연 폴더에만 저장하고 첫 로그인 변경을 요구한다. 고객 서버 8000과 Claude 서버 8010은 종료하거나 설정하지 않았다.

AI 비교는 동일 원문에 저장된 dev qwen3 응답을 고정 프롬프트 v3·가드 v3로 재생한 결과다. 캐시 입력·응답 해시를 확인하고 누락 시 새 호출 없이 중단한다. 13문서의 응답을 재생해 저장 필드 49개가 바뀌었으며 새 LLM 호출은 0건이다. 필드 변경 수는 정확도나 실시간 처리속도 지표가 아니다. 이 과정에서 평가 결과·정답·캐시를 변경하지 않았다.

## 국세청 조회 합의

`APP_NTS_MODE`로 켜고 끄는 기존 구조를 유지한다. 시연·평가는 가상 사업자번호와 사내망 기본 원칙 때문에 항상 `disabled`(미연동)다. 실제 조회는 외부 통신이 필요하며 가상 번호의 미등록 결과는 문서 판독 평가 의미가 없다. 실제 국세청 조회를 수행한 것은 아니다. 연동 경로는 공식 공공데이터포털 API로 한정하고 홈택스 스크래핑은 쓰지 않는다. [시연 준비 문서](../../operations/demo_inbox.md#합의한-국세청-조회-정책)에 이유·현재 설정과 공식 링크를 기록했다.

준비 하위 프로세스와 실행기는 부모 환경에서 API 모드를 설정했어도 NTS를 비활성화한다. 두 업무함 모두 사업자 상태 검사 5개가 REVIEW이며 사람·대표 확인 기록은 각각 0개다. 시연을 위해 통과나 사람 확인을 만들어 넣지 않았다.

## 확인과 남은 작업

새 경계·자료 격리·실패 처리·NTS 비활성 테스트 13개를 포함해 백엔드 전체 **246개 통과**(39.29초, 경고 1,177개). 각 업무함의 계약 5개·문서 28개와 모든 원본 해시, 소기업 1단계 설정을 확인했다. 두 시연 서버를 실제 시작하여 health·화면 200, 비로그인 계약 목록 401과 대시보드 응답 필드를 확인한 뒤 시연 서버만 종료했다. 생성한 PowerShell 문법 검사, 비밀번호·DB의 Git 제외, 고정 구현·dev 정답·자료 목록 해시도 통과했다. `frontend/` 수정·빌드는 하지 않았다.

규칙 상태의 금액 미확인은 AI 결과에서 견적 금액 불일치 FAIL로 드러났고, 모호한 금액은 REVIEW로 유지됐다. 이는 시연 사례 동작 확인이며 새 성능 평가나 test 결과가 아니다.

[설명 문서 목차](../../submission/explanation_outline.md)는 문제 정의 → 구조 → 평가 방법 → 결과 → 한계·향후 계획 순서다. test 숫자는 모두 평가 대기로 남겼다. 사용자 보고로 test 독립 응답 10개가 저장됐지만 이번 작업에서는 내용 대조·해시 검증을 하지 않았고 커밋에도 포함하지 않는다. 사용자 마지막 지시인 “답변만 해주고 지금 업무는 이어서”에 따라 이번 준비를 마무리했다. 이후 같은 세션에서 응답 대조 → 사람 확인 페이지 → 실제 확인 결과 반영 → 정답 확정 → 고정 버전 1회 최종 평가를 진행한다.
