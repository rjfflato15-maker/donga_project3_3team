## 안정화 점검

이어가기 전 점검에서는 백엔드 테스트 99개가 통과했고 프런트 TypeScript 검사와 Vite 빌드도 통과했다. 이 결과는 앱 동작의 회귀 검증이며 문서 분류나 필드 추출의 실측 정확도를 의미하지 않는다.

| 점검 항목 | 확인 내용 |
| --- | --- |
| 업로드 분석 | OCR과 문서 분석은 전역 저장 락 밖에서 실행하도록 기존 코드가 보완됨 |
| 로그인과 금액 정책 | 인증 fixture와 합계 기준 및 미확인 기준 테스트가 기존에 보완됨 |
| 의존성 | python-docx 등 다중 형식 처리 의존성이 requirements에 포함됨 |
| 비밀번호 | 레거시 평문 및 해시 문자열 직접 로그인을 거부하고 이주 계정의 초기화를 요구함 |
| 보완 요청 | RETURNED와 STALE 및 확인 기록이 기존 구현에 있음 |

### 이번 안정화 변경

파일과 이미지 응답을 만든 뒤 감사 기록을 남기도록 변경했다. 마스킹 실패나 존재하지 않는 페이지 요청을 성공한 응답 준비 기록처럼 남기지 않는다. 파일을 전송하는 동안 사용자가 모든 바이트를 받았다는 사실은 확인할 수 없으므로 기존 요청 기록 명칭은 유지한다. 무거운 렌더링과 OCR 전에 읽기 트랜잭션도 종료하여 다른 요청에 영향을 줄이지 않도록 한다.

동시 처리 검증에는 업로드 분석이 대기 중일 때 계약 목록이 응답하는 확인을 추가했다. PDF 미리보기, 가린 PDF 다운로드, 텍스트 미리보기 각각이 대기 중이어도 다른 계약 목록과 원본 다운로드가 완료되는 테스트를 추가했다. 마스킹 실패 및 잘못된 페이지 요청에서 성공 응답에 해당하는 감사 기록이 생기지 않는지도 확인했다.

Git 저장소 루트는 `C:\3조 색인`이다. 그 아래 `tmp`는 기존 `3.project/.gitignore`의 적용 범위 밖이라 실제로 제외되지 않았다. 저장소 루트에 `/tmp/` 제외 규칙을 추가하고 프런트 TypeScript 빌드 캐시도 제외했다. `git check-ignore`로 두 경로가 실제로 제외되는지 확인했다. 이는 Git 제외 설정이며 ZIP에 임의로 폴더 전체를 담는 행위를 막지는 않는다. 제출 ZIP 대상은 별도로 확인한다.

### 안정화 검증 결과

| 검증 시점 | 결과 |
| --- | --- |
| 이어가기 전 | 백엔드 99개 통과, TypeScript 및 프런트 빌드 통과 |
| 안정화 변경 후 | 백엔드 102개 통과, 25.62초, TypeScript 및 프런트 빌드 통과 |
| 평가 도구 추가 후 | 백엔드 119개 통과, 14.91초, TypeScript 및 프런트 빌드 통과 |
| 생성 초안·독립 대조 도구 추가 후 | 백엔드 128개 통과, 14.18초, TypeScript 및 프런트 빌드 통과 |
| Claude 실제 대조·표본 확정 도구 추가 후 | 백엔드 141개 통과, 14.68초, TypeScript 및 프런트 빌드 통과 |

동시 처리 테스트 3개와 평가 기준 검증 17개를 추가했다. 평가 테스트는 독립적으로 작성한 작은 예제로 분모 유지, 모호한 값 확정 금지, 잘못된 PASS, 누락 Recall, 자료 경로 제한, 파일 변경 감지, 검수 전 실행 차단, Excel 입력의 확정과 버전 확인을 검증한다. 이 테스트의 예제 정답을 실제 평가 정답표로 사용하지 않는다.

독립 대조 단계에서는 9개 검증을 추가했다. AI 초안의 정식 확정 차단, dev 예비 측정에서 test 차단, 표시 오류와 모호한 금액의 정답 처리, 균일한 후보 목록, 미판독·빈 답의 일치 처리 금지, 표본 재현성, 중복·정답 노출 응답 차단, 외부 검토 ZIP의 허용 목록을 확인했다. 테스트에서 작성한 작은 독립 응답은 테스트 함수 안에서만 사용하고 실제 Claude 결과로 저장하지 않았다.

기존 코드의 날짜 처리 등에서 발생한 경고 555개가 남았다. 테스트 실패는 없었으며 경고를 모두 해결했다고 주장하지 않는다. Git 공백 검사도 통과했다. 안정화 단계는 기존에 진행하던 파일 변경과 이번 감사·동시 처리 변경을 검증해 `0927842 fix(pilot): checkpoint stabilized local evidence workflow`로 함께 저장했다. 앱 코드와 기존 화면 등 74개 파일의 체크포인트이며 평가 자료·도구는 별도 작업으로 구분했다. 원격에 push하지 않았다.
