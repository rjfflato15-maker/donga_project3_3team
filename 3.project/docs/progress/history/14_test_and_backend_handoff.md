# test 검수 준비와 백엔드 인계

작업 시작 전 dev 사람 확인 페이지를 로컬 커밋 `f58bd4e`로 보관했다. 기존 dev 정답·Claude 응답·사람 기록·페이지 결과는 유지했다. 이번 변경은 백엔드·평가 준비 도구·문서이며 `frontend/`는 수정하지 않았다.

## test 정답 준비

사용자 승인에 따라 test 계약 10건·원본 59개를 정답 준비에만 읽었다. 생성 설계값과 파일 내용·픽셀을 대조한 초안 및 해시 기록, 정답을 제외한 Claude 독립 판독 ZIP, 기존 빌더를 재사용한 사람 확인 대기 페이지를 만들었다. 실제 Claude 응답과 사람 확인은 아직 없으며 정답은 미확정이다. test 모델 출력·성능 수치·최종 평가 시도는 없다.

실제 응답을 받으면 불일치·모호함·해석 확인 전부와 나머지 일치 항목의 10%를 사례·문서 종류별로 선정한다. 사람 확인 페이지는 실제 Excel의 시트·행·ID·해시에 연결하고 원본 결과 JSON과 Excel 사본을 출처로 보존한다. 확인 수는 실제 대조 후 결정한다. 절차와 전달 파일은 [test 정답 안내](../../eval/test_review_preparation.md)에 있다.

정답 검증기가 표본 확인 출처를 dev에만 허용했으므로 test에도 같은 검증을 적용하도록 `evaluation_core.py`의 split 제한만 확장했다. test 예비 측정 차단은 유지했다. 기존 고정 기록은 보존하고 부모 해시·변경 파일을 파생 기록에 남겼다. qwen3 digest·설정, 프롬프트 v3, 가드 v3, AI 추출·판정·스키마 구현은 그대로다. 최종 평가는 실제 독립 판독·사람 확인 후 이 버전으로 한 번 실행한다.

## 화면에 제공할 API

- 검사별 상태·이유·원문 근거와 계약별 한 줄 확인 요약.
- 값별 규칙·AI 보완·사람 확인 출처와 AI 채택·거부 사유.
- 연락 방법·요청일·기한·메모·회신 대기 상태를 가진 재제출 요청 기록. 실제 연락을 발송하지 않으며 회신·취소 이력을 보존한다.
- 개인사업자·중소·중견 기본 설정, 필수 서류·담당/대표 표시 이름·최대 2단계 결재.

원본 해시가 바뀌면 이전 근거를 현재 원문 위치처럼 보여주지 않는다. DOCX는 문단·표 위치로 글자 근거를 제공하고 물리 페이지 배치는 미확인으로 기록한다. TXT는 글자 위치만 제공하며 가드의 채택 정책을 완화하지 않는다. 근거 조회 전 DB 읽기 트랜잭션을 해제하여 OCR 동안 DB 쓰기를 막지 않는다.

2단계 결재는 1단계 기록과 서로 다른 검토자를 요구하고 기존 최종 확인 API로 건너뛰지 못하게 했다. 자료 변경·반려 후에는 다시 1단계부터 확인한다. 기존 1단계 설정은 유지하고 법정 필수 서류나 새로운 권한 체계를 임의로 정하지 않는다. 상세 경로는 [API 인계](../../api/frontend_handoff.md)에 있다.

## 확인과 남은 작업

백엔드 전체 **228개 테스트 통과**(104.53초, 의존성과 datetime 관련 경고 971개). 최종 확인 완료·2단계 대기 요약을 보완한 뒤 관련 API 14개 테스트도 다시 통과했다. 새 확인은 임시 DB·직접 작성한 가상 원문으로 수행했고 실제 test 정답을 개발용 테스트에 넣지 않았다. 독립 판독의 split 격리·빈/미확정 답 차단·사람 확인 빈칸 유지, 권한·연락 기록·결재 우회·반려와 자료 변경·근거와 원본 변경을 확인했다. 사람 확인 페이지의 내장 JavaScript 문법 검사도 통과했다.

로컬 환경은 통합 실행기로 먼저 업무 백업을 저장하고 브라우저를 새로 열지 않고 서버를 시작했다. 새 API 경로가 서버에 등록됐고 `/health`는 200, 비로그인 회사 설정 요청은 401이었다. localhost 모드와 LLM 기본 비활성 설정을 유지했다. 새 운영 테이블만 생성하고 실제 회사 설정·계정·계약 자료를 수정하지 않았다.

frontend 변경 및 빌드는 하지 않았다. 새 성능 수치는 없으며 dev 수치를 test 결과로 사용하지 않는다. 남은 순서는 새 Claude 독립 판독 → 실제 응답 대조 → 사람 원문 확인 → test 정답 확정 → 고정 버전 최종 평가다. 화면 담당자는 인계한 API로 화면을 연결하고 디자인 변경 시 기존 승인 절차를 따른다.
