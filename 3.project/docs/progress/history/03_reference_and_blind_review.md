# 설계 초안과 독립 판독 준비 작업 기록

이 문서는 해당 작업 당시의 기록이다. 현재 상태는 [진행 요약](../development_report.md)을 확인한다.

## 생성 설계 초안과 Claude 독립 판독 준비

사람의 빈칸 작성 부담을 줄이기 위해 `build_reference_labels.py`를 추가했다. 앱 분류기·추출기·RuleEngine의 출력을 사용하지 않고 합성 서류의 생성 설계값과 라벨 기준에서 dev 계약 10건, 문서 59개의 초안을 작성한다. PDF는 별도 라이브러리로 텍스트를 읽고 DOCX는 문단·표 내용을 확인하며 PNG와 스캔 PDF는 동일 설계로 만든 이미지의 픽셀과 대조했다. 문서 59개가 모두 이 내용 대조를 통과했다. 코드와 생성기·기준 문서 해시를 함께 기록하여 예비 실행 전에 변경 여부를 검사한다.

초안에서 표시 합계가 잘못된 세금계산서는 원문 표시 합계를 추출 정답으로 두고 산술 검사를 FAIL로 둔다. 의미 없는 참고 금액의 내부 계산값을 알고 있어도 금액과 범위 4개 필드는 REVIEW로 남긴다. 이로써 생성 의도와 실제 표시 내용을 혼동하지 않는다. 내용과 픽셀 일치는 독립적인 사람 판독이나 페이지 읽기 가능성의 증거는 아니다.

이 PC의 Git `core.autocrlf=true` 설정은 새 체크아웃의 줄바꿈을 바꿀 수 있다. 자료·정답·기준 및 초안 생성 코드의 바이트가 바뀌면 내용이 같아도 해시가 달라지므로 루트 `.gitattributes`에서 평가 폴더와 두 생성 코드의 줄바꿈 변환을 끄고 원본 바이트를 보존했다. 기존 앱 파일의 줄바꿈 설정은 변경하지 않았다.

`reference_labels_dev.json`의 `confirmed`, `human_reviewed`, `claude_reviewed`는 모두 false다. 사람 정답과 test 정답은 변경하지 않았다. 초안용 `--preliminary`는 dev에만 허용하며 사람이 확정한 정식 결과와 다른 경로·제목·메타데이터로 저장한다. AI 작성자가 confirmed=true로 표시해도 정식 명령이 받아들이지 않는 테스트를 추가했다.

사용자는 Claude 로그인 대신 검토 파일을 직접 전달하기로 했다. `package_independent_review.py`는 허용 목록에 있는 dev 원본만 복사하며 등록 기준, 공통 기준, 빈 응답 양식과 프롬프트를 `claude_blind_review.zip`에 넣는다. 초안·생성 코드·앱 코드·추출 결과·성능 보고서·test 원본은 포함하지 않는다. 기존 Claude 대화는 이미 생성기를 읽었기 때문에 새 대화에서 독립 판독해야 한다. 원본 판독 방법과 근거를 응답에 남기게 했다. 이후 사용자가 새 Claude 대화에서 진행한 실제 응답을 전달했으며 완료 결과는 아래 후속 기록에 있다. Codex가 외부 API를 추가하거나 직접 자료를 전송한 것은 아니다.

원래 자료 목록의 문서별 검수 후보는 생성된 문서 유형에 따라 달라져 유형 정답을 추측하게 할 수 있다. 독립 판독 양식에는 모든 문서에 동일한 후보 목록을 주어 이 단서를 없앴다. `compare_reference_labels.py`는 실제 Claude 응답을 계약별로 합쳐서 버전과 중복 ID를 검사하고, 유형·필드 상태 및 값·검수 상태·누락 목록을 대조한다. 비어 있거나 원문을 읽지 못한 답은 UNANSWERED로 기록하며 일치로 세지 않는다.

사람 확인 목록에는 모든 불일치와 모호한 칸, 나머지 일치 칸의 무작위 20%를 넣는다. seed 42, 두 초안 해시, 계약별 표본 포함 여부를 기록하고 완료 상태는 false로 남긴다. 독립 초안이 서로 다르다는 사실만으로 서류가 잘못 생성됐다고 결론짓지 않는다. 모델 판독 오류나 기준 해석 차이도 원인일 수 있다. 표본 오류가 발견되면 범위를 넓히며 20%로 전체 정답 정확도를 보증하지 않는다.

### dev 예비 규칙 측정

| 지표 | 예비 결과 | 표본과 해석 |
| --- | ---: | --- |
| 분류 Macro F1 | 1.0000 | 사용자 유형 힌트와 유형 포함 파일명 없이 59개 분류 |
| 핵심 필드 정확도 | 78.34% | VALUE와 REVIEW 337칸 중 264칸 일치 |
| 누락 Recall | 100% | 실제 누락 2종 모두 검출, 작은 표본 |
| 교차검증 Macro F1 | 0.7530 | PASS·FAIL·REVIEW·MISSING 4개 상태 평균 |
| 문제가 있는 항목에서 잘못된 PASS | 0/17 | 이 표본에서 0건이며 안전성 보증이 아님 |
| PASS 중 잘못된 비율 | 0/49 | 정답 초안과 비교한 PASS 결과 기준 |
| 확인 필요 비율 | 25.0% | 채점 대상 검수 결과 기준 |
| 자동 추출값 제공 비율 | 63.0% | 전체 필드 413칸 중 260칸에 값 제공, 사람 승인율과 다름 |

FAIL 정답 4건 중 FAIL로 찾은 것은 1건이다. 따라서 잘못된 PASS가 0이라는 수치로 오류를 모두 검출했다고 주장하지 않는다. 필드별 상세 집계와 오류 ID는 `docs/eval/dev/preliminary/preliminary_rule.json`에 있으며 Markdown 및 CSV도 저장했다. 분류와 금액 정확도는 합성 서식에서의 개발용 결과이며 최종 발표 수치는 독립 판독·사람 확인 및 별도 test 평가 뒤에만 사용한다. LLM 도입 전 수치는 기록했지만 모든 목표를 달성했다고 설명하지 않는다.

이 단계에서는 앱 화면과 디자인을 수정하지 않았다. 평가 도구·자료·보고서는 `cc27b35 feat(eval): add synthetic baseline and blind review workflow`로 별도 저장했다. Git이 일부 이미지 PDF를 텍스트로 인식해 PDF 형식에 필요한 줄 끝 공백을 경고했으므로 PDF는 `.gitattributes`의 바이너리 diff 대상으로 지정했다. PDF 원본 바이트나 해시는 수정하지 않았다.
