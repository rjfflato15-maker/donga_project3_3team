## 사람 결과의 모호한 질문 1건

이창헌의 실제 test2 JSON은 81개 응답(확인 80·수정 필요 1·보류 0)이다. `404/40402/total_amount`의 원문에는 합계금액 라벨은 있고 숫자는 “확인인” 도장으로 읽을 수 없다. 질문이 “합계금액이라는 이름의 금액이 없다”라고 잘못 묻고 있었다. 사용자의 지적을 질문 문구 오류로 기록하고 REVIEW/null 정답은 유지했다. 원본 JSON의 수정 필요를 확인으로 바꾸지 않았다. 원래 질문 페이지·사용자의 이유·원문/양식 해시·정정 근거를 따로 보존했다. 81칸을 다시 확인할 필요는 없다.

사람 직접 확인 81항목·AI 일치 채택 459항목으로 정답을 확정했다. 사람 전수 검수라고 표현하지 않는다. [준비·정답 출처](../../eval/test2/preparation/README.md)를 확인한다.

추가로 전체 질문을 점검했다. N/A 18문항은 상태 직접 확인이 아니라 파일 열림·가독성·계산 일치 등 원문 사실의 확인이었다. 81개는 원문을 읽고 답한 건수이며 상태·값 라벨 직접 질문은 63개다. 나머지 18개의 N/A 상태는 기존 명세와 독립 판독 일치에 근거하므로 사람이 상태까지 직접 확정했다고 보고하지 않는다. 79문항의 수락 유도 문구도 새 빌더에서 제거했다. 원래 제출한 질문·답·정답 값·고정 예측·점수는 그대로 보존하고 [점검 기록](../../../eval/reconciliation-test2-v1/question_wording_scope_audit.json)을 추가했다.

## 평가 결과와 한계

v3 test는 기존 고정 예측을 채점했고 네 조건은 75.67% / 83.09% / 94.66% / 77.74%다. test2는 버전 고정 뒤 36문서의 예측을 1회 보존했고 추가 추론·가드 실행 0회로 채점했다. test2 네 조건은 **91.67% / 90.20% / 97.55% / 95.59%**다. 가드 적용이 가드 없는 조건보다 낮다는 결과도 그대로 기록했다. 잘못된 PASS는 네 조건 모두 0/7이고, 이번 N/A→PASS는 0이다. 가림 1건은 가드가 REVIEW로 처리했지만 일반적 안전성 우월성은 입증하지 못했다. 자료가 다른 v3/test2를 직접 향상률로 비교하지 않는다.

[최종 test2 보고서](../../eval/test2/final_four_modes.md)에는 분모·처리 시간의 범위·정답 VALUE 거절·읽을 수 없는 값 1건·사람 표본 확인·합성 자료 제한을 적었다. [dev2 네 조건](../../eval/dev2/four_mode_scores/preliminary_dev2_unconfirmed_2d66ff4b6db71733_694c2dfa03c7.json)은 사람 확인 전이다. dev2 N/A→PASS 1건은 별도로 남아 있고 test2 결과로 덮지 않는다. 시간 절감은 측정하지 않았다.

## 전체 검증과 다음 통합

칸별 확인 커밋 `6af74e2` 기준 백엔드 전체 테스트 353개가 통과했다. 사람 확인 범위·기존 LLM·근거·재발행·결재·성과 관련 74개도 통과했고 질문 추가 수정 관련 27개도 통과했다. frontend 테스트 14개와 TypeScript/Vite 빌드는 통과했고 Codex의 frontend 수정은 없다. test2 확인 페이지는 설치된 Edge와 번들 Playwright로 원문·이동·확대·저장·모바일 배치를 확인했고 콘솔·HTTP 오류는 0이었다. 새 질문 문구도 별도 브라우저 문맥의 미리보기로 확인했다. 답은 생성하지 않았고 N/A 구분·유도 문구 제거·기존 원문 표시를 확인했으며 콘솔·HTTP 오류는 0이었다.

병행 세션의 [고객 점검](../../research/customer-audit-2026-10-03/README.md)에서 지적한 전체 사람 확인 표시는 수정했다. 후속 사용자 메시지와 Git에서 재발행·버전 비교·좌표 UI 연결 `feat/ui-polish`의 `bc0f575`를 확인했다. main 병합 전이며 비동기 처리 UI는 동결 전 범위에서 제외하기로 했다. 병행 세션은 미리보기 전용 PNG 가림·계약 ZIP·도우미·요약 응답·작업시간 측정 절차를 작성 중이다. 원값을 편집·요청에 표시하는 범위는 화면 안내로 설명하기로 했으며 이를 전부 오류라고 보고하지 않는다. 새 INFORMATIONAL_NOTICE 응답이 들어온 작성 중 코드의 통합 시험은 기존 테스트 기대값과 달라 1건 실패(358 통과)했다. 해당 세션의 구현·테스트 완료 뒤 통합을 검증한다. 그 작업 파일을 이 세션의 커밋에 포함하거나 대신 고치지 않았다. API 테스트 통과를 실제 UI 연결 완료로 보고하지 않는다. 근거 확인·수정·재발행·재결재의 완료 조건은 backend 흐름에서 검증했고 화면에서도 이어서 시연해야 한다.
