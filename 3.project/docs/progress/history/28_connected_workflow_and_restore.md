# 연결 흐름·복원 리허설과 표시 근거 오류 수정

일정을 기다리지 않고 가능한 검증을 진행해 달라는 요청에 따라 실제 API 흐름과 백업 복원을 점검했다.
시작 시 main과 feat/ui-polish는 이미 `81af2b6`이었다. 이번 작업은 브랜치 병합·frontend 수정·실행 중 서버 재시작을 하지 않았다.

인증된 API 흐름의 102개 확인 항목, 관련 회귀 테스트 78개를 통과했다. 담당자/대표 로그인·비밀번호 변경, 누락·보완 요청, 금액 차이·재발행, 칸별 확인, 맡기기 완료, 회신 처리, 대표 확인, 가림/원본 ZIP 다운로드를 연결했다.
백업을 새 폴더로 복원하고 테이블 10개·파일 36개가 일치함을 확인했다. 이전 세션은 거부되고 새 로그인 뒤 기존 업무 상태와 ZIP 다운로드가 유지됐다.

실제 점검 중 금액·발행일 근거 표시가 공급받는자 구역 필터로 누락되는 오류를 발견해 `review_context_service.py`만 수정했다. 상호/사업자번호의 공급자 필터, 중복 근거 AMBIGUOUS, 원본 해시 검사와 사람 확인 범위는 유지했다.
기존 예측·LLM 모델·프롬프트·가드·검수 규칙·정답·평가 수치는 바뀌지 않았다. dev 기반 자료만 사용하고 보호 자료·외부 접속 차단을 API 작업 스레드에도 적용했다.

[전체 확인 범위·한계·재현 방법](../../operations/workflow_rehearsal.md), [API 인계](../../api/frontend_handoff.md), [5분 시연 대본](../../operations/demo_rehearsal_script.md)에 정리했다.
이번 결과는 API 연결 검사다. 브라우저 버튼·취소·파일 저장과 최종 측정 빌드 고정은 별도 확인 대상으로 남긴다. 시간 절감 실측으로 표현하지 않는다.
