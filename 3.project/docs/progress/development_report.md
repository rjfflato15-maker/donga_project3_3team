# 계약 증빙 자동검수 진행 요약

이 문서는 합의한 기준과 현재 상태만 관리한다. 단계별 변경 내용·검증 근거는 아래 작업 기록에 보존한다. 새 변경은 담당 문서에 기록하고 이 요약에는 상태와 링크만 갱신한다.

## 합의한 범위와 일정

기존 안정화 → 정답표·기준 성능 → 로컬 LLM·근거 검증 → 비교 평가 순서를 유지했다. 남은 작업의 합의 일정은 다음과 같다.

| 기간 | 할 일 | 담당 |
| --- | --- | --- |
| 10/3~10/5 | 고도화 API·UI 연결·시연 준비, dev2 사람 확인, test2 고정 평가 보존 | Codex·Claude. 사용자는 필요한 원문 확인과 결과 JSON 전달 |
| 10/5(월) 밤 | 새 기능 동결·UI 추가 변경 확인·병합 전 알림·전체 테스트 | 21시 이 대화의 후속 점검 예약. 변경된 UI가 있을 때 통합 |
| 10/6(화) | 팀원 5초 테스트 + 시간 비교 과제 2개(누락·재발행), 방식당 10분 상한 | 팀원 참여, 과제 안내문은 Claude |
| 10/7(수) | 팀원 테스트에서 발견한 문제 수정 → 시연 리허설 → 최종 상태 확인 | Codex·Claude·사용자. 새 기능 추가 없이 수정·검증 |
| 10/10 / 10/11 / 10/12 | 설명 문서·소스 제출 / 발표 자료 제출 / 발표 | 팀 |

Codex는 평가 보존·백엔드 API·통합·사내망 시연 안내를 맡는다. Claude는 `C:\3조 색인-ui`에서 frontend와 과제 테스트 안내문을 맡으며, 현재 추가 UI 작업 브랜치는 `feat/ui-polish`다. 10/5 병합 전에는 사용자에게 먼저 알리고 최신 UI 커밋을 확인한다. frontend 충돌은 UI 브랜치 기준으로 처리한다. 병합 후 전체 테스트·빌드와 사용자 화면 확인을 거친 커밋으로 화요일 측정을 고정한다. v3 test와 v4 test2의 예측은 각각 고정·보존했으며 이후 정답 변경은 모델 재실행 없이 재채점만 한다. 로컬 커밋만 하고 push·PR은 하지 않는다. 사람 확인은 약 15분을 목표로 하지만 실제 확인 속도와 수정·보류 여부에 따라 달라질 수 있다.

평가의 35%는 LLM 사용 여부 하나가 아니라 요구 분석, 구조 설계, AI와 도구의 활용, 결과 신뢰성을 함께 다룬다. LLM을 사용했다는 사실과 실제 성능 개선을 구분해서 보고한다. 할루시네이션을 완전히 해결했다고 표현하지 않고, 근거 검증과 사람 검토로 잘못된 추출의 위험을 줄인 범위를 설명한다.

## 현재 상태와 남은 작업

dev의 113칸은 사람이 원문으로 확인했고, 나머지 781칸은 두 AI 초안의 일치로 검증했다. 확정 dev 비교와 가드 v3 고정은 완료했다. test Claude 응답 10개와 원본 묶음의 81개 수령 해시를 확인했고 두 초안 894칸이 모두 일치했다. 불일치·미응답은 각각 0칸이다. **test는 이창헌이 134칸(해석 46·모호 3·일치 10% 표본 85)을 원문으로 확인했고, 나머지 760칸은 두 AI 초안의 일치로 검증했다.** 실제 결과 JSON을 보관하고 정답을 확정했다. 사람 전수 검수가 아니다. 고도화 세션의 v3 예측 1회가 고정된 뒤 패키지 해시를 검증하고 확정 정답으로 채점했다. 이 채점의 추가 추론·가드 재실행은 0회다.

[확정 test 결과](../eval/test/final/four_modes.md)의 필드 정확도는 규칙만 75.67%, LLM만 83.09%, 규칙+LLM 가드 없음 94.66%, 가드 있음 77.74%다. 가드가 정답 일치 제안 100건도 거부해 test에서 성능을 크게 제한했다. 가드 적용은 필드 정확도 목표 90%에 미달했다. 잘못된 PASS는 네 조건 모두 0건으로 이번 평가에서 가드의 안전성 우월성은 입증하지 못했다. 기존 dev 수치와 test 수치를 혼합하지 않는다. 개선은 별도 dev2·test2에서 다루며 v3 test는 튜닝이나 재추론에 사용하지 않는다.

별도 [가드 v4 dev2 예비 비교](../eval/dev2/guard_v4/preliminary_comparison.md)에서는 동일 AI 응답으로 필드 정확도 97.55%→99.51%, 보완 대상 필드의 미해결·추가 확인 비율 50%→16.67%를 확인했다. dev2 정답은 아직 설계 초안이며 독립 판독·사람 확인 전이다. 도장 가림 사례의 N/A→PASS 오류 1건은 남아 있다. v4는 명시 선택 옵션이고 기본 v3·LLM 꺼짐은 유지했다. v3 test 결과를 본 뒤 개선을 선택했으므로 v4의 독립 최종 성능은 버전 고정 뒤 미사용 test2로 확인해야 한다.

[test2 확인 준비](../eval/test2/preparation/README.md)는 기존 새 계약 6건·PDF 36개를 재사용했다. 실제 Claude 응답 6개를 대조하고 이창헌이 81항목을 직접 확인했다. 나머지 459항목은 AI 일치로 채택했다. 80개 확인·1개 수정 필요의 원본 답은 그대로 보존했다. 수정 필요 1건은 숫자가 가려진 상태를 “합계금액이라는 이름의 금액이 없다”라고 물은 질문 문구 오류였다. 라벨은 있지만 금액은 읽을 수 없어 REVIEW/null 정답을 유지하고 원본 답·원문 근거·정정 기록을 별도로 보관했다. 재확인은 필요 없다.

고정 v4 예측 1회와 추가 추론·가드 실행 0회의 채점을 완료했다. [test2 최종 네 조건 결과](../eval/test2/final_four_modes.md)는 91.67% / 90.20% / 97.55% / 95.59%다. 가드 적용은 규칙만보다 높고 가드 없는 조건보다 1.96%p 낮다. 도장으로 가려진 1칸은 가드가 REVIEW를 유지했지만 정답 VALUE 제안 9개도 거절했다. 잘못된 PASS는 네 조건 모두 0/7, N/A→PASS도 0이라 일반적 안전성 우월성은 주장하지 않는다. dev2의 N/A→PASS 1건은 별도 자료에서 남은 오류이며 test2 결과로 지워 쓰지 않는다.

전체 질문 추가 점검에서는 N/A 18문항이 상태 대신 원문 사실을 물었고 79문항에 수락 유도 문구가 있었다. 81개 원문 확인을 81개 라벨 직접 확정으로 표현하지 않는다. 직접 라벨 질문은 63개, 나머지 N/A 18개의 상태 근거는 명세·독립 판독 일치다. 새 빌더의 문구를 고치고 점검 기록과 이 한계를 보고서에 추가했다. 원래 답·현재 정답 값·점수는 변경하지 않았다.

검사 이유·근거, 값별 출처와 AI 제안 사유, 계약별 확인 요약, 재제출 연락 기록, 회사 유형·필수 서류·역할 표시·최대 2단계 결재 API를 추가했다. 계약 목록은 공통 한 줄 요약·회신 대기 건수·가장 이른 대기 기한·다음 결재 단계와 `open_issue_count`를 제공한다. 두 한 줄 요약과 문제 수는 NTS disabled의 BUSINESS_STATUS REVIEW를 제외하지만 원래 검사·판정은 유지한다. [frontend 담당자용 안내](../api/frontend_handoff.md)에 사용법을 정리했다. 통합 실행기·운영 안내와 역할별 소스·문서 정리, 승인한 EXE 아이콘과 [팀 공유 문안](team_update.md)은 이전 작업으로 완료했다.

C업체는 직원 6명·월 약 150건·담당자 1명과 대표 최종 확인이라는 시범 가정으로 [프로필](../architecture/c_company_profile.md)을 정리했다. 소기업 1단계 결재와 중견 2단계 확장 설계를 구분하고 법적 규모는 단정하지 않는다. dev 다섯 사례·원본 28개로 규칙만/기존 AI 보완 결과 두 개의 [시연 전용 업무함](../operations/demo_inbox.md)을 준비했다. AI 비교는 고정 dev 응답 캐시 재생이며 실시간 LLM 시연이 아니다. [설명 문서 목차](../submission/explanation_outline.md)는 작성 재료와 test 결과 자리를 정리한 초안이다.

연휴 고도화 0~8과 추가 처리 상태 API를 완료했다. 실제 근거 bbox·원본 해시·revision, 명시적인 추가/재발행·이전 버전 제외·결재 무효화, 실제 필드 변경/성과·LLM 설정/연결/문서별 기록, 권한을 지키는 맡기기, 검증된 코드 요약, DB 변경 없는 도우미 초안, 중복 게시 없는 업로드 작업/재시도를 제공한다. 고객 점검에서 나온 전체 필드의 사람 확인 오표시도 실제 변경·명시 확인한 칸만 표시하도록 수정했다(`6af74e2`). [API 인계 문서](../api/frontend_handoff.md)에 JSON·오류·revision 규칙을 기록했다. [연휴 작업 기록](history/23_holiday_backend_and_test2.md)에 각 커밋·검증을 정리했다.

Claude UI 브랜치 `8e7b2c2`를 main에 충돌 없이 병합했다(`a8c8b89`, 추가 보완 `ee14d57`). 칸별 확인 `6af74e2`의 전체 353개와 질문 점검 27개 통과 후, 이번 고객 점검 보완까지 포함한 **백엔드 전체 381개, frontend 테스트 14개와 빌드가 통과했다.** 중간에 도우미 INFORMATIONAL_NOTICE의 이전 기대값 때문에 실패했던 1건은 새 정책·테스트를 함께 맞춰 해결했다. 신규 API의 화면 연결 완료를 뜻하지 않는다. 재발행·버전 비교·좌표 연결은 Claude의 별도 `feat/ui-polish` 커밋 `bc0f575`에 있고 main 병합 전이다. 새 업로드 작업 화면은 동결 전 구현에서 제외했다. 같은 값의 사람 확인은 confirmed_fields로 기록하며 바뀐 칸만 보내는 부분 수정도 지원한다. 미리보기 전용 PNG 가림, 계약별 ZIP, 도우미·요약 응답 보완은 완료했고 [후속 기록](history/24_contract_bundle_and_display_alignment.md)에 정리했다. [작업시간 비교](../operations/team_test_measurement.md)는 측정 절차 초안이며 실측 절감 수치는 없다. [팀원 접속 한 장 안내](../operations/team_test_network.md)는 같은 네트워크에서 8021 시연 업무함과 담당자·대표 두 계정을 사용하는 절차다. 실제 사내망 허용과 방화벽 변경은 아직 하지 않았다.

v3 test와 v4 test2의 정답 확정·예측 보존·확정 채점과 요청한 백엔드 고도화는 완료했다. 남은 작업은 dev2 독립 판독·사람 확인, 새 API의 UI 연결·전체 흐름 시연, 화요일 팀원 테스트와 발견한 문제 수정, 최종 제출 문서 작성·시연 리허설이다. 시간 절감은 수동 검수와 앱 검수의 실제 작업 시간을 각각 재기 전에는 주장하지 않는다. 판매용 패키징·2차 인증·자동 업데이트는 별도 범위다.

추가 분석에서 test2 가드 오류는 금액 빈칸 5개를 포함한 빈칸/UNKNOWN 9개였다. 가드 없는 조건은 빈칸 4개와 잘못 채운 금액 1개다. 필드 204칸의 정답 출처는 사람 직접 라벨 확인 39개·사람 관찰 후 기준 적용 1개·AI 일치 164개로 나누었다. [추가 분석](../eval/test2/result_audit/README.md)과 [중립 20문항 안내](../../eval/human_review_page_test2_neutral/README.md)에 근거를 보존했다. test3는 [동결 뒤 계획](../eval/test2/test3_plan.md)만 작성했다.

Claude가 전달한 추가 UI 통합 보고도 코드와 대조했다. 값 수정 후 맡기기 COMPLETE가 stale 이유로 막히는 문제는 [현재본 완료 허용·이전본 차단](history/26_assignment_completion_after_correction.md)으로 수정했다. 권한·처리 메모·동시 수정 검사는 유지하고 배정/완료 당시 자료 기준을 감사 기록에 남긴다. 업무 완료로 계약 결재가 바뀌지 않는다. ZIP의 masked=false 감사 기록은 확인했고, 실제 버튼 다운로드·취소·원본 확인 흐름은 병합 후 사용자 화면 검증에 포함한다.
