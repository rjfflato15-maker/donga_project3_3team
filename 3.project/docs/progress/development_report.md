# 계약 증빙 자동검수 진행 요약

이 문서는 합의한 기준과 현재 상태만 관리한다. 단계별 변경 내용·검증 근거는 아래 작업 기록에 보존한다. 새 변경은 담당 문서에 기록하고 이 요약에는 상태와 링크만 갱신한다.

## 합의한 범위와 일정

실행 순서는 0번 안정화, 2A 정답표와 기준 성능, 1번 로컬 LLM과 근거 검증, 2B 비교 평가, 3번 업무 흐름 보완, 4번 결과 설명, 선택 5번 검수 에이전트, 6번 제출 문서이다. 필수 범위는 안정화와 평가 준비 및 LLM과 비교 평가이며 10월 5일을 목표로 한다. 10월 7일 저녁에 기능을 동결하고 10월 8일부터 문서와 시연 준비를 진행한다.

3번과 4번은 필수 범위가 끝난 뒤 10월 6일까지 진행하는 권장 범위다. 선택 에이전트는 10월 7일 오전까지 완성하지 못하면 향후 계획으로 돌린다. 안내문의 제출 일정은 설명 문서와 소스 코드 10월 10일, 발표 자료 10월 11일, 발표 10월 12일이다. 기능 동결 후에는 시연과 문서 확인을 우선한다.

평가의 35%는 LLM 사용 여부 하나가 아니라 요구 분석, 구조 설계, AI와 도구의 활용, 결과 신뢰성을 함께 다룬다. LLM을 사용했다는 사실과 실제 성능 개선을 구분해서 보고한다. 할루시네이션을 완전히 해결했다고 표현하지 않고, 근거 검증과 사람 검토로 잘못된 추출의 위험을 줄인 범위를 설명한다.

## 앞선 검토에서 추가한 결정

| 항목 | 결정 | 현재 상태 |
| --- | --- | --- |
| 평가 순서 | 정답 초안으로 예비 측정, 독립 판독과 사람 확인 뒤 정식 기준 성능 및 LLM 효과 비교 | 113칸 사람 확인 반영·dev 정답 확정·규칙 기준 성능 측정 완료 |
| 비교 조건 | 규칙만, LLM만, 규칙과 LLM 가드 없음, 규칙과 LLM 가드 있음의 네 조건 | 확정 dev 네 조건 측정 완료 |
| 가드 비교 | 동일한 LLM 제안에 가드를 적용하기 전과 후를 비교하여 모델 출력 변동과 가드 효과를 분리 | 해시 검증 응답 캐시와 ③·④ 동일 응답 재사용 구현 |
| 평가 자료 | 기존 샘플은 개발용으로만 사용하고 새로운 서식 계열은 최종 평가용으로 분리 | 새 합성 자료 dev와 test 각 10개 계약 생성 |
| 정답 | 앱 추출 결과를 참조하지 않고 생성 설계 초안과 독립 원문 판독을 대조, 사람이 불일치와 표본 확인 뒤 확정 | 사람 직접 확인 113칸(해석·모호함 26칸, 일치 10% 표본 87칸), AI 일치 채택 781칸 |
| 모호한 값 | 사람이 의미를 확정할 수 없는 값은 확인 필요가 정답 | 라벨링 안내와 측정 도구에 반영 |
| 근거 검증 | 원문 존재, 위치, 필드 의미, 공급자 구역, 후보 모호성, 형식과 산술을 확인 | 가드 v3 dev 감사 조정 완료, DOCX는 문단·표 위치로 글자 근거 확인·페이지 배치 미확인 |
| LLM 호출 범위 | 규칙 추출이 실패했거나 값이 모순인 필드부터 보완하고 최종 일치 판정은 규칙으로 처리 | 실패·모순 필드만 호출, 최종 판정 RuleEngine 유지 |
| 근거 보기 | 페이지와 위치를 저장하고 채택하거나 거부한 AI 값의 근거와 사유를 함께 제공 | 저장·API 구조 완료, 화면은 시안 승인 후 구현 |
| 추출 점수 | 키워드 점수에서 만든 분류 수치는 실측 정확도가 아니므로 분류 점수로 표시 | 화면 반영 예정 |
| 실패 처리 | LLM 실패 시 규칙 결과와 실패 사유를 남기고 수동 검토를 허용 | 규칙 보존·오류 코드·수동 확인 상태 저장 및 기존 담당자 확인 API 연결 |
| 요약 | 코드가 검수 항목에 연결된 값을 채우며, 자리표시자의 의미와 문장 상태도 검증 | 구현 예정 |
| 업무 흐름 | 이미 있는 보완 요청과 자료 변경 시 재확인을 유지하고 빠진 부분만 추가 | 기존 구현 확인 |
| 모델 비교 | qwen3와 gemma3를 dev에서 먼저 비교하고 작은 GPU 메모리에 부담이 큰 모델은 우선순위를 낮춤 | dev 8문서 비교로 qwen3:latest 8.2B Q4_K_M 선택 |
| 로컬 실행 | 외부 API를 추가하지 않고 Ollama 클라우드 비활성화와 사용 모델 라이선스도 확인 | 실제 서버 cloud disabled=true 확인, 공식 라이선스 링크와 실행 안내 기록 |
| 선택 에이전트 | 재추출과 규칙 재실행으로 조사한 초안만 미리보기로 제공하고 자동 저장 또는 보완 요청 발송을 하지 않음 | 필수 범위 이후 검토 |
| 화면 디자인 | 변경 계획과 이미지 시안을 먼저 보여 주고 사용자의 명시적 승인 뒤 적용 | 이번 작업에서 화면 변경 없음 |

정답 파일의 해시는 특정 파일 버전을 식별하는 값이다. 해시만으로 사람이 검수했거나 과거에 파일이 바뀌지 않았다는 사실을 증명할 수는 없다. 검수자, 확정 일시, 자료 해시를 함께 기록하고 이후 변경은 새 버전으로 남긴다. 숫자를 자리표시자로 바꾸더라도 계약금액을 차액으로 설명하는 의미 오류는 가능하므로 문장 검증이 필요하다.

## 현재 상태와 남은 작업

113칸은 사람이 원문으로 확인했고, 나머지 781칸은 두 AI 초안의 일치로 검증했다. 확정 dev 비교와 가드 v3 고정은 완료했다. test 문서·정답은 열지 않았으며 최종 평가를 실행하지 않았다. 통합 실행기·운영 안내는 완료했고 이번에는 실행기 소스와 문서를 역할별로 정리했다.

남은 작업은 test 정답 확인·확정 후 고정 버전의 1회 최종 평가, 승인받은 근거 화면, 제출 문서·시연 준비다. 판매용 패키징·2차 인증·자동 업데이트는 별도 범위다.

## 확인 자료

평가 항목과 제출 일정은 `자료/3차_프로젝트_안내사항.pdf`, 기능 마무리와 저작권 검토는 3주차 피드백, 성능 목표는 `자료/3조 기획서.pdf`, 역할과 서비스 구성은 기획서 v4를 참고했다. 앞선 제안의 “35%가 비어 있다”, “원문에 있으면 안전하다”, “분류 점수는 정확도다”, “숫자를 자리표시자로 바꾸면 의미 오류가 없다”는 표현은 이 보고서에서 사실로 채택하지 않았다.
