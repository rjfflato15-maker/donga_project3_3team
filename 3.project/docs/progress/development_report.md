# 계약 증빙 자동검수 진행 요약

이 문서는 합의한 기준과 현재 상태만 관리한다. 단계별 변경 내용·검증 근거는 아래 작업 기록에 보존한다. 새 변경은 담당 문서에 기록하고 이 요약에는 상태와 링크만 갱신한다.

## 합의한 범위와 일정

기존 안정화 → 정답표·기준 성능 → 로컬 LLM·근거 검증 → 비교 평가 순서를 유지했다. 남은 작업의 합의 일정은 다음과 같다.

| 기간 | 할 일 | 담당 |
| --- | --- | --- |
| 10/3~10/5 | test 대조·사람 확인·정답 확정·고정 버전 최종 평가, API·UI 연결·시연 준비 | Codex·Claude. 사용자는 test 원문 확인과 결과 JSON 전달 |
| 10/6(화) | 팀원 5초 테스트 + 과제 테스트 3개 | 팀원 참여, 과제 안내문은 Claude |
| 10/7(수) | 발견한 문제 수정 → 시연 리허설 → 저녁 기능 동결 | Codex·Claude·사용자 |
| 10/10 / 10/11 / 10/12 | 설명 문서·소스 제출 / 발표 자료 제출 / 발표 | 팀 |

Codex는 test 확인 준비·백엔드 API·통합·사내망 시연 안내를 맡는다. Claude는 `feat/ui-flow-redesign` 브랜치, `C:\3조 색인-ui`에서 frontend와 과제 테스트 안내문을 맡는다. UI 병합 전에는 사용자에게 먼저 알리고, frontend 충돌은 UI 브랜치 기준으로 처리한다. 모델·프롬프트·가드 v3는 최종 평가 완료까지 고정하며 로컬 커밋만 한다. 사람 확인은 약 15분을 목표로 하지만 실제 확인 속도와 수정·보류 여부에 따라 달라질 수 있다.

평가의 35%는 LLM 사용 여부 하나가 아니라 요구 분석, 구조 설계, AI와 도구의 활용, 결과 신뢰성을 함께 다룬다. LLM을 사용했다는 사실과 실제 성능 개선을 구분해서 보고한다. 할루시네이션을 완전히 해결했다고 표현하지 않고, 근거 검증과 사람 검토로 잘못된 추출의 위험을 줄인 범위를 설명한다.

| 근거 검증 | 원문 존재, 위치, 필드 의미, 공급자 구역, 후보 모호성, 형식과 산술을 확인 | 가드 v3 dev 감사 조정 완료, DOCX는 문단·표 위치로 글자 근거 확인·페이지 배치 미확인 |

| 근거 보기 | 페이지와 위치를 저장하고 채택하거나 거부한 AI 값의 근거와 사유를 함께 제공 | 검사별 근거·필드 출처 API 완료, 원본 변경 시 이전 근거 차단, frontend 담당자용 API 안내 제공 |
| 추출 점수 | 키워드 점수에서 만든 분류 수치는 실측 정확도가 아니므로 분류 점수로 표시 | 화면 반영 예정 |
| 실패 처리 | LLM 실패 시 규칙 결과와 실패 사유를 남기고 수동 검토를 허용 | 규칙 보존·오류 코드·수동 확인 상태 저장 및 기존 담당자 확인 API 연결 |
| 요약 | 코드가 검수 항목에 연결된 값을 채우며, 자리표시자의 의미와 문장 상태도 검증 | 구현 예정 |
| 업무 흐름 | 이미 있는 보완 요청과 자료 변경 시 재확인을 유지하고 빠진 부분만 추가 | 연락 방법·요청일·기한·메모·회신 대기 기록, 회사 유형 설정과 최대 2단계 결재 API 추가 |
| 모델 비교 | qwen3와 gemma3를 dev에서 먼저 비교하고 작은 GPU 메모리에 부담이 큰 모델은 우선순위를 낮춤 | dev 8문서 비교로 qwen3:latest 8.2B Q4_K_M 선택 |
| 로컬 실행 | 외부 API를 추가하지 않고 Ollama 클라우드 비활성화와 사용 모델 라이선스도 확인 | 실제 서버 cloud disabled=true 확인, 공식 라이선스 링크와 실행 안내 기록 |
| 국세청 조회 | `APP_NTS_MODE` 전환 구조 유지. 시연·평가는 항상 `disabled`(미연동). 가상 번호 조회는 평가 의미가 없고 외부 통신은 사내망 기본 원칙과 맞지 않음. 공식 연동은 공공데이터포털 국세청 사업자 상태조회 API만 사용하고 홈택스 스크래핑은 쓰지 않음 | 시연 준비·실행 모두 disabled 강제, [설정과 이유](../operations/demo_inbox.md#합의한-국세청-조회-정책) 기록 |
| 선택 에이전트 | 재추출과 규칙 재실행으로 조사한 초안만 미리보기로 제공하고 자동 저장 또는 보완 요청 발송을 하지 않음 | 필수 범위 이후 검토 |
| 화면 디자인 | 변경 계획과 이미지 시안을 먼저 보여 주고 사용자의 명시적 승인 뒤 적용 | 이번 작업에서 화면 변경 없음 |

정답 파일의 해시는 특정 파일 버전을 식별하는 값이다. 해시만으로 사람이 검수했거나 과거에 파일이 바뀌지 않았다는 사실을 증명할 수는 없다. 검수자, 확정 일시, 자료 해시를 함께 기록하고 이후 변경은 새 버전으로 남긴다. 숫자를 자리표시자로 바꾸더라도 계약금액을 차액으로 설명하는 의미 오류는 가능하므로 문장 검증이 필요하다.

## 현재 상태와 남은 작업

dev의 113칸은 사람이 원문으로 확인했고, 나머지 781칸은 두 AI 초안의 일치로 검증했다. 확정 dev 비교와 가드 v3 고정은 완료했다. test Claude 응답 10개와 원본 묶음의 81개 수령 해시를 확인했고 두 초안 894칸이 모두 일치했다. 불일치·미응답은 각각 0칸이다. 사람 확인 페이지에는 꼭 볼 것 49칸과 일치 10% 표본 85칸, 총 134칸을 준비했다. 사람 확인은 아직 0칸이며 정답 미확정·최종 평가 미실행이다. 추출·판정·모델·프롬프트·가드는 바꾸지 않았다.

검사 이유·근거, 값별 출처와 AI 제안 사유, 계약별 확인 요약, 재제출 연락 기록, 회사 유형·필수 서류·역할 표시·최대 2단계 결재 API를 추가했다. 대시보드가 계약마다 상세 요청을 하지 않도록 계약 목록에도 공통 한 줄 요약·회신 대기 건수·가장 이른 대기 기한·다음 결재 단계를 제공한다. [frontend 담당자용 안내](../api/frontend_handoff.md)에 경로와 데이터 사용법을 정리했고 `frontend/`는 수정하지 않았다. 통합 실행기·운영 안내와 역할별 소스·문서 정리, 승인한 EXE 아이콘과 [팀 공유 문안](team_update.md)은 이전 작업으로 완료했다.

C업체는 직원 6명·월 약 150건·담당자 1명과 대표 최종 확인이라는 시범 가정으로 [프로필](../architecture/c_company_profile.md)을 정리했다. 소기업 1단계 결재와 중견 2단계 확장 설계를 구분하고 법적 규모는 단정하지 않는다. dev 다섯 사례·원본 28개로 규칙만/기존 AI 보완 결과 두 개의 [시연 전용 업무함](../operations/demo_inbox.md)을 준비했다. AI 비교는 고정 dev 응답 캐시 재생이며 실시간 LLM 시연이 아니다. [설명 문서 목차](../submission/explanation_outline.md)는 작성 재료와 test 결과 자리를 정리한 초안이다.

남은 작업은 [test 응답 대조와 사람 확인](../eval/test_review_preparation.md), 정답 확정 후 고정 버전의 1회 최종 평가, frontend 담당자의 승인받은 화면 연결, 최종 제출 문서 작성·시연 리허설이다. 판매용 패키징·2차 인증·자동 업데이트는 별도 범위다.

## 확인 자료

평가 항목과 제출 일정은 `자료/3차_프로젝트_안내사항.pdf`, 기능 마무리와 저작권 검토는 3주차 피드백, 성능 목표는 `자료/3조 기획서.pdf`, 역할과 서비스 구성은 기획서 v4를 참고했다. 앞선 제안의 “35%가 비어 있다”, “원문에 있으면 안전하다”, “분류 점수는 정확도다”, “숫자를 자리표시자로 바꾸면 의미 오류가 없다”는 표현은 이 보고서에서 사실로 채택하지 않았다.
