# 기존 화면 vs Codex 사이드바 새 안

2026-10-06. 사용자 선택대로 새 안은 **Codex 사이드바 디자인 하나**다. Claude ERP 새 시안은 포함하지 않는다. Claude가 재현해 둔 이전 앱 구조는 왼쪽 비교 자료로만 읽어서 사용했다. 원본 작업 폴더는 수정하지 않았다.

## 열기

- 로컬 비교: http://127.0.0.1:8074/comparison/ui_compare.html
- 독립 파일: 이 폴더의 `ui_compare.html`. 이미지·스타일·비교 스크립트를 모두 포함한다. 이 파일 하나로 비교·확대·의견 입력·TXT 저장이 가능하다.
- ‘새 안 클릭 시안’까지 함께 전달할 때는 같은 폴더에 `codex-workflow.html`도 둔다. `codex-workflow.html?story=inbox`에서 시작한다. 이 파일은 React 빌드를 모두 포함하며 백엔드가 필요 없다.
- 기존 독립 예시 `codex-sidebar-example.html`의 시작 화면은 그대로 대표 결재다. 새 흐름 모드는 `?story=`로 분리했다.

## 내용

1. 대표 화면 6개: 업무함, 계약 상세/누락, 원문 대조, 묶음 요청, 부분 회신, 대표 결재.
2. 같은 계약 14단계: 업무함 → 서류 선택 → 계약 기준 확인 → 누락·불일치 → 원문 대조 → 요청 작성 → 회신 대기 → 부분 회신 → 고친 본 → 재검토 → 대표 전달 → 대표 결재 → 지급 기록 → 완료.
3. 예외 4개: 반려, 판독/근거 확인 필요, 저장 충돌, 기존 지급 재확인. 앞의 3개는 기존 화면 캡처가 없어 새 안만 표시한다.
4. 모바일 3개: 업무함, 대표 결재, 원문 대조. 기존 모바일 자료가 없어 새 안만 표시한다.

가상 새봄기획 / 업무지원 시스템 구축 / 부가세 포함 3,410,000원으로 통일했다. 최초 견적서 원문·저장값은 3,520,000원이며, 정정 후 3,410,000원이다. 필요 6종 중 최초 4종 수령, 통장사본·세금계산서 누락으로 시작한다.

왼쪽은 실제 운영 앱의 새 캡처가 아닌 **현재 구조의 재현 HTML**이다. 복사본의 파일 수·서류 금액 등 가상 자료를 맞췄다. 재현 자료의 목록 주변 계약이나 가림 표시까지 새 안과 동일한 것은 아니므로 처리시간·기능 동등성 평가에 쓰지 않는다.

시안 단계 이동은 준비된 상황을 불러오는 도구다. 등록·AI 실행·업로드·승인·지급은 운영 DB에 저장되지 않는다. ‘대표 전달’은 현재 앱의 전달 문장 복사 흐름이며 명시적 상신 API를 구현했다는 뜻이 아니다. 김담당→이대표 표시는 담당 검토와 대표 결정이며, 담당자 결재를 한 단계 더 추가한 것이 아니다. 3~5명 결재선은 이번 결과에 구현하지 않았다.

## 다시 만들기

`scripts/prepare-comparison.mjs`는 지정된 기존 재현 HTML을 읽어 복사본을 만든다. `scripts/build-comparison.mjs`는 `public/comparison/captures/`의 브라우저 PNG를 넣어 비교 HTML을 만든다.

빌드 후 순서: `npm run build` → `node scripts/export-html.mjs` → `node scripts/build-comparison.mjs`.

화면 캡처는 IAB에서 수행했다. 데스크톱 1440×1100, 모바일 390×844이고, 디자인 기준 대조는 별도 1440×900으로 수행했다. `fullPage` 캡처에서 고정 사이드바가 빠지는 문제를 발견해 뷰포트 캡처로 교체했다. 브라우저 클라이언트/스크롤바 영역 때문에 PNG는 각각 1425×1100 및 375×844일 수 있다.

의견은 서버로 보내지 않는다. 새로고침 전에 복사나 TXT 저장으로 보관한다. 실제 다운로드한 `ui-comparison-feedback.txt`에서 줄바꿈과 선택·메모 내용이 유지되는 것을 확인했다.
