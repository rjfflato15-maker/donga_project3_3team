# 승인된 비교 시안의 실제 앱 반영 기준

2026-10-06 정정. 화면 기준은 `codex_sidebar_example/ui_compare.html`의 **오른쪽 Codex 안**과 업무 흐름을 그리는 `src/StoryPreview.jsx`다. 이전 문서의 ‘기존 창 유지’, ‘5단계 막대 유지’ 결정은 폐기한다. `codex_sidebar_ui_spec.md`와 시안의 배치가 다르면 이 비교 시안의 배치를 따른다. 실제 API·권한·원문 확인 조건은 유지한다.

`frontend/build-compare-css.cjs`가 원 시안의 `prototype.css`와 `story.css`를 `.cf-app` 범위로 변환해 `compare-ui.css`를 만든다. `compare-runtime.css`는 실제 원문·폼·키보드·가림·파일 선택에 필요한 추가 규칙이다. 기존 `cp-*` 레이아웃 위에 새 화면을 얹지 않는다. 재생성 명령은 frontend 폴더에서 `node build-compare-css.cjs`다.

## 시안과 달라지는 사실 표시

- 계약·요청 번호는 서버 ID다. 시안의 가상 문서번호와 `R-01`을 실번호처럼 만들지 않는다.
- 이름·날짜·금액·건수·단계·결재자 수는 현재 데이터다. 담당자를 등록자라고 추정하지 않는다. 지원되지 않는 3~5인 결재선을 만들지 않는다.
- 원문은 실제 PDF·이미지·본문이다. 시안의 HTML 견적서를 원문처럼 표시하지 않는다. 검증된 좌표만 하이라이트하고 좌표가 없으면 쪽·줄을 표시한다.
- 원문 확인은 필드별 확인이다. `N/M값 확인`을 표시하며 값 하나 확인을 서류 전체 확인으로 바꾸지 않는다. 사람 확인과 자동 검사 일치를 별개로 표시한다.
- 결재 변경 내역은 조회된 처리 기록이다. 서버가 제공하지 않는 ‘이번 검토만’, ‘지난 결재 이후만’ 범위를 주장하지 않는다. 누락 항목의 받음 기록은 파일 영구 연결이나 검사 통과가 아니다.
- 최종 단계는 `승인`, 앞 단계는 정책 단계명 + `완료`다. 반려는 최종 단계에서만, 의견 1자 이상이며 미확인이 있으면 동의와 10자 이상 조건을 유지한다.
- 개인정보 ON은 현재 가림 정책을 따른다. 요청 문구·값 수정칸은 실제 값을 사용한다. 자동 원문 가림의 누락 가능성 안내를 유지한다.
- 연락 방법·짧게/자세히·편집 가능한 문구·취소 이유·기록 메모·ZIP·설정·개인 맡기기는 실제 기능이라 남긴다. 보조 기능은 메뉴·접는 칸·사이드바 하단에 배치한다.
- 요청 선택 시 자료 기준과 원문 동의를 묶고 변경 시 기록을 잠근다. 동일 내용 재시도에는 같은 idempotency key를 사용한다. 충돌·조회 실패는 계약 상단에 남긴다.
- 업로드 취소·다른 계약 이동 시 파일과 늦은 응답을 격리한다. 등록이 성공하고 기준 저장만 실패하면 새 계약을 중복 등록하지 않는다.

## 대조한 축과 검증

원 시안 캡처와 실행 앱을 **탐색·폭/여백·문자/색·패널 배치·작업 순서·실제 상태/권한** 축으로 대조했다. 등록·기준 확인·원문·요청·재발행·결재 캡처는 가상 업무함에서 실제 API를 호출한 화면이다. 실제 문서 길이, 선택하지 않은 항목, 데이터 건수와 위 사실 표시로 내용 높이는 달라질 수 있다.

화면 자동 검사 77개와 production 빌드 통과. 관련 백엔드 검사 77개 통과(묶음 요청·버전·결재·지급·필드 확인). 가상 계약으로 등록 → 원문 확인 → 묶음 요청 → 2건 부분 회신 → 정정 견적서 → 원문 확인 저장 → 마지막 회신 → 담당 검토 → 대표 승인 → 지급 기록 → 완료를 확인했다. 1280×720에서 승인 버튼이 화면 안에 있고, 390×844에서 원문/값 탭·메뉴 Esc·포커스 복귀·가로 넘침 없음을 확인했다.

백엔드 AI·가드·평가 코드와 v3/test2 고정 예측은 변경하지 않았다. QA 원문·계정·캡처는 버전 관리에 넣지 않는다. 실제 업무 자료와 측정용 업무함은 수정하지 않는다.
