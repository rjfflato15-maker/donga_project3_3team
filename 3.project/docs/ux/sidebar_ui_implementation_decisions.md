# 승인된 사이드바 UI 구현 결정

기준: `codex_sidebar_ui_spec.md`, 승인된 Codex 시안. 실제 API·권한·가림 조건을 우선한다.

1. 계약은 `계약 #서버ID`, 요청은 `요청 #서버ID`로 표시한다. 페이지·정렬에 따라 바뀌는 가상 순번을 만들지 않는다.
2. 등록자를 담당자로 표시하지 않는다. 개인 맡기기는 기존 API에 기록된 담당자를 표시한다.
3. 업무함 완료·전체는 서버 검색 API의 페이지와 총건수를 사용한다. 진행 중 역할 할 일 수와 완료 수를 혼합하지 않는다.
4. 서류 원문 확인은 필드별 확인 건수를 표시한다. 서류 전체가 확인됐다고 추정하지 않는다.
5. 최종 버튼은 `승인`, 이전 단계는 정책 단계 이름 + `완료`로 표시한다. 기존 승인·반려 활성 조건은 유지한다.
6. 진행 막대는 실제 5단계를 유지한다. 보완 대기를 숨기지 않는다. 결재 탭에서는 막대를 숨겨 의견과 승인 버튼 공간을 확보한다.
7. 지급·재확인은 결재 탭에서 같은 요약과 함께 표시한다. 기존 지급을 새 지급으로 바꾸지 않는다.
8. 계약 등록은 업무함 주 버튼과 사이드바 보조 버튼에서 접근한다. 가림 토글은 사이드바 프로필 위에 둔다.
9. 로딩은 기존 표시를 유지한다. 실패·저장 충돌은 탭과 단계에 관계없이 계약 상단에 남긴다.
10. 요청 문구는 현행처럼 수정할 수 있다. 연락 방법·기한·기록 한 번의 구조를 유지한다.

명세서에서 제안한 3~5인 결재선은 현재 서버가 지원하지 않으므로 표시하지 않는다. 실 서버의 정책 단계 수만 그린다.

## 시안과 실제 화면의 대응

| 축 | 반영 | 실제 업무 조건에 따른 차이 |
|---|---|---|
| 탐색 | 222px 왼쪽 메뉴, 접기·펼치기, 상단 56px | 메뉴를 접어도 작업 중 입력과 계약 화면은 유지 |
| 색·문자 | 밝은 회색 바탕, 흰 패널, 파란 주 행동, 14px 본문 | 기존 보안·실패 안내는 필요한 곳에 유지 |
| 업무함 | 상태 탭, 검색, 계약 표, 다음 행동 | 실제 서버 단계·역할을 사용하고 완료/전체는 서버 검색 |
| 계약 | 번호·금액 고정 헤더, 서류/요청/결재/기록 탭 | 실제 5단계 보존, 계약·요청 번호는 서버 ID |
| 원문 대조 | 원문/읽은 값 분할, 출처·근거·검사·사람 확인 구분 | 좌표 없는 근거는 쪽·줄로 표시; 이전 본은 읽기 전용 |
| 묶음 요청 | 항목 표 → 문구 → 연락·기한 → 한 번 기록 | 문구 편집 가능, 실제 발송은 기존처럼 사용자가 수행 |
| 결재 | 요약·변경 기록 왼쪽, 결재선·의견·승인 오른쪽 | 최종 단계에서만 반려, 실제 의견·동의 조건 보존 |
| 모바일 | 900px 이하 메뉴 오버레이, 700px 이하 세로 배치 | 결재·지급 행동 먼저, 원문은 원문/값 탭으로 전환 |

등록·새 서류 추가·설정·개인 맡기기는 기존 동작을 보존하고 공통 색·글자·모서리 규칙을 적용한다. 계약 등록 및 파일 선택에도 키보드 접근을 적용한다.

결재 화면 변경 기록은 최근 저장된 이력이다. 서버가 제공하지 않는 “지난 결재 이후 변경만” 범위나 담당자를 추정해 표시하지 않는다. 값 하나를 원문과 같다고 확인해도 계약 기준과의 불일치는 그대로 남는다.
