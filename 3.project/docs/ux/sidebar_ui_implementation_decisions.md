# 승인된 사이드바 UI 구현 결정

기준: `codex_sidebar_ui_spec.md`, 승인된 Codex 시안. 실제 API·권한·가림 조건을 우선한다.

1. 계약은 `계약 #서버ID`, 요청은 `요청 #서버ID`로 표시한다. 페이지·정렬에 따라 바뀌는 가상 순번을 만들지 않는다.
2. 등록자를 담당자로 표시하지 않는다. 개인 맡기기는 기존 API에 기록된 담당자를 표시한다.
3. 업무함 완료·전체는 서버 검색 API의 페이지와 총건수를 사용한다. 진행 중 역할 할 일 수와 완료 수를 혼합하지 않는다.
4. 서류 원문 확인은 필드별 확인 건수를 표시한다. 서류 전체가 확인됐다고 추정하지 않는다.
5. 최종 버튼은 `승인`, 이전 단계는 정책 단계 이름 + `완료`로 표시한다. 기존 승인·반려 활성 조건은 유지한다.
6. 진행 막대는 실제 5단계를 유지한다. 보완 대기를 숨기지 않는다. 결재 탭에서는 막대를 숨겨 의견과 승인 버튼 공간을 확보한다.
7. 지급·재확인은 결재 탭에서 같은 요약과 함께 표시한다. 기존 지급을 새 지급으로 바꾸지 않는다.
8. 계약 등록은 업무함 주 버튼과 사이드바 보조 버튼에서 접근한다. 가림 토글은 사이드바 프로필 위에 둔다.
9. 로딩은 기존 표시를 유지한다. 실패·저장 충돌은 탭과 단계에 관계없이 계약 상단에 남긴다.
10. 요청 문구는 현행처럼 수정할 수 있다. 연락 방법·기한·기록 한 번의 구조를 유지한다.

명세서에서 제안한 3~5인 결재선은 현재 서버가 지원하지 않으므로 표시하지 않는다. 실 서버의 정책 단계 수만 그린다.
