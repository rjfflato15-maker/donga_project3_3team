# 승인된 Codex 사이드바 UI의 실제 앱 반영 기준

2026-10-06. 사용자가 팀원들의 동의와 마스킹 범위 확인을 전달하고 Codex 새안으로 진행하기로 했다.

## 결정과 담당

- 디자인 기준은 `docs/ux/codex_sidebar_example/`의 Codex 사이드바 새안이다. `ui_compare.html`의 오른쪽과 `codex-workflow.html`을 사용한다.
- 사용자 추가 결정: Claude의 남은 사용량은 승인된 시안을 구현 명세서로 정리하는 데 사용하고, Codex가 실제 frontend 구현과 API·권한·마스킹·업무 흐름 검증을 맡는다. 명세서 도착 전에는 화면 코드를 변경하지 않는다.
- 새 시안을 다시 만들거나 Claude ERP 대안을 섞지 않는다. 승인된 색상·정보 배치·왼쪽 메뉴·접기/펼치기를 따른다.
- 기준 main은 `7664986`이다. 확인 당시 `feat/ui-polish`는 `dd8650d`이며 두 HEAD의 frontend 내용에는 차이가 없다. 미통합 커밋은 이전 시안 문서 등이므로 모두 최신 앱 변경으로 간주하지 않는다.
- 이 문서는 구현 인계 기준이다. 실제 앱 UI 반영·전체 회귀 확인이 완료됐다는 기록은 아니다.

## 실제 앱과 시안의 경계

시안은 가상 데이터와 로컬 상태로 움직인다. 실제 앱에서는 기존 API와 데이터·상태 계산을 연결한다. 시안의 예시 계약, 준비된 다음 단계, 고정 날짜, 승인·지급 성공 전환을 복사하지 않는다.

- `stage`, `work_state.next_actions`, 회사 결재 정책을 목록·상세·버튼의 공통 기준으로 사용한다.
- 시안의 계약번호·요청번호는 서버의 실제 ID로 대응하고, 원문에 있는 번호나 별도 발급 번호로 오인하게 표시하지 않는다.
- 담당자 검토와 공식 결재 단계를 구분한다. SMALL_BUSINESS는 대표 1단계, MID_SIZED는 담당 검토 → 대표 최대 2단계다. 3~5명 결재선은 현재 구현 범위가 아니다.
- 대표 전달은 현재 전달 문장 복사 흐름이다. 명시적 상신 API나 자동 알림·메시지 발송 기능으로 표시하지 않는다.
- 고친 본 도착 안내와 사용자의 항목 수령 기록은 유지한다. 특정 요청 항목에 정확한 회신 파일 버전이 영구 연결됐다고 표시하지 않는다.
- 자동 검사 일치, 원문 사람 확인, 서류 수령, 결재, 지급 완료 기록은 각각 다른 사실이다.
- 지급은 계약 전체 지급 사실 기록이다. 실제 송금·분할 지급 실행 기능으로 표시하지 않는다.

## 디자인 기준

- 전역 메뉴는 왼쪽에 두고 접기/펼치기를 제공한다. 계약 내부 탭은 본문에 둔다.
- 승인된 기본 색상: 본문 배경 `#f7f9fc`, 사이드바 `#fcfdff`, 본문 글자 `#243349`, 강조 `#315eaa`, 경계선 `#e2e8f0`.
- 기준 글꼴은 맑은 고딕 계열, 기본 14px, 줄 높이 1.55, 데스크톱 사이드바 222px이다. 상세 크기·간격·아이콘·선택 상태는 시안 CSS와 캡처를 따른다.
- 현재 앱의 공통 색상 토큰과 재사용 컴포넌트로 적용한다. 시안의 단일 파일과 가상 상태 코드를 앱 전체에 복사하지 않는다.
- 핵심 안내·실패 이유·되돌릴 수 없는 행동의 확인은 유지한다. 문장을 줄이면서 필수 조건이나 예외를 숨기지 않는다.
- 모바일 메뉴는 오버레이로 열고 닫는다. 원문/읽은 값 전환에서도 수정 입력을 보존한다. 화면 폭 변경은 업무 상태 변경이 아니다.
- 새안에 없는 등록·설정·맡기기 기능은 같은 디자인 규칙으로 연결한다. 새로운 업무 기능이나 외부 연동은 이번 UI 반영에 섞지 않는다.

## 마스킹: 기존 범위를 유지

사업자번호만 가리는 것으로 변경하지 않는다. 시안의 가상 이름이나 별표 표시를 실제 가림 로직으로 사용하지 않는다.

| 상황 | 개인정보 ON | 개인정보 OFF |
| --- | --- | --- |
| 계약 목록·검색·상단 거래처 정보 | 거래처명·상호를 가림 | 실제 값 |
| 읽은 값·버전 비교 | 상호·사업자번호·계좌번호를 가림 | 실제 값 |
| 검사 설명·기준값·비교값 | 문장 속 사업자번호·주민번호를 가림. 문장 전체의 모든 정보 가림은 아님 | 실제 값 |
| 원문 미리보기 | 자동 감지한 번호·계좌·연락처·주소·이메일·상호·대표자명 등을 가림. 누락 가능성 안내 유지 | 원문 표시 |
| 값 수정칸 | 실제 값을 표시하고 예외 안내 | 실제 값 |
| 거래처에 보낼 요청 문구 | 실제 거래처명이 포함됨을 안내 | 실제 거래처명 |
| 처리 이력의 사내 처리자 이름 | 누가 처리했는지 알 수 있도록 이름 유지 | 이름 유지 |
| 자료 묶음 ZIP | 서류와 JSON의 감지·등록된 개인정보 가림 | 원본 묶음, 기존 추가 확인 유지 |
| ‘가린 원본 받기’ | 가린 파일 | OFF 상태여도 가린 파일 |

표시 가림은 저장 원본·DB의 삭제·변조·암호화가 아니다. 금액·날짜·검사 상태는 업무 확인에 필요한 값으로 표시한다. 원문 자동 가림을 완전한 비식별화 보증으로 표현하지 않는다.

재사용 기준: `frontend/src/utils/masking.ts`, `DocumentReviewDialog.tsx`의 `display`, `ContractStageView.tsx`의 `maskForDisplay`, 서버 `preview_masking_service.py`, `contract_export_service.py`.

## 유지해야 할 오류·권한 처리

- 동일 계약의 늦은 조회 성공/실패, 계약 전환 뒤 이전 계약 응답을 버린다.
- 409 저장 충돌은 성공으로 표시하지 않는다. 최신 조회 뒤 단계·패널이 달라져도 계약 상단에 충돌 이유를 남긴다.
- revision/fingerprint·최신 결재·지급 대상이 바뀌면 기존 선택·확인 체크·입력을 현재 로직대로 초기화한다.
- 업로드 취소·Esc·계약 변경 시 파일 입력을 비운다. 같은 창의 실패만 재시도용 파일을 유지한다. 늦은 업로드 완료가 다른 계약으로 화면을 되돌리지 않게 한다.
- 모달 초기 포커스, Tab/Shift+Tab 순환, Esc, 닫은 뒤 연 버튼으로 복귀를 유지한다. 폼이 열린 대조창은 Esc로 폼을 먼저 닫는다.
- 사내 맡기기로 결재 권한이 생기지 않는다. disabled 버튼과 안내도 서버의 실제 권한을 따른다.
- 로그인 실패 제한·Caps Lock 안내·비밀번호 변경·세션 만료 처리를 유지한다.
- 국세청 조회 disabled, 로컬 LLM의 실제 설정·연결·문서별 채택 상태를 유지한다.

## Claude 명세서와 Codex 구현

Claude에게 보낼 1회 요청은 `codex_sidebar_spec_request_20261006.md`에 있다. 결과 파일은 `docs/ux/codex_sidebar_ui_spec.md`로 받는다. 새 시안 생성·앱 코드 수정 없이 승인된 시안의 색상·배치·상태·동작과 기존 컴포넌트 연결을 문서로 확정한다.

Codex는 명세서를 이 문서의 실제 API·권한·마스킹 조건과 대조한 뒤 frontend를 작은 묶음으로 반영한다. 테스트·빌드·브라우저 비교를 확인하고 묶음별 로컬 커밋을 남긴다. 본문 순서의 셸·업무함부터 시작하며, 명세서 도착과 검토를 완료한 사실 없이 구현 완료나 변경 시작으로 기록하지 않는다.
