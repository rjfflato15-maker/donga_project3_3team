# 현재 계약 중심 검수 흐름

> 상태: 현재 기준
> 확인일: 2026-10-11
> 기준: contract-risk-review-v3 승인 배포본
> 이전 17개 실행본과 제출본은 별도 보존하며, 현재 실행 소스와 새 제출본은 이 정책으로 맞춘다.

## 정상 계약

6종 등록 → 계약 전체 검수 결과 → 계약 기준·송금 정보·청구 범위의 필수 판단 → 실제 납품·용역 완료 확인과 검토 의견 → 담당자 상신 → 대표 결재 → 지급 사실 기록·회계 자료 출력.

계약 전체 결과가 첫 화면이다. 자동 검사 일치, 원본 근거로 대조한 반복값, 사람의 필수 판단을 구분한다. 자동 처리된 값을 사람 확인으로 기록하지 않는다. 자동 처리한 원문은 필요할 때 상세 보기로 연다.

첫 화면의 ‘담당자 할 일’은 두 경로를 구분한다. 문제가 있으면 해당 문제와 원문 확인 행동을 먼저 표시하고, 문제가 없으면 계약 기준·송금 정보·청구 범위의 남은 판단만 표시한다. 전체 6종 목록과 자동 검사 근거는 기본으로 접혀 있다. 항목을 누르면 선택한 내용과 해당 원문을 대조하는 기존 화면으로 이동한다. 저장하면 다음 판단으로 이어지고 마지막 판단 후 기존 상신 양식으로 돌아온다. ‘담당자 할 일’로 돌아가거나 재진입해도 저장된 확인을 다시 요구하지 않는다. 새 업무 단계·메뉴·서버 정책은 추가하지 않았다.

| 담당자 판단 | 원문 확인 대상 | 저장 의미 |
| --- | --- | --- |
| 계약 기준 확인 | 계약 거래처·사업자번호·합계와 지급 조건 | 현재 계약 기준에 대한 직접 확인 |
| 송금 정보 확인 | 예금주·은행·계좌번호 | 제출 통장자료 대조. 금융기관 계좌 소유 조회가 아님 |
| 청구 범위 확인 | 계약 지급 방식·청구액·범위 | UNKNOWN을 확인 완료로 처리하지 않음 |
| 실제 업무 완료 | 납품·용역 검수 완료 사실 | 서류 존재와 구분하여 상신 때 직접 기록 |

필수 값 묶음은 실제 원문을 대조한 뒤 기존 확인 API로 저장한다. 범위 한 항목은 ‘계약 조건·청구 범위 확인’ 버튼으로 기록한다. 남은 의무가 있는 서류로 이동하고, 마지막 확인 뒤 원문 화면을 닫아 기존 상신 양식으로 연결한다.

## 문제가 있는 계약

누락·불일치·판독 실패·원본 근거 불명·청구 UNKNOWN은 먼저 처리할 항목으로 표시한다. 해당 원문만 열고 기존 기능으로 해결한다.

| 실제 상황 | 행동 | 다음 단계 |
| --- | --- | --- |
| 앱이 원문을 잘못 읽음 | 값 정정·사유 저장 | 해당 항목 원문 확인, 재검사 후 남은 필수 판단 |
| 서류 자체가 계약과 다름 | 원문 확인 후 보완 요청에 담기 | 묶음 요청 → 회신 → 수정본 등록·수령 기록 → 재검사 |
| 등록한 계약 기준이 틀림 | 계약 기준 수정 | 영향받는 금액·청구 판단 재확인 |
| 청구 범위를 읽지 못함 | 조건·금액 확인 후 범위 입력 | 유효한 범위 저장 후 재검사 |
| 근거 검증 불가 | 원문 직접 확인·정정·재등록 | PASS만으로 의무를 없애지 않음 |
| 판단 미완료 | 기존 보류·사유 기록 | 미해결 상태 유지, 상신 차단 |

요청 작성·복사는 외부 발송이 아니다. 외부 전달 사실만 기존 요청 기록에 남긴다. 부분 회신은 받은 항목만 기록한다. 수정본은 이전 본을 보존하고 새 원본으로 검사한다. 회신 대기인 문제를 정상 검사 완료로 안내하지 않는다.

## 자동 대조를 인정하는 범위

원본 해시와 PDF의 보이는 텍스트·거래처 귀속을 확인할 수 있는 구조, 또는 라벨·값·공급자가 명확한 스캔에서 기존 Windows OCR의 전체 읽기와 원본 행 재판독이 일치하는 경우를 인정한다. 스캔은 PNG/JPEG/BMP/WebP와 최대 3쪽의 이미지 PDF가 대상이며 혼합 PDF·복잡한 표·모호한 귀속은 면제하지 않는다. 실제 단어 좌표와 원 단위를 요구하며, 재판독 조건은 독립적인 OCR 정확도 보증이 아니다. 근거는 등록/수정본 처리 때 저장하고 조회·상신 때 OCR을 다시 실행하지 않는다. 누락된 추출값만 이 근거로 보충하고 기존 값과 다르면 문제로 표시한다. 반복 상호·사업자번호는 원문·저장값·등록 계약 기준이 모두 같아야 한다. 견적서·전액 세금계산서 금액은 명시된 원 단위·공급자·계약 합계·관련 검사·공급가액과 세액 산술이 함께 맞아야 한다.

재판독 근거 없는 스캔·DOCX·가려지거나 겹친 글자·모호한 업체/표·분할 지급·판독 불명·AI 확인 대상·보류는 확인 의무를 유지한다. PASS, 모델 신뢰도, 서로 같은 추출값만으로 사람 확인을 면제하지 않는다. 지급 정보와 실제 업무 판단은 자동화하지 않는다.

필수 서류·정상 처리 조건·필수 판단을 함께 검사한다. 기준 계약을 직접 확인하지 않았다면 자동 결과가 있어도 상신할 수 없다. 자동 근거는 사람 확인과 별도로 기존 상신 이력에 저장한다. 원본·값·정책·지급 조건이 바뀌면 기존 상신과 필요한 확인을 다시 계산한다. 완료된 과거 이력을 지우지 않는다.

## 기존 업무와 오류 복구

대표 승인·반려, 요청·부분 수령, 수정본, 지급·출력 API와 DB 구조를 유지한다. 반려 후 같은 원본·기준이 유지되면 이미 한 원문 확인을 반복하지 않고 반려 사유와 업무 완료 판단을 보완해 재상신한다.

새로고침·재진입은 서버 기록을 조회한다. 저장 실패·409를 성공으로 표시하지 않는다. 상신 기준이 갱신되면 작성 중 의견은 유지하고 완료 확인은 새 기준으로 다시 선택한다. 국세청 미조회는 그대로 표시한다. 대표 승인은 실제 송금이 아니며 지급 완료 기록은 별도다.
