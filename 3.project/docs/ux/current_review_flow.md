## 시작과 자유로운 이동

서류 받기·확인·보완·결재·지급의 5단계를 유지한다. 계약 상세의 ‘확인 계속하기’는 현재 서버 기준에 맞는 이전 위치 또는 첫 미확인 항목을 연다. 원문은 왼쪽, 앱이 읽은 값과 등록된 계약 기준은 오른쪽에 표시한다. 현재 판단 항목 하나에 집중하며 ‘확인할 항목 2/8’은 전체 목록에서의 위치이고 완료 비율이 아니다.

‘전체 항목 보기’에서 어느 항목으로든 바로 이동한다. 이미 원문을 확인한 항목도 다시 열어 정정할 수 있다. 선택한 뒤 전체 목록을 접어 현재 판단을 보이게 한다. 이전·다음, ‘다음 확인할 항목 보기’, ‘검토 요약 보기’는 위치만 바꾸며 확인·판단·결재를 저장하지 않는다. 입력 중인 값은 저장 버튼을 눌러야 남는다.

## 네 가지 처리와 필요한 입력

| 처리 선택 | 언제 쓰는가 | 기존 서버 기록 |
| --- | --- | --- |
| 값 정정 | 앱이 원문을 잘못 읽은 경우 | 선택한 필드·수정 사유·현재 revision만 전송하고 그 필드의 원문 확인 기록 |
| 보완 필요 | 실제 서류의 오류·누락 | 기존 보완 요청 초안에 담고 여러 항목을 묶어 요청한 사실 기록 |
| 계약 기준 수정 | 원문과 읽은 값은 맞고 등록된 계약 기준이 틀린 경우 | 기존 계약 수정 화면. 문서 추출값은 변경하지 않음 |
| 문제없음 | 원문과 읽은 값이 같고 판단 가능한 경우 | 명시적 원문 확인 저장. 비교 문제가 남으면 확인 후 판단 근거를 별도로 기록 |

선택한 처리에 필요한 입력만 펼친다. 보완 대상이 없거나 현재 권한·원문 상태가 맞지 않으면 해당 행동을 활성화하지 않는다. 보류는 ‘선택 항목 더보기’에 둔다. 보류 사유는 서버에 저장하고 현재 항목에 ‘판단 보류 중’으로 표시한다. 보류 해제·다시 검토로 돌아오며 보류는 완료가 아니다.

원문 확인과 업무상 ‘문제없음’ 판단은 서로 다르다. 비교 문제가 남을 때 먼저 원문에 현재 값이 있음을 직접 확인하고 저장한 후, 문제가 아니라고 판단한 이유를 기록한다. 자동 검사 FAIL/REVIEW는 PASS로 바꾸지 않는다. 저장에 실패하면 성공·완료로 표시하지 않고 최신 서버 자료를 다시 불러온다.

## 복귀·부분 회신·수정본

브라우저 sessionStorage에는 계약별 선택 항목 ID와 revision/fingerprint/gate fingerprint만 저장한다. 고객 값·사유·완료 여부는 저장하지 않는다. 오래된 기준이나 없어진 원본 ID는 복귀 위치로 쓰지 않는다. 새로고침·재진입 시 확인/보류/회신/승인은 서버에서 다시 조회한다.

부분 회신은 받은 항목만 수령으로 기록하고 나머지는 대기로 남긴다. 회신 기록은 원문 확인이 아니므로 받은 서류의 ‘원문 대조’에서 관련 항목을 다시 확인한다. 요청 저장 중에는 취소·탭 이동을 잠가 서버 저장 결과를 받은 뒤 이동한다.

수정본은 기존 업로드 API로 등록하고 이전 본을 보존한다. 바뀐 원본의 필수 항목은 다시 원문 확인해야 한다. 이전 본은 읽기 전용이다. 변경 내역·세부 값·AI 후보·버전 이력은 필요한 때 펼친다. AI 후보 자체는 저장이나 승인 근거를 자동으로 만들지 않는다.

## 담당자 준비와 공식 결재

필수 원본·원문 확인·회신·보류 처리가 남으면 상신 입력을 숨기고 현재 해야 할 일을 표시한다. 완료 후 검토 요약에서 담당자 검토 의견과 기존 결재 요청을 기록한다. 대표 결재는 기존 결재 화면으로 연결한다.

현재 서버는 모든 정책에서 담당자의 사전 상신을 요구한다. A 기준에서 대표 1단계 정책은 담당자 준비·결재 요청이 공식 1차 결재가 아니며 대표만 공식 결재한다. 회사가 기존 2단계 정책을 선택한 경우에만 담당자의 상신이 담당 검토 1차 결재도 기록하고 대표가 2차 최종 결재한다. 단계 수는 서버 approvals 응답으로 표시한다. 대표의 담당자 준비 겸임 기능을 추가하지 않는다.

국세청 진위 조회 미실행·업무상 예외는 기존 대표 확인 규칙을 그대로 따른다. 판독 실패·원본 불일치·필수 검토 누락은 예외 사유만으로 우회하지 않는다. 지급은 실제 송금 기능이 아니라 기존 지급 사실의 기록이다.
