# 가드 v4 개발 비교 — 예비 결과

가드가 원문과 일치하는 값을 과도하게 거부하는 문제를 줄였다. **새 dev2의 동일 AI 응답에서 필드 정확도가 v3 97.55% → v4 99.51%로 올랐다.** 이 수치는 독립 판독·사람 확인 전 설계 정답 초안으로 채점한 예비 결과다. 기존 확정 test의 v3 77.74%를 대체하지 않는다.

## 비교 조건

- dev2 6개 계약·36개 문서만 사용했다. test2 원문·정답·모델 출력은 열지 않았다.
- 규칙 입력, v3의 보완 대상 12개 필드, qwen3:latest, 프롬프트 `grounded-fields-v3`와 모델 응답을 고정했다. 실제 LLM 호출 대상 문서는 8개다.
- 모델 응답을 저장한 뒤 가드 없음/v3/v4에 재사용했다. 비교 재실행의 추가 추론은 0회다. 모델 설정·자료 해시는 [수령 기록](input_receipt.json), 코드·응답 해시는 [결과 JSON](preliminary_comparison.json)에 있다.
- v3 test 결과를 본 뒤 개선 작업을 선택했다. 따라서 v4의 독립 최종 성능은 버전 고정 뒤 미사용 test2에서 확인해야 한다. 이번 개발에는 v3 test의 개별 원문·응답·거부 사례를 사용하지 않았다.

## 무엇을 고쳤나

명시된 `세전 대금`, `부가세액`, `총 청구액`을 해당 금액 라벨로 인정했다. 표에서 라벨과 값이 바로 다음 줄로 나뉜 경우에는 두 위치를 각각 확인해 연결한다. 한 줄에 상호·사업자번호 등 여러 필드가 있으면 다음 라벨에서 값의 끝을 구분한다. 줄 번호 ±1 보정은 같은 원문·라벨·값과 당사자 구역을 확인할 때만 허용한다.

다른 당사자의 값, 원문에 없는 값, 라벨 없는 참고 숫자, 복수 후보, 잘못된 페이지·형식·사업자번호 체크섬은 계속 거부한다. 확인하지 못한 `ABSENT`가 금융 문서의 기존 규칙 값을 지우지 못하도록 제한했다. 원문 자체의 산술 오류는 실제 인쇄 값을 보존하고 경고를 남겨 규칙이 판정한다. 자세한 정책은 [가드 v4 정책](../../../ai/grounding_v4_policy.md)에 있다.

## 예비 수치

| 조건 | 핵심 필드 정확도 | 검수 상태 정확도 | 위험 상태를 PASS로 판정 | N/A를 PASS로 판정 |
| --- | --- | --- | --- | --- |
| 규칙만 | 94.61% (193/204) | 90.91% (40/44) | 0건 | 1건 |
| 규칙+LLM, 가드 없음 | 99.51% (203/204) | 95.35% (41/43) | 0건 | 1건 |
| 규칙+LLM, 가드 v3 | 97.55% (199/204) | 90.91% (40/44) | 0건 | 1건 |
| 규칙+LLM, 가드 v4 | 99.51% (203/204) | 95.35% (41/43) | 0건 | 1건 |

핵심 필드는 VALUE 203칸과 REVIEW 1칸을 채점했다. ABSENT 48칸은 별도로 집계하며 네 조건 모두 없는 값의 오추출은 0건이다. 검수 상태는 정답·예측이 모두 N/A인 칸을 제외하므로 조건별 분모가 다르다. `위험 상태를 PASS로 판정`은 정답 FAIL/MISSING/REVIEW에 한정한 기존 지표다. 이 세트에는 FAIL/MISSING 정답 사례가 없으므로 모든 위험 상황에서의 안전성을 입증하지 않는다. 기존 지표가 세지 않는 N/A→PASS 오류도 별도 열로 공개했다.

| 가드 결과 | v3 | v4 |
| --- | --- | --- |
| 채택 VALUE 중 초안 정답과 일치 | 6/6 (100%) | 10/10 (100%) |
| 맞는 제안을 거부 | 5건 | 1건 |
| 틀린 제안을 거부 | 1건 | 1건 |
| 보완 대상 중 미해결·추가 확인 필요 | 6/12 (50%) | 2/12 (16.67%) |
| 보완 대상 중 기계 근거 검증 완료 | 6/12 (50%) | 10/12 (83.33%) |
| 전체 문서 중 미해결 보완 필드가 남음 | 2/36 | 1/36 |

v4는 맞는 제안 4건을 추가로 채택했고, 같은 틀린 제안 1건은 계속 막았다. 10/10은 작은 개발 표본이며 일반 정확도 100%를 뜻하지 않는다. 기계 검증을 통과한 AI 제안도 `human_confirmed=false`이며 기존 사람 확인 절차를 유지한다. 따라서 16.67%는 전체 업무의 사람 검수 비율이 아니라 **보완 대상 필드에 추가 확인이 남은 비율**이다.

## 남은 문제와 적용 상태

도장에 가려진 금액 사례(dev2 계약 304)의 규칙 판정 문제는 남았다. 가드는 근거 없는 금액 제안을 거부했지만 기존 규칙 값은 보존되어, 적용하지 않아야 할 금액 대조가 PASS로 남았다. 네 조건 모두 N/A→PASS 1건이다. 가드 없음은 이 문서의 모호한 합계를 잘못 확정했고, v4는 그 제안을 막는 대신 금액 범위 1칸을 해결하지 못했다. 두 조건의 99.51%는 서로 다른 실패를 포함한다.

기본 정책은 v3, LLM 기본 사용은 꺼짐으로 유지했다. 별도 개발 업무함에서만 `APP_LLM_GUARD_POLICY=v4`를 선택해 비교할 수 있다. 실제 업무함·frontend를 변경하거나 실행 중 서버를 재시작하지 않았다. 다음 검증은 dev2 독립 판독·정답 확인과 미해결 규칙 문제의 별도 개선, 버전 고정 뒤 test2 최종 평가다.

검증: 최신 작업 트리에서 백엔드 전체 316개 통과, DOCX 문단·표 위치와 변조 사례를 포함한 가드 관련 77개 통과, frontend 빌드 성공. 전체 검사 중 발견한 기존 감사 기록 비교 오류는 병행 작업에서 수정되어 재검사에 통과했다. 이 가드 변경에 다른 세션의 API 수정은 포함하지 않았다. [CSV](preliminary_comparison.csv) · [상세 결정](preliminary_traces.json) · [개발 범위 기록](development_plan.json).
