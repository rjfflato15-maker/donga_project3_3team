# 제출 설명 문서 구성과 작성 재료

> 상태: 초안
> 확인일: 2026-10-09
> 기준: 2026-10-09 구조 정리 소스 사본. 현재 소스와 과거 설치·평가 기록의 검증 범위를 구분한다.

이 파일은 최신 작성 재료를 연결한 초안이며 최종 PDF가 아니다. 받은 안내대로 기획안·실행 방법·구조 플로우차트를 한 파일로 통합하고 [소스 ZIP](source_package.md)은 별도로 제출한다. 10월 11일 최종 발표자료에는 팀원 역할·후기를 포함한다. 설명 문서·소스 마감과 팀 정보는 확인한 내용으로 채운다.

## 1. 문제와 대상

계약 지급 전 서류 누락·번호/금액 불일치·원문 판독 문제와 보완/회신 추적의 부담을 설명한다. 직원 6명·월 약 150건은 [시범 가정](../architecture/c_company_profile.md)이며 실제 처리 능력·시간 절감 실측으로 표현하지 않는다.

## 2. 구현과 흐름

[현재 구성도·업무 플로우](../architecture/overview.md)와 [현재 ERD](../architecture/erd.md)를 사용한다. 등록·OCR/추출·필요 시 Qwen3 보완·근거 검사·자동 검수·사람 확인·결재·지급 기록·자료 전달을 구분한다.

별도 Qwen2.5-VL은 사용자가 요청한 현재 쪽의 재판독 후보를 제공한다. 후보를 자동 저장/승인하지 않고 원문 확인한 항목만 반영한다. 로컬 분석과 사람이 세무 담당자에게 파일을 전달하는 과정은 별개다.

정산 XLSX·10초 목록 갱신·문제 항목 중심 원문 대조·묶음 요청/부분 회신·필드별 확인/보류·서류 분류 정정·수정본 변경 요약·자료 변경 뒤 재확인을 설명한다. 화면 기준은 [현재 원문 대조 흐름](../ux/current_review_flow.md)이다. 외부 메일 발송·은행 송금·ERP 전용 업로드·세금계산서 진위 확인·MFA는 현재 구현으로 주장하지 않는다. 현재 소스 ZIP에는 Setup이 없으며 이전 설치 기록을 이번 소스의 검증으로 표시하지 않는다.

## 3. 실험 방법과 결과

[평가별 결과·분모·한계](evaluation_results.md)가 제출 요약의 기준이다. v3 test와 v4 test2를 동일 자료의 개선 과정으로 연결하지 않는다. 사람 표본 확인과 두 AI 초안 일치를 구분하고, test2의 FAIL/MISSING 사례 부족을 명시한다.

VLM 가상 스캔 연결 점검은 정식 평가와 별도다. 회귀 테스트 통과는 추출 정확도 측정이 아니며 기계 처리시간은 사람 작업시간 절감과 다르다.

## 4. 실행·운영

[현재 소스 실행 준비](../operations/installation.md), [고객 Setup 안내](../operations/customer_package.md), [AI 설정](../ai/runtime_settings.md), [백업/복원](../operations/backup_restore.md)을 연결한다. 이전 버전의 Setup 설치 기록과 현재 소스의 Windows 미검증 범위를 구분한다. 발표에 쓰는 업무함·코드 버전·모델 활성 상태를 고정해 적는다.

## 5. 제한과 다음 작업

다양한 실제 증빙 일반화, 사람 작업시간 절감, 고객 설치·업데이트·제거·라이선스 정리의 미검증 범위를 적는다. 로컬 실행을 기밀 유출 0%로 표현하지 않는다.

## 제출 전 확인

최신 상태·구성도·화면·API·평가 출처가 같은 버전을 설명하는지 확인한다. 팀원 역할·후기, 실제 과제 안내의 요구사항, 원본/비밀정보 제외, 최종 시연 리허설을 확인한다. 발표 구성은 [발표 초안](presentation_outline.md)을 따른다.
