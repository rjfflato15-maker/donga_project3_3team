# 설명 문서 목차 초안

대상은 [C업체 시범 프로필](../architecture/c_company_profile.md)이다. 아래 순서로 설명 문서를 작성하고 구현 사실·개발 평가·미완료 항목을 구분한다. 이 파일은 목차와 작성 재료이며 최종 제출 문서가 아니다.

## 1. 문제 정의

- 직원 6명, 월 약 150건이라는 시범 운영 가정과 담당자 1명·대표 최종 확인 구조.
- 서류 누락·금액/사업자번호 불일치·모호한 값과 보완 연락을 확인하는 과정의 부담.
- 목적: 원문을 근거로 검토할 항목을 찾고 보완·회신·최종 확인을 이어가는 것.
- 목표 수치와 실제 측정 결과를 구분. 월 업무량을 처리시간 절감이나 운영 능력 실측으로 주장하지 않음.

## 2. 구조와 구현

- 업무 흐름: 등록 → 문서 판독 → 규칙 추출 → 실패·모순 필드 LLM 보완 → 근거 검증 → 규칙 판정 → 담당자 원문 확인 → 대표 최종 확인.
- 로컬 실행: 업무 DB·원본 저장, Ollama 로컬 사용, 클라우드 비활성 확인, 외부 LLM API 미사용.
- 국세청 사업자 상태 조회는 `APP_NTS_MODE` 전환 구조를 유지하되 시연·평가는 가상 번호와 사내망 원칙 때문에 항상 미연동. 공식 공공데이터포털 API만 연동 경로로 두며 홈택스 스크래핑은 미사용. [정책과 설정](../operations/demo_inbox.md#합의한-국세청-조회-정책).
- 근거 정책: 원문 값·라벨·공급자 구역·모호함·형식·산술. DOCX는 문단·표 글자 근거와 물리 페이지 배치 미확인을 구분.
- 보완 요청·회신 이력, 자료 변경 후 재확인, `SMALL_BUSINESS`의 대표 1단계. `MID_SIZED`의 2단계는 확장 설계.
- 로그인·역할·세션·퇴사 계정 비활성·감사·백업과 분리 저장. 2차 인증·판매용 패키징·업데이트는 구현 사실과 향후 계획을 구분.
- 삽입할 그림: 최신 구성도·업무 플로우·운영 기록을 포함한 ERD. 초기 ERD는 현재 DB와 대조해 갱신 필요.

작성 재료: [소스 역할](../architecture/module_map.md), [API 인계](../api/frontend_handoff.md), [운영 문서](../operations/run_guide.md).

## 3. 평가 방법

- dev/test 각 10계약·59원본, 다른 서식 계열의 합성 자료. 실제 고객 자료 미사용.
- 생성 설계·파일 대조 초안과 Claude 원문 독립 판독 비교. dev 113칸은 사람이 원문 확인, 나머지 781칸은 두 AI 일치로 검증. 사람 전수 검수로 표현하지 않음.
- 불일치·해석·모호 항목과 일치 항목 10% 표본의 실제 범위·확인 시각·자료/정답 해시 기록.
- 규칙만 / LLM만 / 규칙+LLM 가드 없음 / 규칙+LLM 가드 있음. ③·④ 동일 응답 캐시 사용.
- 필드 정확도·분류/검수 F1·누락 Recall·잘못된 PASS·채택값 정확도·사람 확인 비율·처리시간. 거부·보류도 분모 유지.
- 가드 v3는 dev 감사로 조정함을 공개. test는 정답 확정과 버전 확인 후 한 번만 실행.

작성 재료: [dev 평가](../eval/dev_workflow.md), [test 확인 절차](../eval/test_review_preparation.md), [최종 평가 조건](../eval/final_workflow.md).

## 4. 결과

### 개발 평가 재료

확정 dev 핵심 필드 정확도는 규칙 78.34%, LLM만 94.66%, 가드 없음 99.11%, 가드 v3 98.52%다. 가드를 통과한 VALUE 중 정답 일치는 68/69이고 요청 필드 추가 확인은 11/80이다. 이 수치는 개발 자료에 대한 결과이며 test 수치가 아니다. 상세 분모·남은 오답은 [가드 v3 기록](../progress/history/09_guard_v3.md)을 따른다.

가드가 맞는 값도 보류해 전체 정확도가 낮아질 수 있음을 설명한다. 기존 틀린 제안 2건 차단과 남은 OCR 오독을 함께 적는다. 네 조건의 잘못된 PASS는 dev에서 모두 0/17이므로 PASS 오류 감소가 측정됐다고 쓰지 않는다.

## 5. 한계와 향후 계획

- 두 합성 서식 계열·작은 표본과 AI 초안 일치의 한계. 실제 다양한 증빙에 대한 일반화 미검증.
- OCR 오독·라벨 해석·거래 주체 오류는 근거 검증만으로 모두 해결되지 않음.
- 국세청 미연동, 실제 검수 시간 절감·월 150건 부하·동시 사용 효과 미측정.
- 중견 조직 적용·2차 인증·판매용 패키징·운영 업데이트·선택 검수 에이전트는 단계별 검증 후 확대.
- 모델·라이브러리 라이선스 고지와 제출 소스의 비밀·고객 자료 제외 범위 점검.

부록은 실행 방법, [시연 업무함](../operations/demo_inbox.md), 모델 설정·라이선스, 최신 API·ERD·평가 보고서 링크로 구성한다.
