관련 소스: [build_source_zip.py](../../tools/submission/build_source_zip.py) · [설정 예시](../../backend/.env.example) · [requirements.txt](../../backend/requirements.txt)

## 제출물의 역할

설명 문서는 기획안·실행 환경/설치/설정/순서·입력부터 결과까지의 구조 플로우차트를 한 파일로 통합한다. 소스 ZIP은 발표와 시연에 쓰는 최종 코드를 담는다. 10월 11일 제출할 최종 발표자료에는 팀원별 역할 분담과 프로젝트 후기를 포함한다. 설명 문서·코드의 마감은 받은 안내의 해당 날짜를 확인하며 임의로 추정하지 않는다.

HTML 화면 설명서는 작성 재료다. 최종 설명 문서 PDF 또는 문서 파일이 필요하다는 요구를 HTML만으로 충족했다고 간주하지 않는다. 설치 마법사 완성과 소스 제출은 별개다. 현재 실행 가능한 소스 경로와 필요한 외부 프로그램을 정확히 설명한다.

## 포함과 제외

| 제출용 ZIP에 포함 | 제외하고 원래 작업 공간에 보존 |
| --- | --- |
| 현재 backend·frontend 소스와 관련 테스트 | `.git`, `.venv`, `node_modules`, 캐시·임시 폴더 |
| requirements·package.json·package-lock·빌드 설정 | 실제 `.env`·DB 접속 비밀번호·토큰·개인 키 |
| 실행기 소스·아이콘·빌드/운영 도구 | 고객 원본·업무 DB·초기 계정 안내·로그·백업 |
| 최신 사용·개발·구조·API 문서, 평가 요약과 출처 보고서 | 과거 공유 ZIP·시안 구현·연구 원본·모델 가중치 |
| 검증 환경의 Python 의존성 버전 목록 | 개발 PC 경로·설정·계정을 그대로 복사한 파일 |
| 제출용이라고 표시한 가상 예제 | 실제 또는 출처를 확인하지 않은 계약·계좌·주민번호 |

보존 기록을 삭제하거나 수치를 다시 쓰지 않는다. 제출본에서 제외한 기록으로 향하는 링크는 제출본의 보존 안내로 바꾼다. 고정 평가 보고서는 당시 결과임을 유지하고 현재 앱의 정확도로 확대하지 않는다. 원본 평가·팀 측정 자료에 의존하는 테스트의 실행 범위는 별도로 안내한다.

`test_team_test_materials.py`, `test_neutral_test2_review.py`, `test_test2_result_analysis.py`는 제출에서 제외한 원본 측정·평가 자료에 의존하므로 해당 세 연구 테스트 파일은 ZIP에서 제외한다. 앱 기능 테스트와 평가 도구 소스는 유지한다. 합성 테스트에서 필요한 평가용 페이지 생성 코드·템플릿·라벨 작성 안내는 포함한다. 나머지 테스트의 실제 실행 결과를 제출 검증으로 기록하며 원래 저장소 전체 테스트와 개수를 혼용하지 않는다.

## 생성과 확인

```powershell
# 프로젝트 루트에서 실행. 실제 설정과 업무 자료를 압축하지 않는다.
& .\backend\.venv\Scripts\python.exe -X utf8 tools/submission/build_source_zip.py
```

빌더는 허용한 경로만 복사한다. 미커밋·미추적 소스도 포함하며 `git archive HEAD`만으로 제출하지 않는다. 제출 파일에서 개인 키·서비스 토큰·실제 환경 파일의 비밀 값과 금지 경로를 검사한다. 리터럴 이메일은 example.com/net/org와 명시한 가상 로컬 도메인만 허용하고, Resend의 예시 발신 주소는 해당 서비스 소스 파일에만 허용한다. 다른 이메일이 남으면 ZIP 생성을 중단한다. 합성 샘플의 이메일은 제출 사본에서 example.com으로 바꾼다.

검사 보고서에는 실제 이메일·비밀 값 대신 파일 경로·줄·규칙만 남긴다. 테스트의 가상 비밀번호와 설정 placeholder는 실제 계정으로 취급하지 않는다. 이메일 패턴 검사 통과가 임의의 개인정보가 전혀 없음을 증명하지는 않는다.

ZIP을 풀어 문서 링크와 소스 해시를 검사하고 필요한 환경을 연결해 테스트·빌드를 확인한다. 압축 파일이 생성됐다는 것만으로 다른 PC 실행이나 고객 설치가 검증됐다고 하지 않는다. 포함 파일과 수정·제외 내역, 검증 범위, SHA-256을 함께 제공한다. 추가 코드 수정 후에는 ZIP도 다시 생성한다.

최종 제출 전에 이 ZIP을 실제 발표·시연에 쓸 버전으로 고정한다. 팀원 실명·역할·후기는 팀이 확인한 내용을 발표자료에 넣으며 자동으로 만들어 채우지 않는다.

## 선택 사항: Setup을 함께 넣는 ZIP

2026-10-11 배포에는 앱 폴더 안에 재빌드한 GUI 실행기 C-Pilot.exe를 포함한다. Python 실행 환경과 화면 빌드는 별도 준비한다. 아래 옵션은 사용하지 않으며 Setup 설치 EXE는 포함하지 않는다. 소스 전용 구조 정리는 Setup 재빌드를 요구하지 않는다.

`build_source_zip.py --installer dist/C-Pilot-Setup-1.0.0.exe`는 검증한 Setup 파일을 앱 소스와 분리된 installer/ 폴더에 포함한다. 소스는 C-Pilot-source/3.project 아래에, Setup·SHA-256·사용안내는 C-Pilot-source/installer 아래에 있다. 고객 DB·계정·원문·로그·모델은 포함하지 않는다. Setup은 Python 런타임과 빌드된 프런트엔드를 포함해 고객 PC에서 Python·Node를 따로 준비하지 않아도 된다. AI 모델은 선택 다운로드이며 설치 검증 범위는 고객 패키지 안내에 기록한다. 기존 ZIP은 현재 작업 폴더의 자동 동기화 사본이 아니므로 코드 수정 후 새 ZIP을 만들어야 한다.
