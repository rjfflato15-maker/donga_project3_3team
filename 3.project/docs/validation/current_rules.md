# 현재 자동 검사 정책

> 상태: 현재 기준
> 확인일: 2026-10-10
> 기준: HEAD `54a8841` + 미커밋 작업 트리. 작업 트리 기준. 설치 검증 범위는 고객 패키지 안내 참조.

관련 소스: [engine.py](../../backend/app/validation/engine.py) · [financial.py](../../backend/app/validation/financial.py) · [common.py](../../backend/app/schemas/common.py) · [workflow_service.py](../../backend/app/services/workflow_service.py)

자동 검사는 현재 문서와 저장된 계약 기준을 입력으로 사용한다. 대표 승인·회신 수령·사람 확인은 자동 검사 상태와 별도다. 판정 상태는 PASS / FAIL / REVIEW / MISSING이며 N/A 평가 라벨과 섞지 않는다.

| 검사 | 현재 정책 |
| --- | --- |
| 원본·판독·종류 | 원본 없음·FAILED·unknown은 확인 대상으로 표시 |
| 필수 서류 | 회사 정책의 필수 종류가 없으면 MISSING. 파일 개수와 종류 수를 구분 |
| 사업자번호 | 계약 기준과 관련 문서의 숫자 10자 비교. 실제 영업 상태·진위 인증과 별개 |
| 예금주 | `ACCOUNT_HOLDER_MATCH`. 통장사본 예금주와 계약 거래처명을 법인 표기·띄어쓰기·문장부호를 뺀 뒤 비교. 같으면 PASS, 다르면 REVIEW(개인사업자 대표자 명의 가능성), 못 읽으면 actual `미추출` REVIEW. 부분 일치·유사도는 PASS로 보지 않음. 계좌 소유 진위 인증이 아님 |
| 국세청 상태 | disabled면 실제 조회하지 않음. BUSINESS_STATUS REVIEW를 업무 목록 문제 수에서 제외해도 원래 결과는 보존 |
| 계약 금액 기준 | TOTAL 또는 공급가액+명시 세액. 기준 불명확하면 REVIEW. 임의 10% 세액 역산 없음 |
| 문서 금액 | 공급가액+세액과 표시 합계가 다르면 FAIL. 의미가 불명확한 숫자는 REVIEW |
| 견적·계산서 비교 | 계약 합계와 청구액을 비교. `잔금`·`선금` 단어만으로 PARTIAL이나 지급 완료를 확정하지 않음 |
| 계약 지급 조건 | 업로드 시 계약서·견적서의 명시 회차·비율·금액을 보존. 등록한 지급 방식과 다르거나 조건끼리 충돌하면 `CONTRACT_PAYMENT_TERMS` REVIEW |
| 회차 청구 비교 | 계산서의 회차가 식별되면 계약 조건의 해당 금액과 대조. 계약 총액과 숫자가 같아도 잔금 70% 조건과 다르면 별도 `PAYMENT_SCOPE` REVIEW |
| 분할 청구 | INSTALLMENT 정책에서 중복 해시·누적 청구액 확인. 전액 계산서와 다른 회차 계산서가 섞이면 확인 전 합산하지 않음. 전액 청구와 분할 지급은 별개 |
| 자료 변경 | 수정·재발행 뒤 revision/fingerprint와 이전 결재·지급 연결을 다시 확인 |

금액은 Decimal 기반이며 0원과 미추출/null을 구분한다. “사람이 원문을 확인했다”는 사실이 계약 기준 불일치를 PASS로 바꾸지 않는다. 지급 기록은 실제 송금 API가 아니며 계약 전체 지급 완료 사실을 별도로 기록한다. 계산서의 외상미수금은 청구액과 별도로 더하지 않으며, 그 표시로 실제 입금 여부를 판단하지 않는다.

[청구 조건 해석](../../backend/app/validation/billing.py)은 명시된 부분/분할 청구 또는 100% 미만 회차 청구에서만 PARTIAL을 읽는다. 잔금 정산만 적힌 계산서는 UNKNOWN이다. 전체 금액이 있는 계약서·견적서·검수확인서는 전체 계약 기준이며, 지급 일정 단어가 있다고 일부 금액으로 바꾸지 않는다. LLM 가드와 VLM 후보도 같은 해석을 사용한다.

계약 조건은 `extraction_metadata.billing_context`에 판독 시 보존한다. 과거 문서에 해당 메타데이터가 없으면 조건을 추정하거나 조회 때 OCR을 다시 돌리지 않는다. 구형·비표준·판독되지 않은 조건은 원문 확인/수정본 등록이 필요하다. 원문 가드는 해당 문서의 근거만 확인하고, 계약 간 비교는 검사 엔진이 담당한다. 신규 가드·프롬프트 버전은 `claim-context-20261010`이며 이전 평가 점수를 이 정책의 정확도로 재사용하지 않는다.

규칙 ID와 기대값·실제값·메시지는 `RuleEngine`이 반환한다. 화면용 카드 수·미연동 안내 제외 정책은 업무 요약 서비스에서 처리한다. 화면 집계 개선으로 평가 판정이나 원래 검사 결과를 변경하지 않는다.

정책 변경 전에는 [규칙 변경 절차](../development/recipes/change_rule.md)를 따른다. 초기 정책 문서는 [v0.1 설계](validation_rules_v0.1.md)로 보존하며 현재 구현 설명으로 사용하지 않는다.
