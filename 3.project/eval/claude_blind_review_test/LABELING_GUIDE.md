# 합성 서류 정답표 작성 기준

정답표는 원문과 등록 계약의 비교 기준을 사람이 읽고 작성한다. 모델이나 규칙 추출 결과를 보며 정답을 채우면 동일한 오류를 정답으로 받아들이게 된다. 먼저 DEV 정답을 작성하고 확정한다. TEST 정답은 최종 평가까지 보류하며 개선에 사용하지 않는다. 다른 사람이 다시 확인할 수 있도록 모호한 판단에는 메모를 남긴다.

## 생성 정보와 독립 판독으로 작성 부담 줄이기

수백 칸을 모두 빈 상태에서 사람이 입력할 필요는 없다. 합성 문서 생성에 사용한 값을 기준으로 Codex가 초안을 작성하고 실제 파일 내용과 대조할 수 있다. 이때 생성 의도와 실제 표시된 내용을 구분한다. 표시 합계가 산술적으로 틀린 경우 추출 정답은 표시 합계, 검수 정답은 산술 불일치다. 의미 없는 참고 금액의 내부 계산값을 알고 있어도 공급가액이나 합계 정답으로 확정하지 않는다.

Claude 독립 판독은 새로운 대화에 원문, 등록 계약 기준, 이 라벨링 기준만 제공하여 진행한다. Codex 초안, 생성 스크립트, 앱 추출 결과와 성능 보고서는 판독 전에 제공하지 않는다. 두 초안이 다르면 판독 오류, 생성 자료의 오류, 기준 해석 차이 중 무엇인지 원문으로 확인한다. 불일치 자체가 자료 오류의 증거는 아니다.

사람은 모든 불일치와 모호한 항목을 확인하고, 일치 항목도 초기 기준으로 20%를 무작위 표본 확인한다. 문서 종류와 시나리오가 고르게 포함되었는지 함께 확인한다. 표본에서 오류가 발견되면 확인 범위를 넓힌다. 20% 확인이 정확도나 신뢰도를 보증하지는 않는다. 실제 확인한 항목과 선정 방식 및 검수자를 기록한다.

생성 정보 초안의 `review.confirmed`와 사람 검수 표시는 false다. `evaluate.py --preliminary`는 이러한 dev 초안으로 예비 수치만 계산한다. 정식 측정 명령은 사람이 확정한 정답을 계속 요구한다. AI 검토를 사람 전수 검수라고 기록하지 않는다.

## 계약 기준과 문서 목록

각 계약의 등록 기준은 `dataset/manifest.json`의 `input`에 있다. 독립 판독 묶음에서는 정답이나 시나리오가 없는 `registered_contract.json`으로 이 기준을 제공한다. 계약상대자, 사업자번호, 등록 금액, 부가세 기준, 분할 지급 여부를 확인한다. `documents`에 들어 있는 파일만 제출한 문서다. 목록에 없는 서류를 다른 계약에서 가져오거나 새로 추가하지 않는다. 원문이 잘못 생성되어 읽을 수 없다면 정답을 억지로 채우지 말고 자료 오류를 먼저 보고한다.

## 문서 유형과 필드

문서 제목과 본문을 함께 보고 유형을 선택한다. 공급자와 공급받는자 정보가 둘 다 있을 때 추출 대상은 공급자 또는 등록 계약의 수급인이다. `company_name`과 `business_registration_no`를 같은 당사자의 값으로 작성한다.

| 정답 상태 | 선택 조건 | 정답 값 |
| --- | --- | --- |
| VALUE | 필드 의미와 값이 원문에서 확정됨 | 원문에서 확인한 값 |
| ABSENT | 해당 의미의 필드가 원문에 없음 | 비움 |
| REVIEW | 값 후보는 있으나 필드 의미 또는 당사자를 확정할 수 없음 | 비움 |

참고 금액 두 개만 있고 공급가액·세액·합계의 뜻을 확정할 수 없는 경우 금액 필드를 REVIEW로 둔다. 숫자가 있다는 이유로 가장 큰 값을 합계로 고르지 않는다. 공급가액과 세액이 명시되어 있다면 각각 VALUE로 작성한다. 합계가 직접 표시되지 않았으면 `total_amount`는 ABSENT이며, 공급가액과 세액을 더하는 규칙 검수는 별도다. 표시된 합계가 틀려도 추출 정답은 표시된 합계다. 산술 오류는 AMOUNT_COMPONENTS로 평가한다.

사업자번호는 첫자리 0을 포함하여 문자열로 입력한다. `000-00-00000` 형태나 10자리 형태를 사용한다. 금액은 원 단위 값이며 날짜는 `YYYY-MM-DD`로 입력한다. `amount_scope`는 문서 전체에 해당하는 FULL 또는 선금·잔금 등 부분 청구 PARTIAL이다. 명시적 청구 범위가 없고 문서 종류로도 확정할 수 없다면 REVIEW, 금액·청구와 무관한 문서는 ABSENT로 둔다. 발행일과 다른 날짜가 같이 있으면 발행일 의미의 값을 선택한다.

유형 시트의 직접 확인 칸은 해당 문서의 유형과 7개 필드를 모두 확인했다는 뜻이다. 값 칸의 수식은 허용하지 않는다. 직접 계산한 값을 추출 정답으로 대신 입력하지 않는다.

## 검수 상태와 적용 조건

검수 정답은 이상적인 문서 읽기 결과를 등록 계약 기준과 비교했을 때 나와야 하는 상태다. OCR이 잘못 읽을 것 같다는 이유로 정답을 변경하지 않는다. 조건이 없어 알림이 발생하지 않아야 하면 N/A다. N/A는 모르겠다는 뜻이 아니며 작성하지 않은 칸을 대신하지 않는다.

| 검수 항목 | 원문과 계약 기준으로 판단할 내용 |
| --- | --- |
| REQUIRED_DOCUMENTS | 해당 종류가 미제출이면 MISSING, 제출되어 있으면 N/A |
| BUSINESS_NO_MATCH와 문서 ID | 공급자 번호가 등록 기준과 같으면 PASS, 다르면 FAIL, 의미·번호를 확정할 수 없으면 REVIEW |
| BUSINESS_NO_MATCH와 business_registration_no | 번호를 확인할 대상 문서가 전혀 없으면 REVIEW, 대상 문서가 있으면 N/A |
| BUSINESS_STATUS | 평가에서는 외부 조회를 사용하지 않으므로 REVIEW. 실제 계속사업자 여부를 추정하지 않음 |
| AMOUNT_BASIS | 등록 계약의 비교 합계를 확정할 수 없으면 REVIEW, 기준이 명확하면 N/A |
| AMOUNT_EXTRACTION | 해당 증빙의 합계와 공급가액·세액 조합을 모두 확정할 수 없으면 REVIEW, 합계를 확정할 수 있으면 N/A |
| AMOUNT_COMPONENTS | 표시 합계와 공급가액 및 세액의 합이 다르면 FAIL, 일치하거나 비교할 구성값이 없으면 N/A |
| AMOUNT_MATCH_ESTIMATE | 비교 합계와 견적 합계가 같으면 PASS, 다르면 FAIL. 증빙 금액 또는 계약 기준이 모호하면 N/A로 두고 해당 REVIEW 알림을 별도 작성 |
| AMOUNT_MATCH_TAX_INVOICE | 전액 청구는 일치 PASS 또는 불일치 FAIL. 청구 범위를 확정할 수 없는 불일치는 REVIEW. 분할 지급 또는 부분 청구는 별도 항목으로 다룸 |
| PAYMENT_SCOPE와 문서 ID | 계약이 전액 지급인데 증빙이 부분 청구라면 REVIEW, 그 외 해당 알림이 필요 없으면 N/A |
| INSTALLMENT_TOTAL | 분할 지급이며 부분 청구를 확인한 경우 누적 합계가 계약 합계와 같으면 PASS, 초과 FAIL, 부족 REVIEW. 적용할 조건이 없으면 N/A |
| PAYMENT_SCOPE와 tax_invoice | 분할 지급인데 각 청구의 부분 여부가 모호하거나 부분 청구 한 건이 계약 전체 금액 이상이면 REVIEW. 그 외 N/A |
| DUPLICATE_INVOICE | 분할 누적에 동일한 파일이 중복 포함되면 REVIEW. 중복이 없으면 N/A |
| ORIGINAL_FILE | 현재 자료의 파일이 존재하고 열리면 N/A, 원본이 없으면 REVIEW |
| DOCUMENT_TYPE | 사람이 제목과 본문으로 유형을 확정할 수 있으면 N/A, 확정할 수 없으면 REVIEW |
| DOCUMENT_PROCESSING | 원문이 읽을 수 있는 정상 파일이면 N/A. 파일 자체가 손상되거나 읽을 수 없다면 자료 오류를 먼저 보고 |

부분 청구 표시는 있으나 원문 총액이 계약 전체 이상인 경우 누적 결과와 청구 범위 REVIEW가 함께 필요할 수 있다. 분할 지급 계약에서는 각 세금계산서를 전액 계약과 개별 비교하지 않는다. 등록 계약이 공급가액 기준이면 등록 세액을 더한 합계로 비교하며 임의로 10%를 추가하지 않는다. 문서의 공급가액과 세액을 명확히 읽을 수 있는 경우에만 합계 계산에 사용한다.

검수 시트의 문서 ID가 붙은 행은 해당 문서에 대한 검사다. `tax_invoice`처럼 종류명이 붙은 행은 계약 전체의 누적 검사다. 검수 항목이 2개 이상 동시에 해당하면 각각 작성한다. 적용되지 않는 후보 행도 N/A와 직접 확인을 입력한다.

## 확정과 변경

모든 입력을 직접 확인하고 Excel을 저장한 뒤 가져오기 명령으로 확정한다. 검수자 별칭과 확정 일시 및 파일 해시가 함께 기록된다. 가능하면 작성자와 다른 사람이 같은 기준으로 다시 확인한다. 의견이 다를 때는 원문 근거를 기록하고 합의한 기준을 문서화한다.

평가 결과를 본 뒤 수치를 높이려고 정답을 바꾸지 않는다. 정답 오류를 발견하면 오류와 수정 이유를 기록하고 자료 버전을 올린다. 이전 수치와 새 수치를 동일한 정답표에서 나온 결과처럼 비교하지 않는다.
