# test2 중립 문구 20문항 재확인

`index.html`을 열고 이름을 입력한 뒤, 원문을 보고 답을 고른다. 숫자·이름은 직접 입력하고 모르면 ‘판단하기 어려움’을 고를 수 있다. ‘답 저장·다음’으로 진행하고 마지막에 `neutral_review_result_test2_이름.json`을 받는다. 기존 81개 답과 정답표는 바뀌지 않는다.

원래 확인 페이지의 여백을 자른 이미지를 그대로 연결했다. 문서 버튼은 분류 정답 대신 파일명으로 표시하고, 정답 초안·이전 답·정답 여부는 보여주지 않는다. 등록 계약 정보는 대조에 필요한 질문에서만 표시한다. 이전 페이지와 브라우저 저장 키·결과 파일 형식도 다르다.

## 선정과 비교

기존 81문항 ID를 정렬하고 Python `random.Random(20261003).sample(...,20)`으로 비복원 추출했다. 답의 일치 여부에 따라 다시 뽑지 않았다. `sample_manifest.json`에 모집단·추출 순서·원본 해시를 보존한다. 선정된 20개는 기존 ‘확인’ 응답이며, 수정 필요였던 1개는 우연히 선택되지 않았다.

현재 커밋의 기존 페이지 바이트 해시는 과거 제출 기록의 페이지 해시와 다르다. 이번 작업에서 페이지를 바꾸지 않았고 HEAD와 바이트가 같다. 새 manifest는 현재 파일의 실제 해시를 기록하며, 선정한 20개 원래 질문의 주장 문장이 실제 사람 결과 JSON의 근거 문구에 모두 그대로 들어 있는지 추가 확인한다. 과거 해시를 현재 파일의 해시로 재사용하지 않는다.

이전 질문 중 N/A 5개는 실제로는 문서가 읽히는지·종류를 구분할 수 있는지 등 원문 사실을 물었다. 이번에도 같은 사실을 묻고 **N/A 상태 라벨을 사람이 확정한 것으로 계산하지 않는다.** 비교 기준은 `comparison_baseline.json`에 분리했다. 확인자는 답을 마치기 전에 이 파일과 기존 답을 열지 않는다. 새 공개 페이지에는 비교 정답을 넣지 않았다.

프로젝트 루트(`3.project`)에서:

```powershell
# 페이지 재현: 결과물이 다르면 덮어쓰지 않고 중단
backend/.venv/Scripts/python.exe backend/scripts/neutral_test2_review.py
# 사용자가 실제 결과 파일을 준 뒤 실행. 기존 정답 가져오기 도구를 쓰지 않는다.
backend/.venv/Scripts/python.exe backend/scripts/neutral_test2_review.py --result "C:\Users\Donga\Downloads\neutral_review_result_test2_이창헌.json"
```

비교 결과는 `docs/eval/test2/neutral_recheck/<응답 해시>/`에 원본 결과·JSON·Markdown으로 보관한다. 일치·불일치·판단 어려움·미응답 수, 비교 가능 응답 중 일치율, 전체 20개 기준 일치 비율을 모두 남긴다. 동일 응답을 다시 실행해도 기존 결과와 다르면 덮어쓰지 않는다.

**현재 상태: 이창헌의 실제 결과를 가져와 20/20 일치(100%), 불일치·판단 어려움·미응답 0개를 확인했다.** [결과 보고서](../../docs/eval/test2/neutral_recheck/README.md)에 원본과 비교 기록을 보관했다. 용어·절차 설명을 제공한 2개와 나머지 18개를 구분했고, 기존 81개 고유 확인 범위에 20개를 더하지 않았다. 같은 사람이 같은 자료를 다시 보므로 기억·학습 효과가 있다. 중립 문구 일치율은 기술적 비교이며 유도 문구의 인과 효과나 정답 정확도 자체를 입증하지 않는다. 동의 버튼에서 선택·직접 입력으로 답하는 방식도 바뀌었다는 한계를 함께 보고한다.
